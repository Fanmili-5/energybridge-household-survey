# 天气、住宅与日期

问卷中的省市、房型、面积和楼层用于选择仿真环境。日期在开始填写前分配，参与者按对应月份描述家庭习惯。

## 匹配规则

| 项目 | 当前规则 |
|---|---|
| 日期 | 从 365 个日期中均匀抽取；同一浏览器会话刷新后保持不变 |
| 天气站 | 优先同城且与住宅组合通过验证的站点；否则使用通过验证的省内代表站 |
| 住宅 | 按房型、面积和楼层选择 50 个住宅变体之一 |
| 面积 | 面积区间取代表值 40、70、105、140、180 m²；建筑面积暂按 80% 换算室内面积 |
| VPP | 从 17:00、18:00、19:00 抽取开始时刻，持续 1 或 2 小时 |
| 电价 | 所有案例沿用原 EB 的天津归一化分时价格，单位不是人民币 |

找不到合格环境时，系统保留答卷并报告无法计算，不跨省替换站点。代表站也不一定是距离最近的站点。

天气文件来自典型气象年，2007 年用于统一实验日历。住宅为单居住热区模型，材料、空调和热水设备参数继承 EB 研究模型。地区与面积匹配不等于还原了参与者的真实住宅。

## 仿真与统计时间

每个案例先用日常对照运行检查抽中的日期，再进行规划；失败时不重抽日期。

两份方案使用相同的 24 小时统计窗口：有电动车时，从所填离家时刻到次日同一时刻；无电动车时，从当日 00:00 到 24:00。时间轴从当日 00:00 展示至仿真结束，可以长于统计窗口。具体定义见[时间窗口设计记录](../docs/STATISTICS_24H_20260914.md)。

## 资源与验证

2026-09-12 的资源检查下载了 338 个站点，其中 246 个可用。50 个住宅组合、3 个夏季日期共检查 50,700 个组合，36,872 个完成 EP 并通过，13,828 个未通过，含运行前预检查拒绝。该报告只覆盖当时的夏季检查，全年日期在案例运行时另行验证。

| 文件或目录 | 内容 |
|---|---|
| `catalog.json` | 来源、匹配规则、资源路径、哈希及已验证日期 |
| `weather/` | EPW 天气和 DDY 设计日文件 |
| `models/` | 住宅变体：公寓底层／中间层／顶层、独立住宅和联排住宅 |
| `administrative/` | 2023-06-30 省市名称快照，用于省市选择联动 |
| `validation.json.xz` | 历史组合验证记录，包含失败项 |
| `versions/` | 历史案例使用的资源版本 |

```bash
.venv/bin/python scripts/bootstrap_resources.py
```

恢复脚本下载天气、生成住宅并核对哈希。维护资源时使用 `scripts/` 中的 `build_regional_resources.py`、`expand_national_weather.py`、`add_regional_representatives.py` 和 `verify_regional_resources.py`。更新资源需保留历史案例引用的版本。
