# 家庭生成审查与修正

2026-10-19。范围覆盖历史主数据构造代码、1000份既有主世界只读核查，以及无旧目录依赖的新生成与住房/生活连接。原50/1000户、排程、仿真和线上版本未改。

| 问题 | 证据与影响 | 本次处理 |
|---|---|---|
| 旧入口不独立 | `household_master.py`固定V33/1000户；构造器读取旧世界、历史计划及绝对运行环境 | 保留历史代码身份，新增显式输入/任意批次规模的公开入口及可运行合成池；不把源码可见说成原1000户原始数据已开放 |
| 成员比较可能漏项 | V33 `integrity.py`逐项`zip`，新增/缺失成员的尾部可能不比较 | 新路径按完整ID集合核对，N/G、角色事实、关系、床位、共享成员与日历同时检查；反例包含成员缺失/追加/重排 |
| 缓存成功记录不足以信任 | V33 `build_one`在记录文件存在时直接返回；单个构造步骤不核验产物完整性 | 新路径拒绝覆盖/自动续跑，以输入/源/代码及全部产物哈希验收；删除文件后保留旧`passed`也无法通过。未声称历史数据已发生损坏 |
| 构造签名遗漏部分实参 | V33 `bundle_id`未完整绑定另行加载的几何profile及全部计划字段 | 新路径将完整池、面积/布局、设备、日历条件和角色政策纳入输入身份，改变输入不复用旧身份 |
| ID与语义可能混淆 | 新接口必须给成员、设备及共享户改ID；设备名可能恰好等于kind枚举 | 使用字段语义限定的ID变换，禁止全局文本替换；实际kind、活动、关系类型保持，测试覆盖asset_id=ac/washer的情况 |
| 跨命名空间与并发输入风险 | 家庭ID与成员/资产ID可能冲突；运行中输入修改可能混绑哈希 | 拒绝身份歧义，并在封存前核对完整输入仍一致；反例测试通过 |
| 共享户接口有身份约定 | 住房生成的辅助户为`目标ID-aux-01` | 新连接沿用相同约定；公开共享家庭实际经过住房绑定与生活A生成，不只核JSON |
| 家庭设备覆盖可能被邻户虚增 | 共享世界会同时含目标与邻户设备 | 4—6类只计算目标有使用权的设备；操作权、床位和家庭归属分别核对 |
| 需要声明的领域边界 | 新内核同一房间多套独立AC不支持；源关系亚型、非同住监护支持也未被完整观测 | 历史核查保留110户多AC兼容提示、4户关系年龄细分提示、16户监护支持边界；新路径不删设备、不改年龄、不编造身世或住户来消除问题 |

历史关系提示的15岁阈值是项目参考复核规则，不能单凭年龄差断言血缘、收养或来源数据错误。110户多AC是当前新物理导出域的限制，并不意味着110户现实中不可能安装这些设备。这里没有将生活支持的存在解释为已观测、免费或可额外处理电器。

新示例为6种有明确设定的合成情境。它们验证功能和反例，不证明人口代表性、1000户生活多样性或所有家庭情境已覆盖。原人口/住房调查及旧输入仍按原许可与版本管理；现有数据迁移另立任务和数据版本。
