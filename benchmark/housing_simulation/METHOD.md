# 住宅与仿真场景构造方法

## 1. 方法定义

本模块将住宅条件、建筑参数参照、气象资源和家庭运行请求转换为可追踪的参考住宅与配对能源仿真环境。构造过程包括参数参照、参考外壳生成、家庭世界装配、配对物理编译、仿真执行与审计。各阶段使用内容绑定的显式输入，批次规模由输入列表确定。

住宅条件记为 $H_i=(A_i,n_i,q_i,F_i)$，其中 $A_i$ 为本户分配建筑面积，$n_i$ 为参考自然卧室数，$q_i$ 为共享家庭数，$F_i$ 为厨房、卫生及热水设施条件。建筑参照 $R_j$ 包含地点、建筑类型、目录年代、构造参数及来源哈希。物理编译另外接收完整家庭世界 $X_i$、A/B 请求 $U_i^A,U_i^B$、天气 $W_i$ 和运行配置 $P$。

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 参数参照 | 地区、建筑类型、给定年代、来源目录、原生文件、EPW | 选择记录、构造参数、气象身份记录 |
| 外壳生成 | $H_i$、构造参数、尺寸语法、层高、边界策略 | 参考布局、多热区外壳、面积账目 |
| 家庭装配 | 外壳、完整住户名册、睡眠组、设施、设备、日历、服务与控制 | 绑定后的家庭世界、逐日物理包、A/B 请求 |
| 物理编译 | $X_i,U_i^A,U_i^B,W_i,P$ | A/B IDF、实际执行计划、计量映射 |
| 数值执行 | 编译模型、固定引擎 | 原始 SQL、时间序列、执行回执 |

`assemble` 自动完成外壳与家庭契约的绑定并生成编译输入；`reproduce` 连续执行公开实例的全部阶段。“完整家庭世界”指满足本模块物理输入契约的场景，不表示观测到真实家庭的全部行为。输入格式见[接口规范](INPUTS.md)，逐项规则性质与实现位置见[规则登记](RULES.json)。

## 2. 原型匹配

### 2.1 来源与支持域

建筑参数以 [DeST 典型建筑库](https://www.dest.net.cn/dxjzk)为原始来源。An 等的[中国典型建筑模型研究](https://link.springer.com/article/10.1007/s12273-023-1058-5)提供按气候、建筑类型和标准年代建立参考原型的方法依据。原型目录用于确定参数参照，不提供目标家庭的实际施工图或总体类型权重。

候选集合首先满足以下条件：省份与城市一致；来源状态为已准入；建筑类型属于输入指定的优先序列。随后保留优先级最高的建筑类型候选。

### 2.2 年代距离与确定性选择

给定住宅年代区间为 $[l_i,u_i]$，候选目录区间为 $[a_j,b_j]$，年代距离定义为：

$$d_{ij}=\max(a_j-u_i,\ l_i-b_j,\ 0).$$

算法保留 $d_{ij}$ 最小的候选。并列时优先使用 `preferred_reference_id`；其余候选按家庭标识与原型标识的规范 JSON SHA-256 排序。该规则不读取仿真结果或人类评价。

当 $d_{ij}>0$ 时，输入住宅年代保持不变，输出记录为明确给定的围护更新参照情景。目录区间属于匹配元数据，其与地方规范实施日期及目标住宅实际建造情况的对应关系尚未得到识别。

实现：`pipeline.match`。

## 3. 原生参数与气象身份

### 3.1 构造参数提取

提取器首先校验 Access 文件 SHA-256，并读取实际 `ENVIRONMENT`。随后根据 `MAIN_ENCLOSURE` 中的构造外键，定位外墙、内墙、屋顶、地面和中间楼板实际采用的材料层。

每层提取厚度、导热率、密度和比热，保存来源构造编号、材料编号、层序及参数向量。当前提取器要求每种围护类别具有唯一的实际使用构造；多构造情形返回拒绝状态，需另行定义映射。

窗参数取自实际引用的 `WINDOW_TYPE_DATA`，包括传热系数 $U$、遮阳系数 $SC$ 和可见光透过率。简化玻璃采用项目换算 $SHGC=0.87SC$。该标量映射属于建模近似，尚未建立角度、光谱及框边界的完整等价验证。

实现：`kernel/native_bundle.py`。

### 3.2 气象文件绑定

CSWD 来源归属依据 [EnergyPlus 24.1 手册](https://bigladdersoftware.com/epx/docs/24-1/auxiliary-programs/references.html)。候选 TMYx 的生成方法和时期依据[数据提供方说明](https://climate.onebuilding.org/sources/default.html)。每项实验必须固定实际使用文件及其来源版本。

原生提取阶段采用站号、坐标和文件字节联合核验：源五位站号末尾补零后对应 EPW 六位站号；源坐标与 EPW LOCATION 坐标的距离须小于 5 km；EPW 字节须满足登记哈希。5 km 为项目身份核对阈值，不表示住宅气候代表半径。

全年序列完整性、缺值及气象量质量检查属于资源登记阶段。`extract-native`执行身份与哈希核验，`compile`执行已登记资源的字节核验。典型年气象与实验日期分别记录。

## 4. 面积约束与参考外壳

### 4.1 几何构造

几何生成器采用开间、双侧走道或单侧走道语法。输入尺寸向量 $\theta$ 指定卧室基准宽深、走道宽度、服务空间尺度及分配比例；源外墙和内墙厚度分别记为 $t_e,t_i$。卧室尺度系数 $s$ 通过求根获得，使本户分配面积满足：

$$A_i(s;\theta,t_e,t_i)=\sum_{r\in\mathcal R} \alpha_{ir} A_r(s)=A_i^{\mathrm{input}},$$

其中 $\alpha_{ir}$ 为房间 $r$ 分配给家庭 $i$ 的面积份额。墙厚参与几何计算；服务空间和走道采用独立尺度。当前实现以 $10^{-6}\,\mathrm{m}^2$ 为本户面积守恒检查容差。

生成器按输入候选顺序尝试尺寸语法，保留首个同时通过几何构造和外壳编译的候选。失败候选记录原因；无可行候选的住宅保留在批次清单中，状态为 `rejected`。

### 4.2 面积与使用权

输出分别记录本户分配建筑面积、整套物理面积、墙体占地、室内净面积和热区参考面积。共享房间采用明确的面积份额；面积份额不自动确定设备使用权、控制权或电表归属。

`natural_rooms` 在当前语法中表示本户自然卧室数。厅、厨房、卫生间、走道及储物区单独分类。这是本生成器的参考建筑定义；调查中自然间的统计语义须在上游转换时保留。

### 4.3 外壳编译

连续共面墙面在开口生成前合并，内部相邻表面建立互指关系。当前外壳采用中间层参考公寓边界：南北选定外表面暴露，侧邻边界为零通量，走道入口按参考外门处理。门窗位置、窗面积、门热阻及楼板芯层为显式模型参数。

外壳阶段不执行床位、照护、设备安装包络及人员操作权限验收。相关空间与服务条件须在完整家庭世界中核验后进入物理编译。

实现：`kernel/geometry.py`、`kernel/faces.py`、`kernel/shell.py`。

## 5. 家庭世界自动装配

### 5.1 成员、居住权与床位

装配输入必须提供整个物理住宅内所有家庭的成员名册。共享邻户不得以缺失人数或零负荷代替；有未登记外部厨房使用者的几何情形拒绝进入当前居住型装配器。成员所属家庭、设施使用权、资产使用权和操作权限分别绑定。

睡眠组按标识排序，每组占用一间具有本户独占使用权的卧室。未指定房间时按房间标识选择首个可安装参考床的候选；每名成员恰好属于一个睡眠组。参考床容量为一或二人，最小短边分别为0.8/1.2 m，长边至少1.8 m。这些尺寸是项目安装筛查参数，未作为住宅法规或人口睡眠安排的统计结论引用。

### 5.2 设施、安装与供电

落地设施、床和设备按确定顺序，在净使用矩形内以0.1 m网格搜索两个朝向。矩形之间保留0.1 m间距，房间一侧保留0.8 m参考通行带。卫生间包含声明的便器与淋浴包络；厨房包含声明的水槽烹饪台与冰箱包络。壁挂设备核对累计安装宽度预算。接电、给排水、排风、室外换热或专用停车条件由输入声明并校验。

该筛查提供可复核的矩形安装见证；未建立真实门扇扫掠、管线路由、家具高度、结构荷载或施工合规证明。贪心顺序固定，无可行见证时保留拒绝状态，不缩小设施或减少成员以完成装配。

供电筛查使用保守铭牌上界：全部资产铭牌功率，加照明及杂项功率密度乘热区参考面积、冰箱与烹饪功率及显式排风预算，不得超过声明的供电容量。程序功率和热泵额定电耗组合另行核对铭牌上界。该条件不替代支路设计或引擎中的逐时电耗。

### 5.3 日历与服务

工作日、周末及可选日期覆盖表逐日展开。每名成员每天0–1440 min恰好由一个连续、不重叠的事件序列覆盖；在家事件绑定可访问房间，离家事件不产生室内人员负荷。睡眠绑定已分配卧室。操作窗口由显式可操作事件导出；设备操作需同时满足年龄至少16岁、资产授权和在场条件。16岁为项目操作资格设定。

同一卫生间的洗浴事件不得重叠。服务声明展开为需求、10 min装载、固定功率程序和10 min取出，洗衣—干衣依赖通过前序服务标识绑定。装配器使用与编译器相同的执行器检查全部基线服务；不可执行基线拒绝装配。B请求保持同一物理世界，只改变允许的服务时点与控制，失败按执行语义记录并传播。

人员日历、照护安排、设备拥有与连接条件由上游明确提供；本模块不从年龄或住宅面积推断工作时间、照护关系或设备拥有率。

### 5.4 设备与来源

热泵采用[EnergyPlus24.1官方PTHP示例](https://github.com/NatLabRockies/EnergyPlus/blob/v24.1.0/testfiles/PackagedTerminalHeatPump.idf)中Zone1的拓扑及性能曲线，按资产标识建立独立命名空间，并用输入替换容量、COP、风量、风机功率、补热及除霜功率。专用室外新风量设为零；住宅空气交换单独计算。该组件是统一参考设备，不代表中国分体空调的型号校准。

储水箱使用[官方分层热水器独立运行接口](https://bigladdersoftware.com/epx/docs/24-1/input-output-reference/group-water-heaters.html)：声明的热水出口体积直接驱动用水流量，无虚构循环泵。`hot_outlet_liters`是水箱出口热水量，未实现混水阀，不能解释为指定温度的混合淋浴水量。水箱体积、功率、效率、散热和节点数均由输入声明；最低出水温度作为服务条件核对。

洗衣、干衣和洗碗使用显式定功率程序及潜热、辐射和排出比例；EV使用连续电池能量账、充电效率、物理接插和出行牵引能量。所有默认数值与热比例属于公开项目参考设定。背景负荷按逐日清醒人数与晚餐事件生成。

实现：`assembly.py`、`components.py`、`WORLD.schema.json`、`kernel/execution.py`。官方资源的源文件哈希、提取流程及许可见`resources/`与`SOURCES.json`。

## 6. 家庭物理模型与成对编译

### 6.1 运行计划

完整家庭世界提供日历、成员位置、设施预约、设备资产、任务、操作、行程及电池事件。编译器以冻结需求为基础，将各臂请求覆盖到相关任务与控制区间，并在覆盖区间外恢复日常方案。

装载、运行和取出按操作人员可用性、设施预约及设备占用状态执行。未执行的装载不会产生对应程序电耗；取出失败导致的设备占用按照既定执行边界传播。EV 在原物理连接和行程条件下连续计算电池状态。A/B 请求及失败记录保持独立于物理结果。

### 6.2 热环境与空气交换

人员日历及实际执行的操作映射到房间人数和设备内热。门户交换、排风和补风采用 [EnergyPlus 分区空气质量流量平衡机制](https://bigladdersoftware.com/epx/docs/24-1/engineering-reference/zone-air-mass-flow-conservation.html)，具体参考值由 `reference_environment.json` 和运行配置固定。

| 参数 | 基准值 | 参数性质 |
| --- | ---: | --- |
| 基础空气交换 | 0.35 ACH | 参考环境条件 |
| 门户开启交换系数 | 0.0625 m³/s/m² | 工程参考参数 |
| 关闭状态交换比例 | 0.05 | 待敏感性分析参数 |
| 浴室间歇排风 | 50 cfm | 参考容量，依据 [DOE/PNNL资料](https://basc.pnnl.gov/resource-guides/bathroom-exhaust-fans) |
| 厨房排风 | 100 cfm | 冻结参考设施条件 |
| 浴后及烹饪后延时 | 20 min | 项目运行设定 |

上述参数与人体接受标签、总体设备拥有率及本地法规认证无直接对应关系。参数修订形成新的实验配置，并重新执行受影响模型。

### 6.3 配对条件与时间范围

两臂共用家庭外壳、天气、设备参数、引擎与前史配置。通知前条件的一致性须由领域验收确认，不能仅由运行完成状态推断。

输入采用ISO日期，逐日活动按原始人类日历展开。目标案例年份统一映射至模拟年2026，前史及尾期相应映射至2025或2027；月日与事件先后关系保留，星期编号不要求相同。采用长度不超过365天且不包含2月29日的运行区间，超域请求明确拒绝。输出时步固定为10 min。

前史按`history_days`完整提供。尾期终点为配置长度与最后请求后至少七天要求的较晚者，基准最晚请求下界为案例日起1920 min；向上取整至完整日。日历不足时拒绝编译，不截断前史或恢复期。实际区间、前史长度及请求终点写入各臂`INPUT.json.gz`。

实现：`kernel/compiler.py`、`kernel/thermal_environment.py`、`worker.py`。

## 7. 执行、产物与验证

执行器核验编译文件、气象文件及引擎版本后运行两臂，保存原始 SQL、错误日志和执行回执。SQL 回读排除预热数据，校验必需电表、温度通道、有限数值和完整的 10 min 时间轴。电量的评价区间由 `evaluated_interval_min` 明确给出。

每个阶段生成产物清单和 SHA-256。文件核验、数值执行、服务完成、实测校准及人类接受为不同验证层次，判定条件见[验证规范](VALIDATION.md)。

公开复现覆盖三个非空家庭世界与六次引擎执行，统一审计计量闭合、程序电耗、服务完成、EV能量、热水供给、通知前轨迹及恢复残差。各条检查的容差和实际结果见`VALIDATION.md`及`VALIDATION.json`。这些工程验证不建立总体代表性、实测校准或人类接受结论；最终实验应另行执行参数与结构敏感性分析。
