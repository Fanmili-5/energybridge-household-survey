# 验证规范与覆盖范围

## 1. 验证层次

本模块区分文件一致性、工程执行、领域有效性和外部效度。各层判定对象和结论范围分别记录。

| 层次 | 检查对象 | 判定条件 | 当前接口 |
| --- | --- | --- | --- |
| 文件一致性 | 输入资源与已登记产物 | 实际 SHA-256 与清单一致，路径位于声明范围 | 资源绑定、`verify`、包完整性检查 |
| 外壳构造 | 面积、房间和材料闭包 | 面积守恒，构造依赖可解析，几何及开口可构造 | `build-shell`及公开测试 |
| 编译一致性 | 打包内核与原内核 | 同输入、同环境下 IDF 字节一致 | 受控编译对照 |
| 数值执行 | 引擎、SQL、时间序列 | 引擎完成，必需通道存在，数值有限，10 min 时间轴完整 | `run`及回读检查 |
| 家庭领域验收 | 共同状态、计量、设备任务、服务与恢复 | 满足具体实验预先声明的判定规则 | 上游家庭验收与下游领域分析 |
| 外部效度 | 实测性能、总体代表性、人类评价 | 依据独立观测与相应统计设计检验 | 本模块工程检查不提供此类结论 |

`completed`表示引擎执行与所列回读检查完成，不等同于设备服务全部完成。警告随回执保留，设备执行失败和人类接受标签另行记录。

## 2. 公开测试

```bash
python -B -m unittest benchmark.housing_simulation.test_pipeline
python -B -m benchmark.housing_simulation.verify_package
```

八项测试覆盖以下性质：

| 测试性质 | 检查内容 |
| --- | --- |
| 批量与面积守恒 | 单户和多户输入；本户面积、自然卧室数及整套共享面积账目 |
| 失败记录完整性 | 无可构造几何的住宅保留在原输入分母内 |
| 输入身份 | 来源字节变化在构建前被拒绝 |
| 输出身份 | 产物损坏可检测，既有输出目录不覆盖 |
| 标识与路径 | 非法输出标识和目录越界请求被拒绝 |
| 年代语义 | 给定年代保持，参照缺口显式标记 |
| 算法来源 | 打包内核文件满足源码映射登记哈希 |
| 数值范围 | 非有限 JSON 数值被拒绝 |

包完整性检查核验技术文档、配置、示例及代码的登记哈希。公开 CI 使用独立依赖安装和合成输入运行上述检查，不读取受控调查或研究家庭资料。

## 3. 已完成的集成验证

机器可读记录见 [VALIDATION.json](VALIDATION.json)。验证日期为 2026-10-19。

| 验证项 | 覆盖 | 结果 | 适用范围 |
| --- | ---: | --- | --- |
| 原生参数提取 | 1 份 Access 原件 | 来源哈希与提取检查通过 | 单份原件的提取路径 |
| 同环境编译对照 | 2 对请求、4 臂 IDF | 与原编译器逐字节一致 | 对应输入及运行环境 |
| 受控引擎集成 | 2 对请求、4 次运行 | 引擎及完整时间轴回读通过 | 编译、运行和回读集成 |
| 公共合成实例 | 1 对请求、2 次运行 | A/B IDF 与 TRACE 一致 | 无居民、无目标可控设备的工程实例 |

原始引擎日志和 SQL 保留于验证环境，公开记录保存相应报告哈希。现有检查未建立零警告、实测校准或跨环境逐字节一致的结论。

## 4. 实验级领域验收

最终 benchmark 应根据版本化输入单独固定领域验收规则，至少覆盖：

1. **输入一致性**：家庭、成员、资产、房间、请求及日期引用一致。
2. **共同前史**：A/B 在规定比较边界前具有相同外部条件与可比较状态。
3. **计量边界**：整套电表、目标设备、背景负荷与住宅外 EV 的边界明确，计量闭合满足声明容差。
4. **服务交付**：程序执行、人工装取、供水温度、出发 SOC、资源冲突及后续阻塞分别回读。
5. **恢复与尾期**：反弹、状态残差和未完成任务按固定观测窗口报告。
6. **参数敏感性**：对前史、空气交换、门交换及关键围护假设执行预先固定的比较。

该清单定义实验级验收要求；当前独立包没有将全部项目实现为统一验收命令。原有批次的领域验证应与其输入及版本绑定，不能仅凭本模块的工程测试推定新批次已通过。

## 5. 当前集成边界

公开外壳接口输出参考几何和围护模型，配对仿真接口接收完整家庭世界。自动完成床位、照护、设备安装、控制权限及日程绑定的通用装配器尚未纳入独立接口。带设备的公开端到端实例及统一领域验收入口属于后续集成工作。
