# 验证规范与覆盖范围

## 1. 验证层次

验证区分文件完整性、构造可执行性、物理数值一致性、家庭服务完成以及实测有效性。后一层结论不能由前一层通过自动获得。公开验证不需要历史1000户输入，也不生成问卷回答或人类接受标签。

| 层次 | 执行入口 | 判定范围 |
| --- | --- | --- |
| 包完整性 | `verify_package` | 代码、文档、Schema、来源及资源文件清单，代码符号/文档锚点/字段映射闭合 |
| 阶段完整性 | `verify` | 全部登记文件及嵌套阶段清单，拒绝篡改和未登记额外文件 |
| 家庭构造 | `assemble` | 完整名册、床位、设施、设备、使用权、供电、日历与可执行基线 |
| 模型与数值 | `compile` / `run` | 固定资源、引擎、模型与10 min SQL轨迹 |
| 物理与服务 | `audit` | 计量、程序、取出、热水、EV、共同前史及恢复 |
| 实测及社会有效性 | 独立研究验证 | 当前工程检查不建立该层结论 |

## 2. 公开自动测试

`test_pipeline.py`、`test_assembly.py`、`test_review.py`与`test_methods.py`当前共52项测试，仅使用公开合成输入，不启动EnergyPlus。覆盖单户及三户批次、面积守恒、失败分母、资源篡改、路径与重复标识、原型选择、非有限输入、完整共享名册、床位容量和房间权限、安装失败、供电与接线、操作年龄/授权/在场、日历覆盖、洗浴冲突、控制范围与通知边界、非空模型编译、失败取出的后续占用、洗衣—干衣依赖、Schema未知字段、前史/恢复覆盖、闰日拒绝，以及不同`PYTHONHASHSEED`下的生成一致性。

新增回归用例覆盖天气登记与全年时序、睡眠/午睡/洗浴房间、热水资产使用权、B授权范围、同区重复空调、EV连接与完整基线储备、首日拔插，以及共同缺失房间通道/水箱节点、服务批次缺失、单位错误、无效文档锚点和新增未映射字段。

测试中的全年合成天气仅供不启动引擎的字段和编译测试，不能作为物理验证天气。真实引擎验证使用下节的完整官方EPW。

## 3. 公开端到端物理验证

实例由`examples/shell_batch.json`与`examples/world_batch.json`构造，包含1人、3人和4人三个物理住宅。4人实例包括目标家庭3人及邻户1人。每个住宅有六类可控设备、逐日人员位置、非空服务与行程，A/B请求不同。

`reproduce`执行三个外壳、三个世界、三个案例及六次EnergyPlus运行。执行环境和文件身份、逐案例检查结果及数值误差写入`VALIDATION.json`和`REFERENCE_RESULTS.json`。CI将本模块复制到空目录执行相同流程，并保存原始SQL、日志与审计产物。

### 3.1 时间与共同状态

- 所有已报告通道包含完整、无重复的10 min时间轴，值为有限数。
- 根据编译器声明的全部房间核对空气温度、平均辐射温度、相对湿度和人数通道，并按水箱节点数核对每个分层温度；两臂同时缺失也判失败。读取通道的单位须与物理量一致。
- SQL、TRACE与RESULT回执哈希须一致，且运行清单绑定编译清单。
- A/B采用同一外壳、天气、设备、前史及运行区间。
- 案例日起`[0,480)`的全部共同通道最大绝对差小于`1e-6`，单位依各原始通道；源请求禁止改变通知前事件。
- 输入须完整覆盖前史及最后请求后至少七天；不得通过缩短日历使验证通过。

### 3.2 电量与供电

逐时核验：

`Electricity:Facility = Electricity:HVAC + InteriorEquipment:Electricity + InteriorLights:Electricity + WaterSystems:Electricity + ExteriorEquipment:Electricity`。

未安装的系统项不参与求和。最大闭合误差不得超过`max(1e-3 J, 最大设施时步电量×1e-8)`。程序设备每时步电耗与实际执行状态下的`功率W×600 s`逐项比较，误差小于`1e-3 J`。热泵必须产生可读取的设备电量通道。声明供电容量同时接受设施时步平均功率检查。

### 3.3 程序与服务

装载、程序和取出均按执行器结果核对。不存在操作失败或被丢弃程序，评价区间内需求清单与实际批次标识、数量须完整一致；相关批次必须完成取出且不超过需求截止。案例日早晨通知前的服务同样计入，不因结束早于480 min而遗漏。失败取出继续占用设备，影响后续需求；前序洗衣未取出时不得运行依赖的干衣服务。运行成功不能代替这项服务检查。

### 3.4 EV与热水

EV电池能量账误差小于`1e-8 kWh`，无不可执行行程、未服务牵引能量或最低储备短缺。通知后EV设备电表与请求网侧能量的时步误差小于`1e-7 kWh`。两臂尾期末电池能量差小于`1e-8 kWh`。

热水按每项需求的出水时间区间，核对最低水箱出口温度及实际用水侧流量。最低温度取10 min报告平均出口温度的最小值，按输入服务阈值判断；该离散验收不保证时步内瞬时最低温度。数值容差`1e-5 °C`。流量积分得到水质量，与请求热水出口升数比较，容许3%的质量/体积密度换算差异。该量未经过混水阀，不能作为混合洗浴水量。

### 3.5 恢复

报告每个房间空气温度、水箱平均温度及各分层节点的末时点差和最后24 h平均绝对差。参考工程门槛分别为房间空气0.1 °C、水箱及节点0.5 °C。两种差均须通过；这些门槛是项目数值比较条件，不是人体热舒适标准，也不构成全部隐含建筑状态完全相同的证明。

## 4. 可复现性证据

在独立目录和干净依赖环境中从公开输入重复执行。比较外壳、家庭世界、配对请求及IDF字节；数值轨迹按上述容差检查。引擎日志中的时间和绝对路径，以及SQL内部记录，不作为跨运行逐字节复现要求。

`PACKAGE_MANIFEST.json`固定发布文件，`SOURCE_MAP.json`记录历史代码出处和现行内核哈希，`RULES.json`将来源支持的机制、项目规则和显式输入区分登记。`FIELD_MAP.json`覆盖236个Schema属性路径，`ASSUMPTIONS.json`登记15组关键参数及性质。链接检查验证来源标识、实现符号和实际文档锚点；该结构检查不替代来源内容的人工判读，证据支持边界见[EVIDENCE.md](EVIDENCE.md)。官方组件可用`export_resources`重新提取并核对字节。

## 5. 警告与适用边界

参考外壳采用墙中心线表面与净使用面积/空气体积的分离记账，EnergyPlus会报告两种面积和体积约定的差异。零流量节点用于未空调房间的质量账注册；官方等风量热泵示例还会提示风机性能曲线未影响当前风量条件。保留这些警告及完整日志，验证记录不声称零警告；严重错误或缺失必需物理通道不能通过审计。

当前验证覆盖公开参考场景的工程构造、设备计量和服务。未建立全国住宅分布代表性、实测能耗校准、真实空调型号校准、三维施工合规、混合淋浴水服务或人类接受有效性。照护与日常行为由输入日历给定；不执行行为推断。门户交换、渗透、设备功率、前史长度和围护方案的敏感性分析仍应针对最终研究配置单独报告。

## 6. 敏感性与数值收敛

范围、容差及细化阶梯在完整矩阵前登记；开发诊断后增加了选定步长下的长前史/恢复期联合确认，未放宽阈值或调整因子范围。各版原始计划及哈希见`STUDY_PLAN_HISTORY.json`。开发联调不计为最终通过证据。三种住宅各在2025-07-15、2025-11-15生成一对请求，共六案例；原始日历均明确提供，不读取历史家庭。默认公开天气为Chicago TMY3，故该矩阵不证明中国气候有效性。中国EPW可用同一接口单独登记、重跑。

### 6.1 前史、尾期与步长

前史比较7→28→56→112天。按相同9天评价区间比较每臂设施电量及全部房间、水箱和节点温度。每臂能量差不超过更细参考的1%；配对效应`E_B-E_A`变化不超过`max(0.02 kWh,0.1×|更细参考效应|)`；状态平均绝对差分别不超过0.1°C和0.5°C。短前史先按连续两级比较诊断；最终部署保留112天，并在已选择求解步长下以112→168天再次确认。仍不通过则验证失败。

尾期比较9→16天，比较各自完整评价期的累计配对效应，并同时要求原有末时点与最后24 h恢复门槛。尾期不能比较两臂总电量相差1%，因为增加的正常运行天数会自然增加总电量。

求解步长依次比较10→5→2→1 min，保留首个同时满足步长、112→168天前史及9→16天尾期判据的较粗步长；任一条件失败均继续细化。行为事件和输出网格始终为10 min，不能把更细热求解解释为更细行为观测。1 min单次运行本身不构成收敛证明。所有判据均为项目数值验收协议，与人体舒适阈值或测量误差界限无等价关系。

### 6.2 参数敏感性

采用[Morris(1991)](https://doi.org/10.1080/00401706.1991.10484804)的elementary effects设计：四级网格、归一化步长2/3、固定种子、两条轨迹及五个独立物理场景因子，共12组设置。因子为基础ACH[0.175,0.7]、门户流量比例[0.5,2]、人体与照明比例[0.8,1.2]、杂项比例[0.5,1.5]。敏感性样本在选定求解步长、112天前史及经确认的9天尾期上运行。报告每案例A/B电量和配对效应的μ、μ*、σ及全部原始效应，不推断这些范围的经验概率。两条轨迹只适用于初步筛查；不作为精确排序、Sobol总效应或人口联合分布分析。

敏感性通过表示全部计划运行通过物理/服务门槛，且所有elementary effects完整、有限；不表示输出不敏感，也不要求B始终节能。效应符号变化必须公开保留。改变来源、气象、设备、拓扑或参数域时须重新运行，不能沿用本矩阵的结论。

### 6.3 气流结构比较

压力网络与规定混合模型使用同一家庭和请求。AFN要求每个区压力及每条链路两向流量存在、单位正确、轴完整；逐区净质量流量绝对残差不超过`1e-6 kg/s + 1e-5×该区总方向流量`。电量差作为结构敏感性结果报告，两种结构接近不作为校准标准。该诊断借鉴[BESTEST比较验证思路](https://doi.org/10.2172/90674)，未执行完整官方BESTEST测试套件，不能声称取得该认证。

### 6.4 结果与复现

`MODEL_COMPARISON.json`另行登记两种气流结构的每臂电量、配对效应及质量残差。`ROBUSTNESS_RESULTS.json`是实际`study/REPORT.json`的发布副本，绑定登记计划、代码树、天气和引擎身份；每组设置的审计清单SHA、全部通过状态及模拟臂数均保留。完整IDF、SQL和日志在本地手动研究运行目录保留，原始大文件不随Git发布。历史完整CI运行的artifact有保留期限；当前CI只保留有界冒烟回归产物，不执行完整研究矩阵。总通过要求物理/服务门槛、数值收敛和敏感性完整性同时成立。

若原允许截止晚于仿真末端，但实际程序在区间内完成，则该服务仍须纳入完整性比对，且保留独立截止不截短。期内已执行任务与有完整可观察需求窗的服务共同形成预期集合，不能因截止跨界误报为额外服务。
