# v69离线示例与UI91正式适配契约

以下原有表格和preview_assets规则限定于公开六户37案离线示例。当前50户UI91正式包在此基础上由reference_physical_release派生，绑定完整500组新配对运行与本题physical_review：可用结果逐题展示，完整性异常保持未知，服务失败及VPP未达标不作剔除条件。A/B、画像、原生SQL及旧答案分别保持版本绑定；UI91视觉与v69回答协议分别登记，见[正式方法](UI91_FORMAL_PHYSICS.md)。

| 上游输入 | 问卷输出 | 不允许的替代 |
|---|---|---|
| `families/families/<hid>.json` 的 facts / archetype_definition / field_origins | profile 人口关系、角色、来源；可见家庭文字 | 将未知收入、职业或真实偏好补造为观测事实；将角色预先当接受答案 |
| 同一户 WORLD_INPUT、设备权限与当日日历 | 成员、设备、操作者、本日生活背景 | 共享住宅自动扩大授权；更换成员或设备 |
| 同一户 layout.json | profile.housing、参考面积与共享情况；布局内容摘要 | 把参考匹配说成实测户型；不同住房的后果套回本户 |
| `pairs/<sample_id>.json` 的完整 A/B | `plans.A/B`、`changes`、完整本题排程 | 用最优 B 替换原样本；给静态失败样本悄悄修排程 |
| 固定实验 events | `VPP_requests`（含通知时间） | 为制造响应而改事件、换家庭或重抽 |
| 当前不存在的物理结果 | `impact=null`、`VPP_results=null`、`outcome_status=not_computed` | 填0、空列表冒充无失败、解析计划冒充实际结果、复制旧50户结果 |
| 实际人类回答 | 当前 `response=null`；预览交互不入库 | 自动填写接受、评分、满意度或生成真人标签 |

本题主区间为当日08:00至次日08:00。程序及装取保留与主区间相交的完整服务链，跨边界不截断程序时长；长历史温控命令只对展示区间做等价裁切。完整原始 A/B 仍由原文件 SHA 和命令 SHA 绑定。控制差异在 A/B 共同边界上比较状态，不能把仅仅分段不同当成策略变化。

同日 B 变体的 `case_id` 包含原样本 ID；索引选择案例而非只匹配日期。日程中允许充电的窗口、空调/水箱设定值仍使用 v69 原有命令描述，不能解释为实际充电功率、室温或出水温度。

## 前端复用边界

`preview_assets` 读取已定 v69 `index.html`、`view.js`、CSS及必填校验器，**从不写回 collector**。派生资料包只做以下接口适配：

- 原表单 HTML（题目、字段、选项、量表、步长、必填）逐字保持；CSS和必填校验器逐字保持。
- 家庭文字使用来自本户资料的显式投影，不为满足旧 profile.role_policy 形状而捏造温度容忍度、自动化许可或经济权重。
- 未计算后果使用独立渲染分支；不会进入 v69 对已计算后果的成功/失败推断。
- 案例选择值换为案例 ID，以承载同日多 B；页面布局沿用原版。
- 包标题、状态和说明标为离线资料预览。传输适配器只在内存检查六项填写，不向任何采集地址 POST，不持久化答卷；服务端所有 POST 返回405。

生成时核对已知代码锚点；v69源文件变化时拒绝静默适配。资料包自带原资产摘要、逐案内容摘要和由实际 JS 渲染器产生的 `DISPLAY_MODELS.json`。预览的 adapter_revision 独立登记，不冒充可直接装入 v69 正式发布/采集协议的资料包。生产版本固定一户十题且要求已封存后果；当前六户37题没有绕过这些正式准入条件。

静态失败诊断保留在研究侧 `AUDIT.json`，不在受访者界面预置“应接受/应拒绝”结论。热水需求、给定舒适范围和照护关系来自同户明确字段；未知舒适范围保留未知。EV的声明室外位置只映射到v69已有“车位”显示名，profile保留原 `source_room_id=null` 和投影说明，不因此新建物理房间。

当前生产修复版本另见[完整后果验证](FULL500_PHYSICS_REPAIR_VALIDATION.json)与[修复及补生成方法](PHYSICS_REPAIR_PRODUCTION.md)：当前500题后果齐全，3个原日期替换明确登记，旧45个工程未知状态为历史诊断，不能继续当作当前线上题目。
