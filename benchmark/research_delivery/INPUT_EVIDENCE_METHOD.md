# 机会账本未知项的输入核对

`input_evidence_audit`从封存上下文逐项核对未知机制对应的设备、需求、A程序及事件控制记录。
它不调用机会声明、候选生成或准入判断，不生成补充控制，也不修改原账本分类。

同一设备/需求日期可能对应多个动作机制。因此同时报告机制条目数和去除机制重复后的设备/需求日期数，
不能把每个未知机制都解释成一个缺失家庭或一份损坏资料。

程序缺失时，记录需求释放、期限和A片段边界，区分释放晚于片段、期限早于片段及片段内程序未匹配。
若输入实际含有对应程序却被标为缺失，检查直接失败。控制缺失时，核对相同资产和指令种类，
记录现有控制区间及其与固定VPP事件的关系；如果存在事件内控制，缺失标记检查失败。
空调房间用房记录缺失与明确没有事件内用房区间分别表示，不能混成同一个布尔值。

没有事件控制行不证明压缩机或加热器实际停机，也不授权补造一个事件内设定。
未来需求尚未进入A片段不等于当前家庭没有完成必要服务。本审计只定位现有证据范围；
未来如改变机会分类，必须另记规则版本、逐项对应并保持原报告。

复现入口：

```sh
PYTHONPATH=. python -B -m benchmark.research_delivery.input_evidence_audit \
  --collection /absolute/path/to/sealed-linked-bank \
  --ledger /absolute/path/to/INPUT_OPPORTUNITY_COVERAGE.json.gz \
  --out /absolute/path/to/new-audit-directory
```

输出包含完整机制CSV、保留控制区间的JSON、原始上下文路径及哈希和审计摘要。
已有输出不覆盖；审计前后校验来源，不按候选收益或是否入选决定审查范围。
