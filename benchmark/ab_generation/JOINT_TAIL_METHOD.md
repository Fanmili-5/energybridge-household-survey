# 新联合目录的正式长尾分层验收

本方法只用于第二条线的合成离线实验。线上问卷不变，1000户仿真暂停。原EB的阶段与信息边界见 `DESIGN.md`、`OFFLINE_EXPERIMENT.md`。本次代码及验证接续 `JOINT_LOAD_SUPPLY.md`，原有回执继续保留，不能用本次结果覆盖旧结果。

## 1. 输入与依据

输入是3个公开合成家庭、8个已声明情境的冻结A：基准、轻载、较重载、多批洗衣、宽事件窗口、共享设备、8kW供电压力及温控扰动。具体清单为 `examples/joint_tail/references.json`，原A构造计划为 `examples/joint_load_supply/plan.json`。这些不是8户，也不是新的人群调查。

`joint_tail.frame`只读每个情境的 `assembled`、`contexts`、`baseline_compiled`、`baseline_runs`、`baseline_audit` 及哈希；不读取早期研究的B选择、B报告、RESULT或答卷。以前做过的B数值不进入当前优先级、配额或匹配条件。完整未来A是离线信息特权，不能据此声称实时预测或在线控制性能。

## 2. 生成目录与四个新增覆盖轴

默认联合搜索允许2至全部独立单位，同一设备的不同批次也可以组合；同批次的不同剂量互斥。完整洗衣和关联烘干算一个服务链单位，但实际响应分别核对每台设备。有限搜索、两单位剂量覆盖、高阶见证和预算缺额见 `JOINT_LOAD_SUPPLY.md`。

在既有设备族、机会证据、方向、费用、剂量、组合、人工模式等轴上新增：

- `unit_count`：独立请求单位数；不把洗衣及依赖烘干误算为两个独立决策。
- `family_count`：不同设备族数；与单位数分开。
- `same_family_jobs`：是否有同族的多个程序/充电需求；空调冷热两轴不冒充多个洗衣批次。
- `power_risk`：已知程序/EV剖面超限、仅保守热/背景上界未认证，或无此静态问题。上界超出不能直接写为实际过载。

普通和EV不足压力两个固定变体都使用新联合搜索。目录保留所有实际生成请求，包括静态冲突；不读取推荐规则赢家作为抽样池。相同冻结上下文与规范化B命令只计一次，不同来源保留别名。不同情境不是新家庭，家庭分组ID不变；不按文案、候选编号或费用相同去重。

## 3. 固定分层及取样

事前计划为 `examples/joint_tail/plan.json`：22层，其中18层必验、4层作为公开缺口监测。每层1户、每户1个请求，固定种子20261019。小规模验证只用于检查方法与边界，不是最终训练样本量方案。

必验层包括：供电上界压力、EV出发不足压力、同族多批静态冲突、其他静态冲突、A=B、6/5/4/3单位正常联合、两单位混合证据及全部有依据联合、洗衣费用增加、洗碗/EV/制冷有依据、非活动制热轴探索、热水反向探索及顺向请求。

4个可选监测层是：已知剖面本身超供电、同族多批可执行联合、热水有状态依据、冬季制热有依据。它们未出现时公开缺额，不自动改为“不适用通过”；不能把静态诊断当作同族可执行联合的物理覆盖。

重叠层按计划顺序首次匹配独占，未抽中的同层请求也不借给后续层。每层先按家庭，再按户内请求的稳定SHA256优先级无放回取样；算法和名义有限目录入样概率沿用 `TAIL_METHOD.md`。家庭的不同情境共用家庭ID，不因多做情境而伪装为更多家庭。匹配数、独占数和缺额分别列出，避免把分层重叠造成的缺额冒充没有该类候选。

第一个B运行前封存：计划、参考A回执、全部规则、候选目录、生成覆盖、抽样覆盖、被选B哈希。不存在依据B结果的重抽、补位、改种子、改剂量、改配额或换成功B。若必验层缺失，仍执行既定其他样本、保留全部结果，验收失败。

## 4. 无效、无响应、物理失败及数据错误

| 类别 | 是否执行 | 如何计数 |
|---|---|---|
| 人员/设备冲突、越权、改写过去等静态问题 | 诊断层不执行 | 只验证静态拒绝；不获得物理覆盖信用 |
| 明确EV不足压力 | 符合原权限、连接和身份边界后执行 | 预先只允许充电超原连接这一静态问题；须实际检出声明的出发目标不足，不以其他错误冒充 |
| 明确供电压力 | 计划显式启用且仅有两种供电静态问题时执行 | 保留实际超限或未超限，两者都报告；压力风险不保证实际失败，不因意外成功重抽 |
| 已执行但无可观察响应 | 保留 | 与A=B对照、探索和有依据请求分开报告；不能当作数据缺失或删掉 |
| 物理/服务要求失败 | 保留 | 例如B总功率超过声明容量、出发电量不足、热水或声明温度/服务要求不达标；不代表现实设备损坏、真实违法或人必然拒绝 |
| 引擎、读回、A复现、身份或能量闭合错误 | 原诊断与未知值保留并隔离 | 不获得有效物理覆盖信用，不填成零收益或生活偏好；不换B掩盖 |

普通B可解释的失败清单为 `SERVICE_FAILURES`：EV出发目标、热水服务、服务执行/完整性、已声明舒适范围、总供电。其余错误不能借“失败长尾”名义放行。供电压力白名单只豁免两种供电筛查状态，绝不豁免装取、先后依赖、权限、过去、设备身份或输入错误。关联烘干也必须有自己的控制授权，不能借洗衣机授权越过。

所谓实际结果限于声明模型。程序设备是完整批次等效功率，不解析电机波形；热设备使用原生热模型；EV连续电量另算、EP计电负荷。全户功率为EP原生区间平均有功功率，不是浪涌、断路器或电气规范认证。

## 5. 验收层次及自查

分别报告：

1. 生成覆盖：各参考情境/变体的两单位剂量、同族交互、请求数、高阶族组合、预算和缺额。
2. 抽样覆盖：22层的匹配/独占目录、可用家庭、要求、抽中、完整验证和缺额；另输出全部声明轴的单因素和两因素覆盖表，包括零覆盖格。
3. 后果覆盖：逐目标实际执行/响应、无响应、有害服务结果与隔离数，以及相同案号下的原生B轨迹重复。命令不同不自动算独立物理后果；相同后果也不据此删除重抽。
4. 完整性：实际导出B哈希等于被选B、同一A全通道复现、读回完整、计量闭合、所有已选记录有去向、冻结选择没有变化。

`passed`仅表示生成覆盖、18个必验层、所有已选记录完整性及声明的逐目标响应合同通过。`full_declared_strata_covered`单独报告全部22层是否覆盖；可选缺额不会被前者隐藏。探索性无响应与物理服务失败不自动使方法失败；有依据目标无响应比例超过0.5会使响应合同失败，样本仍全部保留。

当前小样本不足以证明人口分布、未枚举高阶剂量、全年季节和人类理解有效性。新增情境须另存版本及事前计划；不能修改本次冻结目录和样本来补齐已知结果。

## 6. 复现

```sh
# 先按 JOINT_LOAD_SUPPLY.md 生成8个A参考情境。
python -B -m benchmark.ab_generation.joint_tail frame --reference-root /tmp/joint-review-new --out /tmp/joint-tail-frame-new
python -B -m benchmark.ab_generation.joint_tail execute --reference-root /tmp/joint-review-new --sample /tmp/joint-tail-frame-new --energyplus-dir /Applications/EnergyPlus-24-1-0 --workers 2 --out /tmp/joint-tail-physical-new
# 仅重放公开冻结A目录的取样，无需引擎或旧人群：
python -B -m benchmark.ab_generation.joint_tail frame-frozen --reference-root benchmark/ab_generation/validation/joint_tail/frozen_inputs --out /tmp/joint-tail-frozen-replay-new
```

输出目录必须全新。两个执行worker只并行运行独立的已冻结请求，顺序和结果不会反馈到抽样。跨引擎/平台重算A可改变上下文哈希与具体抽样；公开冻结A用于精确重放同一目录，不能代替重新验证A物理回执。实际结果及缺额见 `JOINT_TAIL_VALIDATION.md`。
