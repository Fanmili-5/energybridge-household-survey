# 家庭到A/B及单B选题：内部方法复核

日期：2026-11-09。范围：既定家庭之后的日常A、候选B、选题及整份计划reward用途；不重开已冻结的国家比例和家庭生成规则。

## 判断

“固定日常A，生成候选B，再为每道题选择一个B”的设计合理，适用于判断日常安排的调整是否值得接受。候选数与问卷题数不同；最终一题是一份A与一份B。候选生成不等于替真人判断赢家。

当前整套实现需要大修，不能验收为可发放、可训练或已与RL接通的数据集。测试仅支持其所覆盖的执行和选择层。

## 已检验和本轮修补

- 公开合成池200条候选，涉及两个模拟家庭、每户10个日期，最终选择20题，每个家庭/日期恰好一个B。输入倒序后选择相同，输入未被改写。日期复制仅用于测试选题槽位，不作为生活真实性或正式1000户证据。
- 选题使用命令可推导的名义削峰方向、任务数量、改动类型、服务余量和偏好张力做覆盖；物理结果和真人答案不能进入选题。不得将“结果盲选”写成完全不使用任何分析量。
- 发现选择器会接纳明确标记native执行失败、但engineering_issues为空的缓存记录；已补上失败、禁用及不完整执行审核的拒绝门禁。旧版没有该审核字段的记录仍只属于旧版路径。
- 发现新版家庭入口省略配置会落到旧API默认协议；已改为读取CURRENT_CONFIG，显式历史回放配置保留。
- 67项相关测试通过，包括完整程序/充电反例、每题单B、固定十题计数、结果隔离、选取重放、新增门禁及入口协议。

## 修订顺序

1. 接通冻结家庭到日期化世界、真实服务需要与日常A，并验证A/B能由EB主方法的电器接口表达和执行。
2. 在同一A上生成可执行B；接入已确认的六类内部覆盖口径，选取规则在结果与真人标签产生前冻结。
3. 先验收八国×六类的小样及完整时间轴，再分别计算A/B后果并生成正式材料。
4. 通过每题单B、每户十题、源版本、执行、后果绑定和呈现检查后扩量；真人标签产生后另行验证reward用途。

“机械可执行”“贴近日常生活”“偏好模型适合RL”是不同的验收要求，不能互相替代。新1000户正式问卷及物理运行仍为0，正式释放关卡未通过。

## 验收范围更正（2026-11-09）

用户明确要求对齐EB主方法电器调用。此前将PPO基线特定8维动作范围列作本阶段硬门槛不成立，该条撤回。主方法以washer/dryer/dishwasher_start_h、ev_mode、ev_charge_start_h/end_h、热水器预热参数及空调温控等字段调用设备，合法性由家庭能力、服务约束和主方法校验决定。主方法文档明确以22.0举充电开始例子，因此不能仅因超过PPO基线20:00上限而否决。

替代验收链为：家庭需要 → 完整A/B计划 → EB主方法计划字段及校验 → 实际电器调用 → 对应执行后果。本次更正不代表该整条链已经接通；底层设备类回放通过仍不能代替主方法调用链通过。
