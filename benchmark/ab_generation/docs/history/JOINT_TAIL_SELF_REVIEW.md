# 新联合长尾验收自查

本轮自查区分实现正确、数据完整、覆盖接受和外部有效性。具体结果见 `JOINT_TAIL_VALIDATION.md`；结论是实现与回执复核通过，但18个必验层只完成17个，不能称benchmark全面验收通过。

## 查到并处理的问题

1. 原文档仍写“两族静态通过候选配对”，与新生成器不一致。现已统一为独立需求单位、同族多批和高阶联合，明确有限预算与未覆盖空间；旧规则只用于显式历史回放。
2. 仅看设备族会混淆“多台设备”和“多个独立任务”。增加请求单位数、族数、同族多批和供电风险四个轴；洗衣及关联烘干作为一个单位，实际响应仍逐设备核对。
3. 关联烘干不能继承洗衣机的控制权限。现在最终服务链检查每个改变任务对应的资产权限；新增回归验证此边界。压力白名单也不能豁免该问题。
4. 新能耗模型改变费用取舍后，旧目录的洗衣费用增加层不再有候选。没有降低门槛或改种子；必验缺额和严格验收失败被保留。CI验证已知失败状态能重现，不以软件检查绿灯代替覆盖接受。
5. 上界未认证不等于实际超限。两个事前供电压力样本中，一个没有超限、一个超限，均原样保留；EV出发不足、两组无响应和混合响应也保留。

## 证据反查

- 首次正式B执行前的完整计划、全部规则、9,275条去重目录和19条选择已经封存；执行前后选择SHA完全相同。
- 19条均有去向：2条静态诊断、17组配对/34个引擎臂。没有模型或读回错误获得正常覆盖信用。
- 逐批核对原身份、批次能量、程序与时长不变；导出B哈希与选择相符，17个配对A均完整复现原参考。
- Python3.9.6/3.14.3对固定结果重算一致；146项A/B检查及含住房/家庭接口的218项检查通过。
- 公开冻结A重建的样本与原样本、分层及命令哈希一致。原13条历史样本仍用旧规则精确回放。
- 严格覆盖门返回失败，缺失洗衣费用增加层。其他监测缺额和928个未选中单/双因素格没有隐藏，也没有后果驱动的补位。

软件重算证明统计与准入逻辑一致，不替代从SQL重新仿真。原生SQL、IDF、完整变体和日志封存于本地证据；公开输入、固定版本及命令支持重新生成。原始结果、完整覆盖表、索引和数据状态见 `validation/joint_tail/`。

## 尚未成立的结论

3个合成家庭不证明人口代表性；8个情境不是8户。当前只验证工作日降载，周末、增载、冬季、重叠多事件和未枚举高阶剂量仍有范围缺口。28次有依据目标出现不是独立样本数，也不能估计真实无响应率。

联合响应可能包含设备耦合，不证明每条子命令独立的因果效果；数值非零不保证人能感知。洗衣相对形状的单设备来源、人工绝对尺度及烘干近似未变成家庭实测校准。没有推断人的接受、满意度或真实授权，也没有把供电区间功率检查当作电气安全认证。

线上问卷、原50户发布包及答卷未修改，1000户仿真继续暂停。
