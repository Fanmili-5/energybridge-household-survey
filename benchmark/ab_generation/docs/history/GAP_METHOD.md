# 三个缺额的计划规则修订

本轮按**计划设计与可解释性**验收，不要求新增EnergyPlus运行。静态有效表示满足声明的日程、依赖、授权和已知功率约束；不表示实际能耗、温度或人的接受程度已经验证。物理后果属于后续可选验证。原 `validation/joint_tail` 的22层、19个样本、17/18历史物理验收结论及全部失败样本保留，不用新版本回填。

## 缺额来自哪里

| 缺额 | 固定原A的诊断 | 修订 |
|---|---|---|
| 洗衣费用增加 | 多批原六档有20个预测正差请求，但均静态无效；完整10分钟网格有1个静态有效正差请求 | 在同一±120分钟内使用全部24个非零10分钟档位 |
| 同族多批联合 | 原144个两批剂量组合有0个静态有效；细网格2304个组合有6个 | 保留单独无效的原子候选，在联合后重新检查冲突，避免漏掉相互修复的组合 |
| 冬季制热 | 原8个情境均为7月15日，原生事件窗制热为0 | 事先固定独立12月16日情境；分别报告计划有效性与可选物理结果 |

两批同时后移40分钟，是可核查的联合见证：洗衣开始由18:20/20:00变为19:00/20:40，各自烘干与装取随链移动。单独移动第一批会与第二批原机器占用冲突，两批一起移动则通过完整原A检查。原六档没有40分钟。全部6个见证见 `validation/gap_supplement/CONSTRUCTIVE_WITNESSES.json`。

费用正差约0.001126元，口径是请求所移动的洗衣及依赖烘干链的预测电费差，不是实际全户账单，也不能据此认定人能感知。这一层证明成本符号的设计有覆盖，不证明损失幅度足够用于问卷。

## 生成和检查怎样做

1. A先由固定家庭需求、生活安排、设备、习惯与授权生成。B不得反向修改A，不通过电价或事件塑造A来凑差异。
2. 程序设备枚举24个移位与 `timer_only` / `shift_chain` 两种模式，保留任务身份、程序时长、批次质量和能量。热控及EV沿用已登记的剂量。原六档默认值仅供历史或显式稀疏设计复现；输出 `program_shift_domain` 明报漏档，不能把稀疏目录为空解释成没有机会。
3. 联合搜索按任务单位而非设备类别计数：两个洗衣批次可联合，同一任务的互斥剂量不可同时使用。对声明的任意两单位剂量组合完整枚举，再补高阶单位及设备组合见证，预算32768；不声称高阶全部剂量穷尽。
4. 对完整组合B重算：不能改过去或越权；装载须在需求释放后、程序须在装载结束后；取出须在程序结束后；洗衣→烘干依赖正确；同机含取出前占用、操作者及房间不能冲突；须满足机器窗口、EV连接与已知负载/供电约束。基于上界不能认证的功率状态明确标注，不能伪装成已验证物理安全。
5. 无效候选原样记录原因，允许作为诊断/roleplay负例；有效候选也不只保留最优项。A=B是显式对照。后续若执行B，无响应、反向响应、服务失败都保留；引擎错误与数据缺失另记，不冒充物理失败，不因结果不好重抽。

检查实现还消除了全历史装取的重复扫描，改为按任务ID建立首条取出索引；字面补丁在返回边界深复制以隔离输入。首条重复取出、缺取出则占用至时域末的原语义不变。优化前后两个完整生成输出共11565个请求逐字节相同，见 `GENERATION_EQUIVALENCE.json`。时间投影只用于缺额诊断；全部合法见证再用完整A检查，108个原粗网格请求与完整检查的原因及预测相符，不能把投影当新A。

## 新版本怎样固定与覆盖

`examples/gap_supplement/scenarios.json` 固定3个A情境、2个公开合成家庭：夏季1.2kg、5.1kg和冬季单人家庭。两个夏季生活输入与完整A命令与原批次相同。冬季固定2025-12-16、生成历2025-08-01至2026-01-01，沿用原设备与习惯；夏季事件18:10–19:10，冬季沿用08:00至次日08:00宽窗口。日期、24档、120分钟、32768预算、种子20261019、10个层及每层配额均为人工实验设定，不是文献估计或人口比例。

`tail_plan.json` 保留费用增减、同族有效/无效联合、制热上调/下调、其他无效、A=B、探索性制冷及高阶联合10层。正式抽样仍使用原 `sampling.py`：指令规范化去重、首个匹配层独占、先家庭后请求的固定哈希优先级；不看实际B结果。后续静态最终取样已补齐，见 [FINAL_SAMPLING_METHOD.md](FINAL_SAMPLING_METHOD.md)：使用原三情境的全部设备目录，17631个去重请求按原计划取10个，十层各1个；421个可用单轴/双轴组合仅覆盖218个，203项缺失原样记录。未运行候选B，不将旧11565个原始请求、全部目录数或层配额当作实际物理响应或人口代表性。完整结果见 [GAP_VALIDATION.md](GAP_VALIDATION.md)，旧正式样本不变。

冬季已有的A/A先导记录保留：A存在制热负荷，但未满足原舒适要求，原因记录见 `WINTER_CAUSE.json`。这不否定10个制热候选的静态有效性；其中8个有已有A状态的机制支持（上调、下调各4个，逐条补丁见 `WINTER_PLAN_CANDIDATES.json`），支持也不保证实际响应。`A_STATUS.json` 与 `gap_review prepare` 是旧物理流程的准入记录/辅助工具，不是当前计划设计的准入门槛。冬季物理失败不删除、不更换家庭、不放宽要求，也不计作物理通过。后续是否进入正常物理配对或专门的失败情境实验，另行确定；本轮不执行。

## 科研依据与适用边界

- [Apaydin-Özkan 2021](https://doi.org/10.3390/s21093287)支持可控窗口、离散调度、不可中断任务与累计功率约束的建模。论文不提供我们的生活安排、10分钟、120分钟或配额，也不验证本生成器。
- [Lei等2007 IPOG](https://www.nist.gov/publications/ipog-general-strategy-t-way-software-testing)和[NIST SP800-142](https://csrc.nist.gov/pubs/sp/800/142/final)支持明确因素水平、交互覆盖与预算边界。我们实现的是两单位剂量枚举加高阶见证，不称为IPOG实现，不以二因素完备推断全局最优或全部后果。
- [EnergyPlus24.1供暖盘管参考](https://bigladdersoftware.com/epx/docs/24-1/engineering-reference/coils.html#single-speed-electric-heat-pump-dx-air-heating-coil)用于解释已有冬季物理诊断；原模型−15℃运行下限是项目设备参数，不是所有热泵的通用常数。该模型不作为本轮计划验收前提。
- 原EB固定版本、公开来源与许可边界沿用 `SOURCES.json`、`AUTHORIZATION.json`。新增的是自有合成配置、代码与诊断，不新增真实住户数据、控制授权或人类偏好标签，不复制论文全文。

## 完整未来A的离线条件

完整A未来日程允许生成器核对后续任务、机器占用及服务期限；可用的已有A状态轨迹只作离线oracle机制筛查。两者均须声明信息条件，不表示现实决策时已知未来真实行为、温度或电量。缺少物理状态时不能宣称已证实热控响应；可保留计划为待验证/探索，不阻止日程与授权检查。静态计划、已有机制依据、实际响应、服务后果和人类接受分别报告。

这次修订由旧缺额诊断触发，不是旧实验的事前注册。验证仅限公开合成情境及声明离散空间，不保证任意家庭无错或完整benchmark就绪。线上问卷不动，1000户继续暂缓。
