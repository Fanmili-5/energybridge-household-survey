# 按EB主方法审核家庭A/B构造

2026-11-09内部方法复核。验收目标以用户纠正为准：对齐EB主方法的计划校验、实际电器调用和执行语义，不套用PPO基线固定动作范围。已冻结的家庭数据与国家/角色配置不重开。

## 审稿结论

方法方向可保留，当前实现需要大修，正式数据验收未通过。内部候选多个、每题最终仅一对A/B，与比较家庭日常安排和调整提议的任务相符；不能以接口测试代替生活合理性及完整物理验收。

## 新增直接检验

使用上游固定提交`2b17ae63e613da776c93e900f5dace50d63a88a8`的原始规划校验模块，以及family_runner主方法电器应用函数原样节选，调用隔离的同版本电器套件。规划模块和直接依赖的Git blob已与官方原件核对。未执行完整family_runner；未启动LLM、EnergyPlus、真人数据读取或训练。

八项公开合成检验通过：

1. 日常A通过计划校验，五类电器指令原样接受；洗衣、烘干、洗碗完整运行，EV完成名义补能。
2. 响应B通过计划校验，22点充电由主方法实际接受，并按连续会话完成；证明22点本身不因PPO基线范围而非法。
3. 先向套件写入A的充电安排，再改B，会触发已有充电窗口保护；比较A/B必须从对应初始状态分别分支，且明确哪些承诺在决策前已经存在。
4. 已启动的洗衣程序重新移时被拒绝。
5. 在显式合成规划约束没有包含该热水器运行时窗口上限的情况下，通用校验允许10—17点，实际应用函数却将其裁剪为13—17点。这个反例要求家庭约束传全，并核对实际接受的动作；不据此声称真实完整主方法必然遗漏同一约束。
6. 早于车辆到家的充电计划被规划校验拒绝。
7. 补能窗口不足的计划被规划校验拒绝。
8. 响应B的充电窗口与声明VPP冲突时被规划校验拒绝。

这些参数是明确的公开合成测试设定，不是新1000户的数据。A按普通服务、B按响应场景检查，不能用本次组件测试比较真实A/B节电收益。空调只检查了计划字段约束，没有验证EnergyPlus空调执行；热水器只验证动作应用，没有验证水温后果。

## 审稿问题与验收要求

| 优先级 | 问题 | 当前证据 | 必须补齐 |
|---|---|---|---|
| P0 | A是否贴合对应家庭生活 | 新1000户日期化A仍为0；合成接口输入无法回答 | 从该户生活、设备和服务需求编译A，检查真实装取窗口、洗烘顺序、共享设备及补能；不因拥有电器就每日制造需求 |
| P0 | 展示计划是否等于实际执行 | 新反例证明应用层可能拒绝或裁剪请求 | 保存原请求、验证后计划、实际接受指令和拒绝/修改记录；有实质变化时先冻结最终执行方案，再跑后果并出题 |
| P0 | A/B分支是否可比较 | 先写A再改B可触发承诺保护 | 相同家庭、日期、天气及决策前状态分别运行；已发生服务和既有承诺在双方保持一致，不复用A运行后状态作为B起点 |
| P0 | 后果是否来自对应计划 | 新正式问卷和物理运行均为0 | 对各自最终计划计算物理结果，绑定计划与初始世界、模拟器版本；正式材料按已确认UI91口径展示双方后果 |
| P1 | 六类内部细分覆盖 | 既有选题目标仍为家庭和全局范围 | 按六类分别核算有依据的候选与入选覆盖，保留每户10题及缺口台账，不捏造任务补覆盖 |
| P1 | 每题只选一个B且不泄漏答案 | 既有公开合成池200候选选20题、每户10题，67项相关测试；本轮Python源码未变 | 正式批次重验恰好1000×10题、每题仅A/B一对、选择规则冻结、结果/答案隔离、展示及回写映射可追溯 |

空调必须在每户配备并纳入控制；具体日期是否需要运行应由季节、人员在家和舒适服务需要决定。不能用开启所有电器制造看似完整的覆盖。

## 通过标准及下一步

先完成一户从家庭到完整A/B、主方法实际接受记录、独立分支物理后果和可读问卷材料的闭环；再在既定八国×六类小样上检查生活合理性及调用一致性，之后扩到1000×10。新增八项组件检查与此前67项检查不是正式1000户完成证明。

主方法字段与调用口径已经核对，但新版家庭日期化适配、完整主方法/仿真runner集成、六类内部细分覆盖和成对后果材料仍未完成。后续reward model的性能另行评估，不把某个RL基线动作范围作为当前数据的硬限制。
