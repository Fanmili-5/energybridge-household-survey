# 面向用户roleplay的A/B生成规则

本次修正规则和算法，服务于后续角色扮演情景供给。普通提案、探索性请求、无效响应和服务失败均可提供不同生活取舍。没有把物理成功当作接受答案，也没有按执行结果挑选更好的B。源码为`life.py`、`opportunity.py`、`generate.py`、`sampling.py`，实际逐设备回读为`effects.py`。

## A：从明确的服务条件构造正常使用

| 电器 | 生成时的保护 | 仍需声明或验证的量 |
|---|---|---|
| 洗衣 | 有衣物库存才形成批次，容量内分批；原人员装载、完整程序、取出；检查已知硬件批量上限和程序功率上限 | 衣物进入量、每日/满批政策、习惯、期限、时长；未知硬件容量不伪造为已核验 |
| 独立烘干 | washer的唯一完整批次后继；洗衣取出后再装入；自身功率、时长、期限和资源约束 | 只支持完整转移，未建模晾晒、分流和重复烘干 |
| 洗碗 | 在家晚餐才形成家中餐具需求；按在家参与者计数；保留装取和完整程序 | 固定程序、晚餐服务映射；早午餐餐具库存与多程序选择未实现 |
| AC | 独立占用、温度要求、控制习惯和双设定；保留风机、权限和区间外控制 | 人的未知温度要求继续为null；设备模型和热环境按固定住房版本解释 |

| EV | 初始能量不超过容量，效率和SOC边界有效；原行程、实际插拔和连续能量账；不足保留 | 当前一车、同日往返、固定功率充电模型；不补外部充电或隐含帮手 |

程序排程使用10分钟候选时刻、先后依赖和人员/房间/设备不重叠约束。习惯偏离和等待代价采用已有项目权重，逐批贪心；没有声明全局最优，也没有用VPP或电价优化A。需求无可行安排仍保留，不能进入正常物理基线。设备用量、频次和程序参数尚未全部实测校准；新增边界保护不等于完成校准。

## B：先证明请求针对什么机会，再构造变化

### 程序与EV的逐时剖面

程序设备保持原批次、原完整程序、操作者和服务约束。EV从实际A剩余充电开始，在原许可和物理连接内暂停并重新分配剩余能量。生成时计算每个目标设备在主区间的

`L1 = sum_t abs(E_B_profile(t) - E_A_profile(t))`。

全天净电量或电费相同仍可能存在移时。只有每个涉及设备的剖面具有数值上非零的变化，才给出`status=supported`。这个量来自声明功率和A剩余充电的解析代理，不是最终B仿真结果，更不是节能量。静态服务不足仍单独标记，不被解析变化掩盖。

### 热设备的状态与阈值

额定功率余量仅用于搜寻候选。候选还须检查原生A轴向负荷、当前状态、新设定及持续区间：

- AC增载检查温度位于新制热/制冷目标要求运行的一侧且有名义余量；降载还须有对应A线圈运行，并使新目标进入停止/减小需求的一侧。保留另一轴和风机。当前固定模型使用空气温度双设定；不能把该关系直接用于不同的温控器模型。
- 水箱不把平均温度当作已知的加热器感温点。新A参考携带前一报告边界的全部原生分层节点。设目标为S、死区为d：增载使用`max(nodes) < S-d`的充分筛查；降载在A确有加热的条件下使用`min(nodes) >= S`。边界比较使用公开数值精度。
- 缺节点、死区或未满足状态条件，标为`exploratory`，保留具体原因；不能只因静态无冲突就标作已获状态支持。

这些条件是基于完整A的离线、采样状态筛查。B改变后的热状态、5分钟求解与10分钟报告间的启停、设备耦合和恢复可能不同，故`actual_response_confirmed=false`。它们不承诺必然响应、目标达成或人的舒适与接受。

### 时间窗口及联合请求

对每个剂量/时长，先枚举原许可内的窗口。保留原“最长、再最早”代表；若存在不同的、有状态依据的窗口，再增加一个“有依据优先、最长、最早”的代表。相同区间归并。没有读取B后果，也没有只保留较好的窗口；本方法不是所有连续启动时刻的穷举。

三种单设备方法对照只从静态通过且有机制支持的候选选择。全目录继续保留探索性请求与静态失败。当前联合B覆盖同族多批及2至全部独立单位，保留有静态问题的单请求参与联合重查，并逐子请求记录依据：`all_supported`、`mixed`、`all_exploratory`。一台设备有依据不能替另一台提供依据；组合的实际相互作用仍须重新执行。

`admission=normal`只表示静态准入。`opportunity=supported/exploratory`是另一维度，不能把normal解释为已交付有效调节。故意EV目标不足、其他静态冲突、引擎/数据错误继续分开处理。

## roleplay覆盖与防退化

新版最终静态取样与验收见 [FINAL_SAMPLING_METHOD.md](FINAL_SAMPLING_METHOD.md) 和 [GAP_VALIDATION.md](GAP_VALIDATION.md)。十层配额10/10；可用单轴/双轴水平组合218/421，缺203项。静态有效与冬季既有物理失败分开记录。下述实际响应门槛留待后续可选物理实验，本轮不执行、不作为计划验收条件。

既有正式小型计划为[examples/joint_tail/plan.json](examples/joint_tail/plan.json)，历史计划为`examples/rule_review/plan.json`。缺额诊断后的新版本为[examples/gap_supplement/tail_plan.json](examples/gap_supplement/tail_plan.json)：完整24个非零10分钟档位，报告`program_shift_domain`及联合交互覆盖，旧六档只保留稀疏设计/历史复现用途。在第一个B运行前，封存完整目录、命令去重、种子、独占分层和家庭→请求两阶段抽样。覆盖设备、剂量、时长、方向、人工策略、预测费用符号，以及新增的`opportunity`和`joint_support`。记录还携带原实验日期的`day_type`与固定事件的`event_direction`；不得为填层改写生活日历或事件。保留缺额，不跨层换成成功B。

计划明确包含有依据和探索性请求、不同任务数联合、同族多批、费用增加取舍、A=B对照、静态拒绝和声明的服务失败。执行后逐目标设备报告用电时点、实际执行时点、温度和SOC，给出`all_targeted_assets_change`、`mixed_target_response`、`no_target_response`和`identical_control`。只有EV变化的联合B不能当作热水器已有作用。相同案号下的原生B轨迹指纹另报，命令不同不自动算独立物理后果。

本计划要求六种设备至少各观察到一次变化，并要求有机制支持的目标设备中无响应比例不超过1/2，防止该子集多数为空操作。该1/2是“拒绝多数退化”的项目验收预算，不是论文估计、真实无效概率或人能感知的阈值。探索性、对照和失败分别报告，不用它们稀释这一分母。达不到时整批验收失败，所有原样本和结果仍保留，不重抽。模型/读回错误不当作可解释的无效响应或用户拒绝。

分母按每份提案中的逐设备依据计算：混合联合中的有依据子设备仍计入；程序链按各资产非零解析L1计入，不因整条链的exploratory标签抹去。缺少这些设备的读回时记录缺失并验收失败，比例保持未知，不能当作无响应或成功。这里计数的是目标出现次数，不是独立电器或家庭数。

数值守卫为剖面/电量1e-9 kWh、温度/电池状态回读1e-7（相应单位）；只区分计算意义上的变化。没有以此声称问卷差异已经足够明显。连续值、分层缺额及单/双因素未覆盖表同时发布。
