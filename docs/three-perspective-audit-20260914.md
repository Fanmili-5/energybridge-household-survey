# 问卷系统三视角审计（2026-09-14）

> 历史记录，保留当时的测试结果和设计依据。项目使用说明见[文档目录](README.md)。

审计代码：`59337c486219040c523c9402c7d1a61ffa19ea68`。问卷 v4.5 / 页面 v6.9 / 配对流程 v3.5 / 参与者视图 v2。

**结论：可运行、可追溯，可以准备开展小规模真人预试；尚不能据此宣称量表已验证、全国样本有代表性、全部设备体验已测量，或 50 人同时生成时有低延迟保证。** 本轮不改变 EB 策略、问卷答案、计费 API 设置或正式采集开关。

研究对象是：一名家庭代表填报家庭事实、代报成员偏好，并基于明确的模拟情境，对原安排和 EB 调整给出接受/拒绝、四项评分及原因。它不是逐成员独立访问，不是观测真实用电行为，也不等于采集了全家协商后的共识。

## 1. 问卷设计者：这些数据能回答什么

| 检查点 | 已核实 | 结论与边界 |
| --- | --- | --- |
| 与目标匹配 | 家庭事实与偏好进入 EB 可观察资料；可选研究信息独立保存；不强制归入五类预设 | 能收集面向家庭代表判断的条件化监督样本 |
| 标签来源 | 接受/拒绝、四项分数、原因来自提交；缺失不补分；不使用模拟成员投票充当真人标签 | 真人标签必须在正式采集模式下产生；代理填报的成员态度不能冒充成员本人回答 |
| 选项含义 | 控制偏好三档；温度/任务调整三档；重要程度五档；保存问题和选项快照 | 比旧重叠选项清楚，但尚未做真人认知访谈，不能称为经过信效度检验的量表 |
| 评分解释 | `score` 整体，`comfort_score` 舒适，`energy_score` 用电与费用满意度，`vpp_score` 响应处理满意度（含自主决定体验） | 后两者是综合评价，不能直接称为独立的“价格敏感度”或“控制感”心理量表；四分也不是同一潜变量的重复测量 |
| 情境覆盖 | 日期在填答前按会话稳定抽取，全年 365 日；VPP 1–2 小时；天气与住宅由注册资源匹配 | 增加情境多样性，不等于实现人口随机抽样；典型年天气不是该历史日实况，住宅不是实测校准的用户住房 |
| 对照与筛选 | 原生 `no_dr` / `agent` 两路；同一 IDF、天气；无变化、低收益、技术回退不按效果剔除 | 能保留多种策略结果。API/EP 失败是技术缺失，不是拒绝；仍须观察不同情境的失败和未评分分布 |
| 可重复核查 | 问卷、家庭、情境、两方案、展示、反馈和原生文件都有保存与哈希关联 | 具备数据审计基础；版本和同一浏览器下的重复案例需在分析时保留分组 |
| 数据身份 | `household_id` 是浏览器会话代理标识 | 不能保证一个 ID 就是独立真实家庭，不能把提交数直接称为独立家庭数 |

**仍需补足的结果信息：** 目前 EV 离家电量达标、热水使用时达标在参与者页面显示“本次未验证”。原 EB 虽有 `target_reached`、`soc_end`、`ready_at_bath`，但不能直接改成物理舒适性结论：`soc_end` 是结束时状态；`ready_at_bath` 的原始实现可基于累计加热能量是否大于零，不是 EP 出水温度检查。应对齐具体离家/用水时刻及数据来源后补充。现阶段只能研究参与者对已展示信息的判断，不能声称完整覆盖这两类服务体验。

**方法依据：** AAPOR 建议问题聚焦、选项互斥且有逻辑顺序，并在投放前预试；CDC 的认知访谈用于检查理解、回忆、判断和选答过程。它们支持上述审查方法，不证明本问卷或后续 SFT 已有效。

- [AAPOR：问卷设计与预试](https://aapor.org/standards-and-ethics/best-practices/)
- [CDC：认知访谈](https://www.cdc.gov/nchs/ccqder/question-evaluation/cognitive-interviewing.html)

## 2. 工程设计者：链路是否能可靠完成

本轮启用原生 EP 检查后，**195 项测试全部通过，0 跳过，耗时约 44 秒**。测试框架使用假模型凭据、固定模型替身并禁止外网连接，付费 API 调用为 0。

实际覆盖：

- 非夏季原生基线（1、4、10 月）、冬季完整配对、广东/上海/北京区域输入、原生设备接口、十分钟任务时钟与电表一致性。
- 家庭答案到真实 EB 提示输入的传递、保留原生技术分支、执行轨迹和展示冻结、接受/拒绝及小数评分保存。
- SQLite 持久化、重复提交幂等、重启恢复、越权读取阻断、结果或标签被篡改后的导出拒绝。
- 50 路家庭资料同时保存及有界任务准入。准入测试特意使用低容量配置，验证超额返回 429 且已保存资料不丢失，并不代表全部生成请求都应立即执行。
- 验证码绑定会话和请求、过期、三次错误后失效、成功后不可复用、管理员与参与者入口隔离。

线上只读核对：页面可访问、v4.5 三档控制选项正确、绘图脚本哈希一致、仍为 `engineering`、验证码和生成均启用。现有 2 份家庭资料均标为工程测试；3 个任务、21 个文档保留。

当前实际配置：网站任务工作槽 16、待处理上限 128；每浏览器最多 2 个任务、每天最多 250 个任务；计算端 EP 槽 32、API 槽 4。单任务超时 1200 秒，队列等待上限 2400 秒。这些是资源保护上限，**不是用户可接受等待时间的验收成绩**。

旧的 50 案例测试报告显示去重、恢复和保存通过，但使用固定模型替身、0 次付费 API，且关闭了当时的队列等待保护。不能把其约 18 秒批次结果迁移成线上 50 人真实模型规划的性能承诺。当前瓶颈仍可能是 API 服务时间、速率限制与多轮规划。

图片验证码与浏览器配额提供有限防滥用能力，不是实名去重，也不是 OCR 攻击或大规模攻击的完整防御证明。

## 3. 填写者：能不能看懂并顺利完成

复核了同版本上轮手机 390px 与桌面 1365px 的完整浏览器测试和截图：填答、验证码、等待、自动进入对比、四项小数评分、原因、保存及刷新恢复均走通。本轮没有再次发起线上收费生成。

已经改善：控制选项不再重复；时间十分钟一档、温度 0.1℃；上方调整前/下方调整后的完整时间轴；所有结果指标直接可见；新结果不展示 EB 内部复查理由；未知服务结果没有伪装成成功。

**还存在的阅读负担：**

- 问卷题库共 66 个条目，按设备和住房条件分支，并非人人都答 66 题；成员列表另有每人 10 个字段，其中仅生活节奏必填。三人成员页的手机测试截图高 4944px，按 900px 视窗约 5.5 屏。问题清楚不等于填写短，后续应优先考虑逐位成员填写，保留选填能力。
- “相对成本单位”、运行功率与耗电量、空调设定与室温仍需要理解。当前有说明，但只有真人预试能判断说明是否足够。
- 六设备对比截图约 2.3 屏，评分约 0.9 屏。手机完整时间轴仍须横向滑动；需要确认参与者会发现并使用。
- 测试证明按钮与保存链路可用，没有证明完成时间、认知负担或放弃率。现有收集漏斗从家庭资料保存开始，不能完整统计保存前退出或每题耗时。

## 4. 进入正式采集前的顺序

1. **小规模真人预试。** 建议先找 5–8 人，覆盖不同家庭人数与手机使用习惯；这是本项目的起始建议，不是统计充分性标准。让他们复述控制三档区别、指出错峰时段与主要变化、区分相对成本和人民币、区分空调设定和室温。人工记录填写/等待时间、卡住的位置和评分缺少的信息即可，不必给正式问卷继续加题。
2. **补全有明确来源的服务结果。** EV 对齐离家时刻，热水对齐用水时段与温度；未验证状态继续保留，不能凭已有粗略标志补成“满足”。
3. **按真人预试优化成员页，确认真实 API 等待体验。** 使用自然产生的试填任务观察延迟，不用批量收费压测替代。
4. **冻结问卷与显示版本，再启用正式真人采集。** 目前保留工程模式；正式模式需要切换。不能直接把工程记录批量改标成真人样本。
5. **观察数据覆盖和丢失。** 已有漏斗可检查保存后生成/评分/导出的损失、地区月份设备分布、无变化/回退和分数分布。不同问卷版本按快照解释，不按接受率或节电大小筛掉样本。

本轮未发现上述测试覆盖范围内的阻断故障；发现的限制主要是服务结果完整性、真实填写负担、正式模式准备和收费 API 下的等待体验。数据采集链路可行不等于已证明训练收益；训练与独立评测仍由后续负责人员完成。
