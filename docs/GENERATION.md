# 家庭与A/B生成总览

[规则依据表](GENERATION_RULES.md) · [复现层级与命令](GENERATION_REPRODUCIBILITY.md) · [覆盖和分组统计](GENERATION_STATISTICS.md)

目标是一份完整用电计划的真人判断题：给定家庭、当天生活与任务，比较日常安排A和调整方案B。后续配上同版本仿真后果，由真人填写接受/拒绝、评分和原因。

目前已完成家庭与计划输入，尚未完成本版物理后果和真人采集。以下说明对应封存的1000户×10题，不把工程检查当成居民接受度的证据。

## 1. 家庭从哪里来

| 国家 | 家庭调查来源 |
|---|---|
| 中国 | CRECS 2012 |
| 美国 | RECS 2020 v7 |
| 英国、西班牙、德国 | ENABLE.EU，2019发布版 |
| 印度 | IRES 2020 |
| 墨西哥 | ENASIC 2022；住房另用ENIGH 2024参考匹配 |
| 澳大利亚 | ECA 2025能源消费者调查 |

选国依据是逐户数据可取得、字段可映射和家庭/能源情境互补。八国各125户，用于均衡比较各国情境；每国均有六类角色。这是实验配额，不是全球人口抽样。

六角色采用EB原论文附录A表7的角色扮演调查构成97/116/73/88/91/119，通过最大余数法分成166/198/125/151/156/204户。角色和态度采用EB实验定义，不由问卷答案或节电效果反推。

## 2. 怎样生成完整家庭

算法为：调查字段归一化 → 国家/角色配额 → 固定种子的相容源户选择 → 联合生活安排补全 → 整数规划分配控制组合 → 审核并冻结。

保留同户的成员、住房、设备和可用生活约束；缺少的精确年龄、钟点、参考面积等按明示规则补齐，跨调查住房匹配单列来源。参考周包含工作、通勤、上学、接送、照护、用餐和洗浴，检查同一成员不能同时出现在冲突活动中。原调查字段与参考条件分开保存。

每户控制4—6类功能：空调、洗衣、烘干、洗碗、热水、EV。空调每户必备且必控，F类含EV；4/5/6类分别333/333/334户。来源没有空调时，在参考情境中补充，保留原调查记录。背景电器不进入这六类控制覆盖目标。

详见[家庭算法和依据](../benchmark/household_stage1/generator/METHODS.md)、[字段依据表](../benchmark/household_stage1/generator/EVIDENCE_MAP.md)。

## 3. 怎样从家庭得到A和B

首先固定任务，之后才生成方案：

- 洗衣：前一天换下的同批衣物；烘干接这批洗衣。
- 洗碗：明确指定已有餐次的餐具，吃完并准备好后才允许运行。
- 热水：对应已给定的洗浴服务；EV对应连接窗口和补能目标。
- 每题是一个独立日情境，同户十题不是连续十天的车辆状态模拟。每日完整程序是题目设定的工作负荷。

A用单线程OR-Tools CP-SAT安排洗衣、烘干和洗碗的完整程序，满足准备/截止、同批先后及共享设备独占。目标先尽量避免22:00后结束，再减少参考时刻偏移和洗后等待。22:00是A的软偏好，不是B禁令；A不读取B、响应收益或真人答案。

本版洗衣/洗碗/烘干采用120/90/90分钟、1.5/1.2/2.5kW，来自锁定的原EB persona参数。AC和热水采用明确的参考服务规则；EV按给定连接与目标SOC连续补能。

B使用原EB主方法动作域内的受约束组合搜索（IPOG-C式）生成多个候选：

| 功能 | B可改变什么 |
|---|---|
| 空调 | 原方法可调用检查点上的制冷设定温度 |
| 洗衣、烘干、洗碗 | 整段程序启动时间，保留时长、功率、同批顺序 |
| 可控热水 | 加热许可窗口和目标温度 |
| EV | 给定连接内的一段连续充电许可窗口，保留硬件和目标SOC |

程序不拆成十分钟开关片段；没有另加停冷、装卸或插拔动作。10分钟是指令网格。空调设定、热水许可和EV许可分别与实际室温、加热及充电时长区分。

户内整数规划每个日期只选一个B，再用全队列CP-SAT保护每户基础覆盖、覆盖有机会的控制功能及动作细分，争取跨国重复。B可以不受居民欢迎、没有正向名义减电或冲突软舒适偏好；接受标签留给真人。不能为凑覆盖改家庭作息或事后补任务。

原版动作锁定至[EB paper-v1-final/c58a2a7a](https://github.com/Agentic-Intelligence-Lab/EnergyBridge/tree/c58a2a7a3189482f57b93ddd0637f2c58ce5b5d0)。逐项规则及命令见[A/B算法](../benchmark/ab_generation/ALGORITHM.md)。

## 4. 当前是否满足benchmark构造要求

| 要求 | 已核验范围 |
|---|---|
| 来源和家庭结构可追溯 | 1000个不同主源户；八国、六角色配额及48个交叉格成立 |
| 六类控制覆盖 | 每户4—6类、AC必控；4990个有事件机会的家庭×功能项覆盖，另11项有逐日无机会证明 |
| 同题比较公平 | A/B共享家庭、当天任务、负载批次、准备条件和设备要求 |
| 动作可执行 | 20000份原始电器执行证据；完整程序、同批洗烘、连续EV与非EV当天完成 |
| 题位与细分覆盖 | 10000题，每日期一个B；939个当前有完整见证的根动作格均出现，924格至少两国、15格单国 |
| 输入身份与重建 | 10000份任务/事件/A/B/题号/完整输入一致重建；223项相关回归和6项包检查通过 |

这些证据支持将家庭和A/B作为后续配对物理核验输入。939格是声明的有限动作子域，不代表全部连续动作、高阶组合或每格都有跨国重复；原969/969是旧版本成绩。

## 5. 怎样复用与复现

[全队列命令](../benchmark/ab_generation/COHORT_RECIPE.md)区分两个用途：solve从冻结候选池重新求解，reproduce依据明示的历史候选ID锁重建封存版，再与参考数据逐题比较。后者已对当前1000户×10题验证，差异0；它不证明从头重跑全部历史候选搜索和优化会选中相同B。

新求解可能得到不同B，也受预算限制。当前正式数据保留原版924格两国重复；试验新解的918格未替换它。调查原件、真实家庭卡、候选包、选择锁与答卷按许可留在受控存储。
