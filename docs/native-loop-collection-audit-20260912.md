# EB 原生流程重新审计 — v3.1

目标：真人问卷提供家庭输入 → 原 EB 的 `no_dr` / `agent` 两条仿真路径 → 真人接受/拒绝与四项评分。低收益、无变化、原生回退都不作为剔除样本的理由；API/EP 未形成完整结果时不伪造评价。

## 审计发现与修正

| 原问题 | 已修改 |
| --- | --- |
| 我写的适配器以第 72—96 小时为比较日，移植后前三天也调用模型 | `native_scenario.py` 直接生成 0—24 小时和第 1 天事件；不再先生成四天再减 72 小时 |
| 家庭日历仍由旧窗口生成多天 | 当前家庭只投影一天，日历、EP 与图表使用同一时间轴 |
| 原生跳过模拟接受分支内又插入我写的技术预检/回退 | 删除插入语句和整个额外 gate；原规划修正、原执行器自身校验直接保留 |
| 当前 worker 仍导入旧控制器 | CLI 只导入 native worker；旧 runner 显式归为 `legacy_paired_worker.py`，仅历史回归使用；公网旧生成接口关闭 |
| 图表通过加减 72 小时适配旧绘图函数 | 绘图以显式 `start_sim_h` / `end_sim_h` 为准，不再伪造第四天 |
| 原天津分时价格被固定 0.60 元覆盖 | 直接使用 `_prepare_run_assets` 返回的原始价格；按真实单位显示“相对用电成本”，不冒充人民币 |
| 擅自补电器负荷端口、修改 EV 参数与住宅设备 | 删除物理改造和 7 kW 参数覆盖；原住宅和原设备参数保留，仅增加 SQLite 输出格式 |
| 非有限原生诊断指标可能使 JSON 保存失败 | 仅在保存时转为 null，同时记录字段路径；不改控制器状态，不填成 0 |
| 云端原仓库资源不完整，含天津价格文件缺失 | 按固定提交的文件哈希逐项核对和补齐，不用替代数据掩盖资源缺失 |

## 原项目与明确的适配边界

固定提交：`2b17ae63e613da776c93e900f5dace50d63a88a8`。原 `family_runner.py` 保持原文件，并在运行时验证其 SHA-256。

- **控制过程**：原 `run_family_agent` 的整个日内回调 AST 与派生入口完全相同，不再容许“删掉适配语句后相同”的宽松检查。原工具、修正轮数、复查与执行规则均保留。
- **家庭输入**：实际问卷投影进入原 persona/calendar/onboarding 接口；条数限制仅在输入边界扩展，防止真人答案丢失。未收集的追问记为未知，不由模型替家庭作答。
- **家庭评价**：使用原 `ENERGYBRIDGE_DISABLE_ACCEPTANCE_FALLBACK=1` 开关；移除模拟同意/拒绝。最终评分延后，原评分记忆不接收占位分数。SFT 标签只来自真人。
- **实验参数**：一天是此次问卷“同一天比较两条路径”的参数，原函数默认值是三天。日期采用原资产生成器默认的 2007-07-01，天津资源固定；事件开始从 17/18/19 时抽样、持续 0.5/1 小时。这些是显式问卷实验设置，不声称为原 EB 的默认实验。
- **运行设施**：API 并发限制、失败处理、只读执行记录、文件保存与网页展示不替 EB 生成或修改策略。

## 原资源本身的限制

原住宅没有 washer/dishwasher/dryer 对应的动态 Schedule:Constant 接口。因此，原 `appliance_sim` 的任务运行与 EP 住宅电表不能当成同一个测量层。当前两类数据分别保留：`native_device_power_kw` 为原电器模型输出，`actuators` 为实际 EP 写入。缺失端口记录在 `physical_asset_binding.unbound_native_device_ports`，网页明确说明；没有再偷偷补物理模型。

住宅中固定背景负荷仍是原项目设置，不等于填答者家中所有设备的逐项重建。跨夜任务也不会自动扩展为多天仿真。上述限制不以改编控制器掩盖。

## 验证范围

测试包含：原生日内回调 AST 完全一致；直接原入口与采集入口的 `no_dr` 实际 EP 电量、室温、任务安排逐项一致；当前 worker 不加载旧执行模块；单日日历/事件/图表一致；模型无效而原生回退时仍保存完整比较并接收真人小数评分；没有调用模拟接受或接受拒绝回退函数；价格单位不误写为货币；旧结果不被当前配置重写。

本轮不增加付费模型调用。之前获准的 `gpt-5.4-mini` 对照在 300 秒上限终止，不作为此次 v3.1 真实模型成功证据。测试模型答复与真人数据严格分开。
