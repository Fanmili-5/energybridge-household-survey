# 地区接入上线后自审

2026-09-12。审计范围：当前源码、资源目录与完整验证报告、线上环境预览和计算端健康状态。没有创建线上规划任务，没有调用付费模型。当前可继续演示试填，尚不应宣称已完成正式真人采集验收。

## 发现与建议

1. **正式采集前的必要配置：线上仍为 engineering。** `server.py` 的真人模式需 `--human-pilot` 启用；现有公开会话确认仍为 engineering。该模式下回答标为工程测试，不能因填写者是真人就作为正式真人标签使用。当前保留测试模式符合试填阶段；发放前应切换真人模式并验证 consent、target_source、data_origin、评分与导出准入。管理员继续单独标记，不把历史测试数据批量改为真人数据。

2. **验证缓存遗漏 DDY 和执行环境指纹。** `scripts/verify_regional_resources.py:108` 复用旧结果时仅比较模型 IDF 与 EPW 哈希。复现确认：只改变 DDY，现有缓存条件仍返回可复用；验证代码或 EnergyPlus 版本变化也不会单独使缓存失效。建议把 DDY、EP 引擎与验证代码指纹纳入缓存键，旧报告缺字段时重新验证。本次全量报告的通过记录已逐项对照当前 IDF/EPW/DDY，一致；这是后续更新时的漏洞，不是已证实本次资源失配。后续工程修复已补齐缓存指纹与失效测试，见 TIME-AND-VERSION-MECHANISMS.md。

3. **新版自动重跑旧案例尚不完整。** `simulation_environment.verify` 要求保存的资源目录哈希等于当前目录哈希。仅新增一个无关站点，也会使旧环境被新版拒绝。当前是安全拒绝，不会悄悄更换天气，旧结果和旧发布目录也仍保留；但需要手工使用旧发布版本重现。建议按目录哈希归档并路由到对应运行版本，或者在正式采集批次内冻结发布，批次结束再升级。后续已增加按目录哈希归档与选用历史物理资源的机制；完整代码/模型重现仍需保留对应发布版本，见 TIME-AND-VERSION-MECHANISMS.md。

## 必须限定的结论

- **50,700 是组合检查数，不是全部实际启动过 EP。** 其中 13,050 个组合在缺少配套设计日的预检查阶段就被拒绝。36,872 个通过结果包含实际 EP 输出与设备用电检查。此前把总数写成“50,700 次实际 EP 仿真”不准确，相关文档已更正。
- 日期池仅 `2007-07-01`、`2007-07-15`、`2007-08-01`。这是夏季情境采集，不能声称全年天气多样性已覆盖；2007 是实验日历载体，并非参与者实际年份。
- 住宅是 50 个参数化研究变体，并非 50 类已校准的中国住宅。材料与 HVAC 沿用作者参数，天气/设计日/地温和几何热边界已变化；电价仍为统一天津价格权重。
- 资源矩阵检查的是物理接口和技术运行，不等于验证全部真人家庭配置、全部 EB 策略或 50 人同时生成的等待时间。本轮没有付费模型规划质量与延迟的新证据。
