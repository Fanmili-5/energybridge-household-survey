| 问题 | 处理 |
| --- | --- |
| 多位成员堆在一页 | 每次显示一位，底部上一位/下一位，上方可返回修改；选填内容直接显示。草稿保存全部成员与当前位置。缺少生活节奏时跳到对应成员，不要求补齐选填项。 |

| 热水只有设定温度 | 从 EP SQLite 读取问卷用水时刻附近的水箱温度，显示明确的十分钟区间与均温。页面只标明水箱温度；出水是否验证等技术说明仅留后台。缺少任一分支可靠数据时，不展示该比较项。 |
| 等待信息难懂 | 按日常仿真、规划、调整仿真显示简短进度；断网自动查询原任务。失败保留资料和显式重试按钮；权限失效、记录不存在停止无限查询。 |

## 数据与执行边界

- 原 EB 规划、控制命令和单日仿真范围保持不变。新增状态观察不改变设备模型计算；测试逐步比较观察前后功率和 SOC。
- 原生 EP 首次设备回调可在00:10，末端可出现24:00回调。当天结束电量取截至24:00的区间，不把24:00之后的模型更新计入。
- EV SOC 是原 EB 电器模型估算，不是 EP 直接测量电池，也不是真实车辆数据。目标达到状态属于设备模拟结果，不是用户接受标签。
- 参与者不显示“实际出水未验证”“次日尚未验证”等研究核验文案；未知状态留在结构化审计记录，不补成零、成功或用户拒绝。
- 两个分支各保存 `service_evidence.json`，纳入结果文件哈希；原始 EV 观察序列保存在 `appliance_clock.json`，水箱原始输出保留在 EP SQLite。
- 用户看到的新结果进入原有展示快照与 SFT 候选输入；旧展示与旧标签不重写。
- 资料保存仍保留未知值。切换成员的显示状态不会改变家庭人数、漏存其他成员或复制其态度。

## 验证与下一步

本地启用原生 EP 的200项测试通过，无跳过、无付费模型调用。手机390px与桌面1365px浏览器测试使用临时数据库及固定模型替身，覆盖逐位填写、漏填定位、跨成员与刷新保留、验证码、仿真、断网重试、评分与导出。

仍须由真人预试判断填写负担与真实模型等待体验；这轮工程测试不证明量表有效或50人真实API任务的完成时间。正式采集开关保持 engineering，历史工程记录不重标为真人数据。
