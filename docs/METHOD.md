# Benchmark生成：家庭、A/B方案与IDF

本项目构造一种具体的决策任务：给定家庭背景、EB角色态度、一天的用电计划A、调整方案B及其参考仿真后果，请参与者站在该家庭立场判断是否接受，并给出评分和原因。后续模型学习这种整份计划的评价，可供EB调用；是否能改善EB决策仍需单独实验。

**当前结论：家庭输入不变；新10000组A/B完成原版执行与索引封存，两组新配对物理试例和一个UI91隔离预览通过；全量物理、覆盖尾项及真人采集仍待验收。** 数量和版本见[当前状态](BENCHMARK_STATUS.json)，审查意见见[ACL视角复核](ACL_BENCHMARK_REVIEW_20261112.md)。既有50户的公开[发布指针](household1000/CURRENT_QUESTIONNAIRE50.json)目前登记为reference50-v4-ui91-trial，属于含合成展示值的界面试用版，不作为八国V9正式标签集。本次未实时核验线上部署，也不切换题集。

## 1. 家庭如何生成

先建立调查源池，按国家与角色配额选取相容且不重复的源户，再生成参考周、服务需求及可控电器组合。这里的“家庭”包含调查支持的背景和明确给定的实验条件，不把参考作息当作实测日记。

| 国家 | 本批来源 | 使用口径 |
|---|---|---|
| 中国 | CRECS 2012冻结原件 | 项目已有调查原件，经字段适配；不是从公开网页重新下载的微观数据 |
| 美国 | RECS 2020 v7 | 家庭、住房及能源相关字段 |
| 英国、西班牙、德国 | ENABLE.EU 1.0（2019发布） | 各国调查字段统一映射；发布年不自动等于访谈年 |
| 印度 | IRES 2020 | 家庭与能源调查字段 |
| 墨西哥 | ENASIC 2022；ENIGH 2024 | 前者支持家庭成员/照护；住房等跨调查匹配字段保留匹配身份 |
| 澳大利亚 | ECA 2025年6月Consumer Energy Report Card工作簿 | 按已登记适配器提取支持的调查字段 |

字段、原件版本、来源链接和许可范围见[来源登记](../benchmark/household_stage1/SOURCES.json)、[数据合同](../benchmark/household_stage1/generator/DATA_CONTRACT.md)。不同调查没有的字段不冒充同户观测。

固定设计为八国各125户，共1000户。这是平衡跨国比较的实验配额，不按世界人口加权。六类角色配额为A166、B198、C125、D151、E156、F204，来自原EB保留的584份人类角色扮演样本构成（97/116/73/88/91/119）按最大余数法缩放；不是全球自然家庭类别的流行率估计。每国都有六类，以减少国家和角色绑定。

算法采用固定种子的哈希排序与约束选户、规则生成参考周、整数规划分配4—6类可控电器。每户空调必须配备且受控；F类包含EV；4/5/6类配额为333/333/334户。原调查设备事实与实验增配分别保留，311户的空调为参考增配，不改写源调查的拥有情况。角色、态度及生活规则的逐步依据见[生成依据表](../benchmark/household_stage1/generator/EVIDENCE_MAP.md)，实现与扩量入口见[可复用生成器](../benchmark/household_stage1/generator/)。

每个家庭保存成员、住房、设备、活动/照护、参考周、服务需求、态度/舒适参考、授权和逐字段来源。原件观察、源插补、跨户匹配及实验补全分别标记。没有用LLM自由编造整户信息。冻结1000户的摘要为：

`81fe13c3bb37cfe961418333690a5008e68b09e834f73241437a42fba5b82a11`

这一步已通过来源、生活、服务、设备覆盖及独立重放检查；它支持后续构造，不等于已经验证真实家庭偏好预测。

## 2. 如何从家庭生成A和一个B

**A：家庭参考周＋OR-Tools CP-SAT联合排程。** 从吃饭、家务、洗浴及停车连接构造目标时刻，在明确服务/硬件窗口内安排完整程序。洗碗对应已完成的一餐，同批衣物先洗后烘；若当日晚餐来不及完成完整程序，使用家庭参考周中真实存在的较早一餐并保留实验负载分配身份。热水器窗口围绕洗浴，EV保留给定SOC、离场目标和连续充电。不读取VPP收益、B后果或人的答案。A是实验参考日程，不是实测日记。

**B：原版有限动作＋IPOG-C＋CP-SAT。** 来源固定到官方[paper-v1-final/c58a2a7a](https://github.com/Agentic-Intelligence-Lab/EnergyBridge/tree/c58a2a7a3189482f57b93ddd0637f2c58ce5b5d0)。实际检查时钟由冻结原family_runner相关AST执行，避免以后来V2/V3包装回判旧题。

| 电器 | 可以改变 | 保持 |
|---|---|---|
| AC | 原版全局22—28℃制冷设定值，一位小数及实际可达检查点 | 制热20℃；无停冷/独立制热/风机/直接功率新动作 |
| WM/DR/DW | 整个程序开始时刻 | 原程序、时长、功率和同批洗烘先后；无人为装取新动作 |
| WH | 原一段预热窗口及目标温度 | 原水箱/功率，45—75℃与硬件域交集及窗口上限 |
| EV | 给定停车连接内的连续充电窗口 | 原初始/目标SOC、功率与效率；达到目标后停止 |

连续EV、每日完整服务和非EV不跨夜是本批实验选择。记录网格不是启停频率；原型资源窗口也不是实测电机连续运行时长。家庭温度偏好是软属性，不作动作准入边界；B可以不方便、效果差或被拒绝。VPP关联候选是本批选题范围，不冒称原Agent只会做这些提案。

**从候选中选一个B：SciPy/HiGHS整数规划。** 每户十个日期、每日一题，优先覆盖已见证联合任务数，再优化电器/取舍覆盖、重复和固定种子破同分。同类跨国家共同补细分格；随后采用保持每户原有基础覆盖的单步和联合重选，新B重新原版执行。原始格在选题前登记，未知热响应不算零；不按仿真收益或人的答案选题。

实际完成1000户×10题、20000次原版A/B回放；细分入选949/969，跨国目标945/969。仍有20个细分格未入选、57户在事件关联题中未涉及全部受控类，不能宣称穷尽覆盖。六类总体和每个角色均有覆盖。详见[本轮记录](research/AB_GENERATION_REPAIR_20261114.md)及[可复用CLI](../benchmark/ab_generation/README.md)。

旧10000题全部保留，原4335一概判废结论已撤回；[原版重审](research/original_eb_reaudit_20261113/REPORT.md)与本轮新生成分开。旧题后果和答案不继承到新方案。

完整可复用版本见[算法1与统一入口](../benchmark/ab_generation/ALGORITHM.md)：既可从授权调查原件准备源池并生成家庭，也可接入冻结家庭；随后自动执行两阶段补候选、跨户覆盖重选与当前索引封存。依赖统一锁定，实际求解预算传到求解器；搜索未解决、可行未证最优、已证无解和模型错误分别记录。跨目录复现按实际A/B哈希核对。

## 3. 家庭和A/B如何接到IDF

IDF是EnergyPlus的建筑物理输入文件。它来自固定公开的住宅构造算法、完整地区材料/围护包、登记地点天气及EB设备模型；不是从家庭问卷里直接获得真实住宅IDF。

住房类型、参考面积、户内层数、共墙与上下暴露先解析为支持的参考条件。相同条件复用共享住宅缓存；新条件沿同一生成算法补模型，不逐户随意修改。人口/在家时间、用水服务和设备配置通过适配器接入；缺项或冲突返回缺口，不用近似命中伪造精确匹配。来源与可复现运行见[IDF模块](../benchmark/idf_reference/README.md)、[构造方法](../benchmark/idf_reference/METHOD.md)和[资源准备](../benchmark/idf_reference/SOURCES.md)。

A、B在同一个住房、天气、硬件、人员/用水需求和初始条件下运行，只改变声明的控制。回读事件期及整日电量、有人时室温、实际热水服务、EV完成情况；各后果分开报告，不把“事件减电”说成“全天节电”。

当前公开IDF源码快照采用固定官方EnergyPlus25.2、OpenStudio3.11及原EB120L/3kW单节点水箱，保留自己的来源锁。服务器后来扩展的35城试验、24小时题窗回读和换城候选属于另有实现锁的研究运行；本次发布聚合状态，不将这些内部扩展伪装成公开九地点示例已经支持全部35城。完整内部运行代码/依赖尚未全部移植到公开模块。

旧版A/B上的76组配对：完整恢复口径62组通过，24小时题窗口径68组通过。两者是同批请求不同口径，不能相加。本轮端到端试例沿已确定的24小时题窗报告；7/14天累计恢复节能仍有缺口，时间步、预热和数值阈值未放宽。日期来自现有七月，不能称全年季节覆盖。

新换城候选对9组替代请求有7组通过、2组未通过；芝加哥→迈阿密5组、伦敦→爱丁堡2组通过。1000户住房路由可解析，57户参考地点改变、943户不变，八国配额不变；默认尚未切换，洛杉矶和艾哈迈达巴德各有一组原失败尚无通过的替代。换城是参考实验分布的改变，保留原失败和气候覆盖损失。这些旧版结果不代替本轮新10000题的同版本物理验收。本轮已另跑美国、印度两组新A/B，通过原标准的题窗/步长/预热/尾段比较，且与当前封存方案哈希匹配；全量后果未完成。见[IDF聚合进展](../benchmark/idf_reference/VALIDATION_STATUS_20261112.json)。

## 4. 最后收集什么，何时能正式发放

一条样本应绑定：家庭及来源摘要、角色、日期、A/B实际指令、IDF/天气/引擎/规则版本、配对后果、实际呈现版本及回答。人物不是最终标签：参与者看家庭卡、A/B和后果后再作答。沿用UI91后果展示路线；隔离预览复用原UI91响应表单且未改字段；具体发放版本与代码簿须锁定，不混用旧线上试验的整数档与待生产版本。

问卷记录接受/拒绝、响应安排评分、舒适/节能/VPP评分以及原因；响应安排评分不能未经定义就当作独立总体reward。完整文档示例见[Notion](https://app.notion.com/p/41506135328a8132b0cdf142fc226c38)，其中演示填写和演示后果明确不作为已采集标签或真实仿真。

正式发放前完成四项：
1. 新10000题已生成和原版执行、封存；继续处理覆盖尾项，保留分母和逐项缺口。
2. 对这批确切A/B做同源IDF配对计算，所展示后果必须可回溯；数值不可计算不填0，物理表现不好不据此择优删除。
3. 独立回读“指令→实际轨迹→统计→页面”，再用小规模真人验证题意、生活合理性和回答可靠性。
4. 冻结按家庭/共享来源/配对组隔离的评测划分，参与者重复另行控制；定义评价目标、基线与跨国/跨角色诊断。

原计划10000条是材料数；最近讨论的约2000条API模拟回答是另一项拟议标签需求，分配尚未冻结。模拟回答与真人标注明确分开，不能用合成标签证明真实人类偏好效度。本轮实际运行新原生计划、两组配对物理验证及一个隔离UI91预览；没有模型API、训练或上线。电价/补偿口径仍待确定，未计算值不填0。
