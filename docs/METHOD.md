# Benchmark生成：家庭、A/B方案与IDF

本项目构造一种具体的决策任务：给定家庭背景、EB角色态度、一天的用电计划A、调整方案B及其参考仿真后果，请参与者站在该家庭立场判断是否接受，并给出评分和原因。后续模型学习这种整份计划的评价，可供EB调用；是否能改善EB决策仍需单独实验。

**当前结论：家庭输入已完成；新版A/B通过动作与小批回放；新版A/B到IDF结果、问卷和评价的整批交付尚未验收。** 数量和版本见[当前状态](BENCHMARK_STATUS.json)，审查意见见[ACL视角复核](ACL_BENCHMARK_REVIEW_20261112.md)。旧50户线上版本有自己的[发布指针](household1000/CURRENT_QUESTIONNAIRE50.json)，本次代码更新不切换线上题集。

## 1. 家庭如何生成

先建立调查源池，按国家与角色配额选取相容且不重复的源户，再生成参考周、服务需求及可控电器组合。这里的“家庭”包含调查支持的背景和明确给定的实验条件，不把参考作息当作实测日记。

| 国家 | 本批来源 | 使用口径 |
|---|---|---|
| 中国 | CRECS 2012冻结原件 | 项目已有调查原件，经字段适配；不是从公开网页重新下载的微观数据 |
| 美国 | RECS 2020 v7 | 家庭、住房及能源相关字段 |
| 英国、西班牙、德国 | ENABLE.EU 1.0（2019发布） | 各国调查字段统一映射；发布年不自动等于访谈年 |
| 印度 | IRES 2020 | 家庭与能源调查字段 |
| 墨西哥 | ENASIC 2022；ENIGH 2024 | 前者支持家庭成员/照护；住房等跨调查匹配字段保留匹配身份 |
| 澳大利亚 | ECA 2025年6月Consumer Energy Report Card工作簿 | 按已登记适配器提取支持的调查字段 |

字段、原件版本、来源链接和许可范围见[来源登记](../benchmark/household_stage1/SOURCES.json)、[数据合同](../benchmark/household_stage1/generator/DATA_CONTRACT.md)。不同调查没有的字段不冒充同户观测。

固定设计为八国各125户，共1000户。这是平衡跨国比较的实验配额，不按世界人口加权。六类角色配额为A166、B198、C125、D151、E156、F204，来自原EB保留的584份人类角色扮演样本构成（97/116/73/88/91/119）按最大余数法缩放；不是全球自然家庭类别的流行率估计。每国都有六类，以减少国家和角色绑定。

算法采用固定种子的哈希排序与约束选户、规则生成参考周、整数规划分配4—6类可控电器。每户空调必须配备且受控；F类包含EV；4/5/6类配额为333/333/334户。原调查设备事实与实验增配分别保留，311户的空调为参考增配，不改写源调查的拥有情况。角色、态度及生活规则的逐步依据见[生成依据表](../benchmark/household_stage1/generator/EVIDENCE_MAP.md)，实现与扩量入口见[可复用生成器](../benchmark/household_stage1/generator/)。

每个家庭保存成员、住房、设备、活动/照护、参考周、服务需求、态度/舒适参考、授权和逐字段来源。原件观察、源插补、跨户匹配及实验补全分别标记。没有用LLM自由编造整户信息。冻结1000户的摘要为：

`81fe13c3bb37cfe961418333690a5008e68b09e834f73241437a42fba5b82a11`

这一步已通过来源、生活、服务、设备覆盖及独立重放检查；它支持后续构造，不等于已经验证真实家庭偏好预测。

## 2. 如何从家庭生成A和一个B

先把家庭与参考住房、设备能力和服务窗口绑定。**A是按固定EB noDR日常规则生成的参考计划**：在原服务窗口内按固定种子选择开始时间，保留完整程序、固定时长/功率和任务先后关系，EV按给定连接、初始SOC和离场目标运行。生成A不读取VPP收益、B结果或人的答案，也不为增加可调整空间重抽A。

再从A枚举原EB Agent允许的有限修改，生成候选B。依据固定到[原EB提交](https://github.com/Agentic-Intelligence-Lab/EnergyBridge/blob/2b17ae63e613da776c93e900f5dace50d63a88a8/experiments/benchmark/family_runner.py)；原生动作校验见[实现](../benchmark/ab_generation/eb_agent_contract.py)和[来源锁](../benchmark/ab_generation/upstream_eb_agent_contract.provenance.json)。

| 可控类 | B可以改变 | 必须保持 |
|---|---|---|
| 空调 | 原Agent范围内的制冷设定温度及合法检查时点 | 不添加停冷、独立制热、风机或直接功率动作；按实际0.1℃精度执行 |
| 洗衣机 | 完整程序的开始时间 | 程序、功率、时长、任务身份；本批不跳过每日任务 |
| 烘干机 | 完整程序的开始时间 | 同上；同批衣物声明存在时保留先洗后烘 |
| 洗碗机 | 完整程序的开始时间 | 同上；不添加人为装取动作 |
| 热水器 | 一段当日预热窗口和储水目标温度 | 原水箱及功率；45—75℃与硬件域取交集，并遵守原窗口上限 |
| EV | 停车连接内的一段连续充电时段 | 初始SOC、目标SOC、功率与效率；允许跨夜，完成时停止 |

除EV外不跨夜、每日完整任务保留、EV连续等是本批明确采用的约束；不将它们冒称原EB所有分支的普遍限制。空调的0.5/1/2℃、正负方向和20/30/60分钟等是可执行覆盖锚点，不保证真实压缩机会按该时段连续启停。十分钟是记录网格，不是每十分钟重新开关电器。

**多个B是候选，最后每户每个日期只选一个。** 候选构造使用单设备变化、二元覆盖设计和代表性的3—6类联合变化。试跑选题用OR-Tools CP-SAT：硬约束为每天一题、每户十个不同日期、所有受控电器均被涉及、存在单类和多类题；同角色跨国家共同覆盖细分方向/幅度/时长与联合组合，再减少基础题量偏差和重复。固定18:00—19:00是本批当地时间的实验事件，不声称各国真实峰时都相同。

B可以让用户不方便、舒适感变差或不愿接受，真人的拒绝是有效标签。执行错误、擅改硬件、删任务不能拿来凑题；软偏好冲突与可计算的服务不佳不自动删除。不预先按节电最多或“必然接受”选B。

目前49户490题通过新版原生动作与电器回放：102项适用空调格均覆盖且每项至少来自两个国家，178项已冻结联合目标均覆盖。178项源于初始试跑候选，不证明完整全球任务空间已覆盖。生产生成器已接入六类动作守卫，试跑目录构造/CP-SAT选题及原生队列仍有服务器侧编排依赖，不能把公开CLI旧默认配置说成可一键重建新版490题。[规则与验收](../benchmark/ab_generation/validation/eb_native_v3/README.md)分别登记源码、规则、历史试跑和公开复现边界。

旧10000题仍保留；其中4335个B不满足新版动作合同，必须重生成，不能用于新版发放。新版490题尚未运行EnergyPlus。

## 3. 家庭和A/B如何接到IDF

IDF是EnergyPlus的建筑物理输入文件。它来自固定公开的住宅构造算法、完整地区材料/围护包、登记地点天气及EB设备模型；不是从家庭问卷里直接获得真实住宅IDF。

住房类型、参考面积、户内层数、共墙与上下暴露先解析为支持的参考条件。相同条件复用共享住宅缓存；新条件沿同一生成算法补模型，不逐户随意修改。人口/在家时间、用水服务和设备配置通过适配器接入；缺项或冲突返回缺口，不用近似命中伪造精确匹配。来源与可复现运行见[IDF模块](../benchmark/idf_reference/README.md)、[构造方法](../benchmark/idf_reference/METHOD.md)和[资源准备](../benchmark/idf_reference/SOURCES.md)。

A、B在同一个住房、天气、硬件、人员/用水需求和初始条件下运行，只改变声明的控制。回读事件期及整日电量、有人时室温、实际热水服务、EV完成情况；各后果分开报告，不把“事件减电”说成“全天节电”。

当前公开IDF源码快照采用固定官方EnergyPlus25.2、OpenStudio3.11及原EB120L/3kW单节点水箱，保留自己的来源锁。服务器后来扩展的35城试验、24小时题窗回读和换城候选属于另有实现锁的研究运行；本次发布聚合状态，不将这些内部扩展伪装成公开九地点示例已经支持全部35城。完整内部运行代码/依赖尚未全部移植到公开模块。

旧版A/B上的76组配对：完整恢复口径62组通过，24小时题窗口径68组通过。两者是同批请求不同口径，不能相加。首版按已确定的24小时题窗报告；7/14天累计恢复节能仍有缺口，时间步、预热和数值阈值未放宽。日期来自现有七月，不能称全年季节覆盖。

新换城候选对9组替代请求有7组通过、2组未通过；芝加哥→迈阿密5组、伦敦→爱丁堡2组通过。1000户住房路由可解析，57户参考地点改变、943户不变，八国配额不变；默认尚未切换，洛杉矶和艾哈迈达巴德各有一组原失败尚无通过的替代。换城是参考实验分布的改变，保留原失败和气候覆盖损失。这些结果都不能代替新版490题的同版本物理验收。见[IDF聚合进展](../benchmark/idf_reference/VALIDATION_STATUS_20261112.json)。

## 4. 最后收集什么，何时能正式发放

一条样本应绑定：家庭及来源摘要、角色、日期、A/B实际指令、IDF/天气/引擎/规则版本、配对后果、实际呈现版本及回答。人物不是最终标签：参与者看家庭卡、A/B和后果后再作答。沿用UI91后果展示路线；具体量表范围由实际发放版本与代码簿锁定，不混用旧线上试验的整数档与待生产版本。

问卷记录接受/拒绝、响应安排评分、舒适/节能/VPP评分以及原因；响应安排评分不能未经定义就当作独立总体reward。完整文档示例见[Notion](https://app.notion.com/p/41506135328a8132b0cdf142fc226c38)，其中演示填写和演示后果明确不作为已采集标签或真实仿真。

正式发放前完成四项：
1. 冻结全量规则与覆盖分母，按新版重生成1000户×10题并检查逐户约束、重复及缺额。
2. 对这批确切A/B做同源IDF配对计算，所展示后果必须可回溯；数值不可计算不填0，物理表现不好不据此择优删除。
3. 独立回读“指令→实际轨迹→统计→页面”，再用小规模真人验证题意、生活合理性和回答可靠性。
4. 冻结按家庭/共享来源/配对组隔离的评测划分，参与者重复另行控制；定义评价目标、基线与跨国/跨角色诊断。

原计划10000条是材料数；最近讨论的约2000条API模拟回答是另一项拟议标签需求，分配尚未冻结。模拟回答与真人标注明确分开，不能用合成标签证明真实人类偏好效度。本次只同步代码、方法和聚合证据，没有新启动仿真、模型API、训练或上线。
