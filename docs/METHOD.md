# 家庭、A/B、IDF与真人问卷

本项目构造有调查依据的参考家庭用电决策情境：真人获得家庭、当天生活与任务、完整A/B及后续同场景仿真后果，判断是否接受B并评分。当前完成家庭和计划输入，尚无本版物理后果或真人标签。

## 1. 家庭如何生成

先取同一调查户的成员、住房、设备和可用活动信息，再绑定EB角色，补齐参考生活安排；每个字段保留来源。角色、态度和精确钟点是实验设定，不把它们写成实测个人偏好。

| 国家 | 主要家庭来源 |
|---|---|
| 中国 | CRECS 2012 |
| 美国 | RECS 2020，v7 |
| 英国、西班牙、德国 | ENABLE.EU，2019发布版；发布年不等于每户访谈年 |
| 印度 | IRES 2020 |
| 墨西哥 | ENASIC 2022；住房类型另用ENIGH 2024参考匹配 |
| 澳大利亚 | ECA Energy Consumer Sentiment Survey 2025 |

八国依据逐户资料可取得、字段可映射和家庭/能源情境互补选择；中国保留研究起点，德国与EB场景衔接，三个欧洲国家使用同一调查工具交叉核对。各125户是跨国家庭情境的均衡设计，不是全球人口抽样。每国都有六类角色。

六角色权重沿用[EB论文附录A表7](https://arxiv.org/html/2608.08691v1)的584份人类角色扮演调查构成97/116/73/88/91/119。最大余数法得到1000户的166/198/125/151/156/204；这不是全球自然人群角色占比。

生成采用固定种子的相容源户搜索、国家×角色配额约束和整数规划控制组合分配。每批主源户键唯一。每户控制4—6类，空调必备且必控，F类含EV；4/5/6类分别333/333/334户。调查无空调或未测空调时，参考情境补充空调，原调查记录不改。角色和控制组合不由节电效果或接受标签反推。

精确年龄（原件没有时）、生活钟点、参考面积、温度偏好和设备参数标记为实验赋值；跨调查匹配单列。完整实现、合同和依据见[家庭生成器](../benchmark/household_stage1/generator/README.md)、[算法](../benchmark/household_stage1/generator/METHODS.md)、[依据表](../benchmark/household_stage1/generator/EVIDENCE_MAP.md)。

## 2. 如何由家庭生成A/B

顺序是：家庭和生活安排 → 固定任务来源/准备时间 → A → 同题B候选 → 每日期一个B。不能先生成旧B再补任务解释它。

洗衣处理前一天换下的同批衣物；烘干接该批洗衣；洗碗指定前一天晚餐或当天一餐的餐具，吃完后才有负载。每日一程序是题目给定的工作负荷，不宣称真实家庭每天如此。

A使用单线程OR-Tools CP-SAT安排完整程序，先尽量避免22:00后完成，再减少参考启动偏移及洗后等待；共享设备不重叠。洗碗跟随该批餐具准备时间，不锚到无关晚餐。AC/WH采用参考服务规则，EV保持给定连接与目标电量。A不读取响应收益、B、物理结果或答案。22:00是A的软构造偏好，不是B禁令。

本版洗衣/洗碗/烘干120/90/90分钟、1.5/1.2/2.5kW，来自固定EB persona配置；这是采用的参考程序，不是EB唯一合法时长。

B使用原EB主方法动作、IPOG-C式有界组合搜索与约束检查生成候选，每题最终只呈现一个B：

| 功能 | 可修改对象 |
|---|---|
| AC | 制冷设定温度及原方法实际检查点；无新增停冷、风机、直接功率动作 |
| 洗衣/烘干/洗碗 | 整段程序起点；时长、功率、同批顺序和当天完成不变 |
| 热水 | 可控储热设备的一段加热许可窗口/目标温度；固定背景服务不改 |
| EV | 给定连接内连续充电许可窗口；硬件、初始/目标SOC不变，未改EV时保留普通模式 |

来源锁定为[paper-v1-final/c58a2a7a](https://github.com/Agentic-Intelligence-Lab/EnergyBridge/tree/c58a2a7a3189482f57b93ddd0637f2c58ce5b5d0)。原接口条件、同题任务条件、参考硬件与居民软偏好分别处理，不拿后加adaptive-v3或独立RL baseline范围回判数据。

户内每日期选一个B；全队列CP-SAT再保护每户基础覆盖、覆盖有实际机会的功能和合法细分，争取跨国重复。额外外部事件必须先明确再生成候选，不能为覆盖改作息。搜索/分配均有预算，不宣称穷尽或全局最优。

居民不喜欢、湿衣等待较长、超出软温度偏好、没有正向名义减电的B可以保留；接受标签由真人给出。生成器的诊断与覆盖标签不进入模型输入。空调设定不是实际室温，加热许可不是实际加热，充电许可不是充电时长。

当前1000户×10题有10000对计划、10000份同题输入和20000次原版执行检查。当前有限域939个有见证根动作格全部出现；924格在至少两国出现，15格仅一国。旧969格中925格命中、44格在当前冻结条件下未获合格机会，另有14个本版新格。不能沿用旧969/969成绩。详见[A/B算法及复现范围](../benchmark/ab_generation/ALGORITHM.md)。

## 3. IDF如何衔接

IDF由固定OpenStudio-HPXML参考住宅构造、围护材料、地点天气和EB设备/生活需求编译；不是调查户住宅的重建。见[IDF模块](../benchmark/idf_reference/README.md)。

后续从本版PAIR_INDEX读取上下文、任务、事件和实际A/B，核对pair_id、scenario_sha256、A/B哈希、event和context_sha256，再绑定CASE/IDF。两侧共享住房、天气、硬件、外部需求及首个不同指令前的历史；合法预热会改变事件开始时状态。

本版物理后果为null，新仿真0。旧版两组试例、历史76对或公开住房例子保留原版本，不能继承为本版120/90/90程序和新任务的验收。新版交接、室温/热水服务、EV完成、事件/全天电量仍需验证；当前仿真暂停。

## 4. 真人最终填写什么

一题包含家庭及来源摘要、给定生活和任务、完整A/B、响应事件、同版仿真后果及模型身份，再收集接受/拒绝、原UI91评分和原因。真人判断针对整份计划/运行结果，不把每个10分钟点当作独立reward标签。

当前consequences和targets为空，collection_ready=false。正式发放前需验收物理交接、UI91评分代码簿与前后端/导出一致性、费用/补偿口径和真人理解测试。接受B相对A不自动定义跨家庭可比较的绝对效用。

同户10题、共享源记录、C/D配对和重复参与者关系必须用于分组。125组C/D配对加750单户组共875个构造组，不等于875个已证独立观测；实际采集与数据划分尚未验收。状态见[BENCHMARK_STATUS.json](BENCHMARK_STATUS.json)。

全队列分配与封存版复现见[可复用命令](../benchmark/ab_generation/COHORT_RECIPE.md)。10000题完整输入已一致重建；历史选择回放、新求解和物理验证分别报告。
