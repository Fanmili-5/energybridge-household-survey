# 家庭、A/B、IDF与问卷：当前完整流程

这套benchmark研究整份用电计划的接受判断与评分：参与者看到家庭背景、角色、计划A、调整方案B及同场景仿真后果，站在该家庭立场作答。后续模型学习条件化的计划评价；其用于EB后的收益需要另外验证。

**当前状态（2026-11-15）：1000户和10000对A/B已封存，原生执行与969项细分覆盖通过。IDF有两组与当前A/B身份一致的配对物理试例；全量同场景仿真和正式真人数据尚未完成。**

| 环节 | 输入 → 输出 | 当前证据 |
|---|---|---|
| 家庭 | 调查源池、国家/角色配额、参考规则 → 1000户完整家庭 | 来源、生活/服务一致性、控制覆盖、重放已通过 |
| A/B | 冻结家庭、日期、EB动作域 → 每户10个日期、每日一个完整A/B | 10000对，20000次原生执行；原目标969/969 |
| IDF | 住房/设备/生活需求、同题A/B与实际事件 → 配对物理结果 | 两组当前计划试例通过；新版场景批量闭环待完成 |
| 问卷 | 同题家庭、计划和真实后果 → 接受、各维评分及原因 | UI91隔离样例已验；当前10000题未正式发放 |

统一接口见[交接合同](PIPELINE_CONTRACTS.md)，最新证据与ACL自审见[完整复核](research/PIPELINE_REVIEW_20261115/REVIEW.md)。[机器状态](BENCHMARK_STATUS.json)区分当前、历史和计划。

## 2. 怎样从家庭生成A和一个B

**A是日常参考计划。** WM/DR/DW用CP-SAT安排完整程序，优化参考启动时刻偏移与洗后等待，同时保护同批依赖、设备独占和当日完成。EV按停车与SOC连续补能；AC、WH采用明确参考规则。A不读取B、仿真收益或真人答案；程序目标的最优不等于学到了真实生活分布。

**B来自EB原生动作。** 计划动作和检查时钟固定至[paper-v1-final/c58a2a7a](https://github.com/Agentic-Intelligence-Lab/EnergyBridge/tree/c58a2a7a3189482f57b93ddd0637f2c58ce5b5d0)。程序保持完整，搜索在已有动作范围内进行；IPOG-C式受约束覆盖与定向依赖补齐都有预算，UNKNOWN与已证无解分别保存。

| 功能 | B修改的对象 |
|---|---|
| AC | 原允许的制冷设定值与实际可达检查点；无新增停冷、风机或直接功率动作 |
| WM/DR/DW | 整个程序启动时间；时长、功率与同批洗烘顺序保留 |
| WH | 原一段加热许可窗口和目标温度，服从原生与硬件域 |
| EV | 停车连接内连续充电窗口，保持原SOC、功率、效率和补能需求 |

每日完整服务、仅EV可跨夜、连续补能是明示的benchmark提案范围。软温度偏好与便利冲突仍可进入B，接受程度交给人评价。名义电量变化不冒充EnergyPlus结果。

**每个日期只选一个B。** 先覆盖已见证联合任务数，再权衡其他覆盖和重复；跨户补选保护已有基础覆盖。稀有细分集中于少量日期时，使用明确的外部事件场景并联合分配题位。新增事件域是16:00—20:00开始、持续一小时的实验网格；它不代表各国实际电网事件频率。

最终9376题保留18:00—19:00，624题采用补充时段。48个国家×角色组合各有13道匹配时段题，其中604题为补充对照。相比父批次634个B改变、10000个A完全相同，每户最多改4题。

原根动作细分969/969至少出现一次；这不等于全部双电器或更高阶组合已覆盖。29格仅1户1题，332格少于5户。跨国目标为每格1或2国，其中964/969达标；30格只有1国，25格原本目标为1国，另5格未达双国目标。算法保护的是已达成目标分数，不保证每格原有全部国家集合不变。

原版执行、改题标签复算、独立重跑和迁移样例已有收据。正式算法及命令见[完整生成算法](../benchmark/ab_generation/ALGORITHM.md)和[场景选题算法](../benchmark/ab_generation/SCENE_ALGORITHM.md)。

## 3. IDF从哪里来，怎样匹配家庭和A/B

IDF是EnergyPlus物理输入。当前主路线是[benchmark/idf_reference](../benchmark/idf_reference/README.md)：固定OpenStudio-HPXML构造算法提供几何和完整物性，各国依据选择命名围护构造，地点包提供天气、时区、进水及工况，原EB设备模型承接生活需求和控制。它生成可复刻的参考住宅，不复原调查户真实房屋。

住房类型、参考面积、户内层数、共墙及上下暴露解析为住房请求；设备存在/可控与服务资产关系形成设备请求；逐日人员、用水、任务和实际A/B形成CASE。相同物理定义复用住房/安装包；新条件沿固定算法生成并检查，冲突及越域返回缺口。完整来源、构造与资源准备见[IDF方法](../benchmark/idf_reference/METHOD.md)和[来源与资源](../benchmark/idf_reference/SOURCES.md)。

A、B共享住房、天气、硬件、外部需求和共同初态。共同历史应一致至首个不同指令之前；B合法预热可在事件开始前改变状态。随后回读事件与24小时电量、室温、热水服务和EV完成情况，分别报告；事件减电不自动等于全天节电。

版本分开锁定：计划语义采用论文c58a2a7a；公开IDF源码的EB基础锁为2b17ae63；物理运行使用CPython3.13.13、OpenStudio3.11.0+241b8abb4d、EnergyPlus25.2.0-cf7368216c。版本可以不同，但每项控制映射和结果都需按实际版本验证。[housing_simulation](../benchmark/housing_simulation/README.md)的EnergyPlus24.1公开示例是独立工程路线，不作为本批次的默认物理证据。

公开快照含九个地点示例。服务器35城为另有实现锁的候选研究配置，1000户可解析住房并不等于其10000个日期全部物理通过。旧76对中，完整恢复口径62对通过、24小时口径68对通过，不能相加。另9对换城请求7通过2失败，亦不能加到旧76对成为同版本总通过数。57户参考地点改变，默认尚未启用，洛杉矶与艾哈迈达巴德各一组旧失败仍无通过替代。

当前两组新计划物理试例经重新核对，A/B及18:00—19:00事件与封存批次一致，24小时及登记的数值比较通过；这不授予其他9998题准入。7/14天恢复期累计节能和全年季节覆盖仍不支持。

**尚待贯通的接口：** 最新PAIR_INDEX已登记每题event、context_relative_path及场景哈希，并输出PHYSICS_HANDOFF v2；现有两题试例适配器仍从旧试跑目录取_A上下文，未建立读取新版_SCENE并核对六项身份的通用批量闭环。624道补充时段尚无同场景物理试例。后续不得直接拿旧上下文或默认18:00—19:00计算新场景后果。

## 4. 问卷最后收集什么

一条正式样本应包含家庭/角色和来源摘要、日期与事件、完整A/B、IDF/天气/引擎/规则身份、配对后果、实际页面版本和真人答卷。UI91继续展示仿真后果，收集接受/拒绝、响应安排评分、舒适/节能/VPP评分及原因；各维评分不能未经定义就改名为总体reward。

当前10000是情境材料数，当前V9真人答案为0。另有约2000条API模拟回答的讨论，尚未冻结分配，也不是已执行生成。旧线上reference50-v4-ui91-trial含合成展示值，不作为新V9金标准；本次未实时刷新其在线记录。演示回答、API合成回答和实际真人回答分别保存。

正式发放前依次完成：新版场景到CASE的通用身份交接；实际题目的同场景配对物理与页面回读；冻结电价/补偿、评分代码簿及标签目标；小规模真人理解与回答可靠性检查；按家庭、C/D配对及其他共享来源/标注者关系冻结拆分，再执行有相同反馈预算的模型评测。

本次同步只更新方法、证据和审稿结论；最新真实结果见[复核记录](research/PIPELINE_REVIEW_20261115/RESULT.json)。
