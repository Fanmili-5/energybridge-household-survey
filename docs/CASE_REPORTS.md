# 案例编号与问题反馈

参与者可以选填昵称，并在等待、失败、结果或提交反馈后报告问题。昵称不是身份验证，不进入家庭画像、EB 输入或 SFT。

## 如何关联

| 字段 | 含义 |
|---|---|
| `owner` | 浏览器匿名会话，用于访问权限和生成次数限制，不代表已确认的独立个人 |
| `household_submission_id` | 一次保存的家庭问卷；修改答案后另存一份，旧记录保留 |
| `case_id` | 一次生成任务，等于 `jobs.id`，绑定当时的家庭问卷和答案快照 |
| `report_id` | 一次问题报告，绑定案例；尚未创建案例时绑定已保存的家庭问卷 |

案例与家庭问卷的关联沿用原实现。姓名或昵称保存在 `household_submissions.payload.participant_name`，不混入 `raw_answers`。

## 问题报告

`POST /api/reports` 接收 `target_type`（`case` / `household`）、`target_id`、`category`、`description`、`ui_version` 和幂等键 `request_id`。

问题类型：生成失败、等待太久、安排不合理、显示异常、其他。说明最多 2000 字，每个浏览器会话每 24 小时最多提交 20 条报告。重试同一请求返回原报告编号，不重复保存。报告不占生成额度，也不会调用 EB、EP 或模型 API。

数据库 `case_reports` 独立保存原始报告、家庭资料关联、报告时状态、页面与代码版本及核查历史。报告仅能关联当前会话拥有的记录。管理员通过 `/admin/` 查看报告、按核查状态筛选、填写备注和下载诊断记录；原描述与原评分均不覆盖。

核查状态：待查看、已确认问题、非故障、已修复。标记问题不等于删除样本；状态变更保留历史。没有强制 EB 生成不同方案，也没有因用户报告而修改 SFT 标签。

## 诊断导出与保留

管理员使用 `/admin/api/admin/diagnostics/case/<case_id>` 获取该案例；也可以用 `household/<household_submission_id>` 查看尚未生成成功的家庭资料。

诊断 JSON 包含数据库中的原始记录、关联案例、问题报告及本机已收到的文本轨迹。它是排查资料，不是训练数据。不会要求已有 `outcome.json` 或 `decision.json`；缺失阶段列在 `missing_documents`。

附带文件限 JSON、日志、文本、ERR 和 CSV；排除符号链接和凭据文件，删除会话及昵称字段并对常见密钥、URL、内部路径脱敏。每个文件最多 2 MiB、附件内容合计最多 16 MiB、最多列举 2000 个文件。超过限制、未写完或远端尚未传回的内容不能被当作已完整导出。`artifact_manifest` 列出本机文件与包含情况；SQLite 和服务器原始文件保持不变。导出仅在研究组内部使用。

数据库备份自动包含报告。`backup_backend.py` 的完整备份现在包含所有已结束案例的轨迹，包括失败、超时、取消等；默认定时轻量备份仍不复制仿真附件。活跃任务不作为可恢复的仿真检查点。失败病例没有完整结果和真人评价时，留作故障分析，不混入默认 SFT 导出。

## 必填项复核

| 信息 | 当前处理 |
|---|---|
| 姓名或昵称 | 新增选填，不用于唯一人数统计 |
| 家庭人数、在家习惯、所拥有电器 | 保留必填，用于构造家庭和日常安排 |
| 已选择电器的时间、运行时长和设备约束 | 保留必填；未选择的电器不要求回答 |
| 成员字段 | 日常作息必填；年龄、身份和各项态度均选填 |
| 家庭用电取舍、提前通知 | 保留，用于规划输入和评价情境 |
| 地区和住房建模字段 | 可先保存资料，生成前需要补齐适用字段 |
| 收入、电费、使用频率、经历等补充背景 | 保持选填，可以整页跳过 |

此次不删掉 EB/EP 必需字段，不修改原规划规则或评分结构，不把报告是否存在作为自动清洗规则。
