# 场景补齐与生成算法复核（2026-11-14）

**结论：本轮“保持1000户×10题、补齐原20项、家庭与日常A不变、动作仍来自EB”的生成阶段通过。可以进入同场景物理仿真和问卷材料构造。这里是代码与产物自审，不是外部同行评审意见，也不是整套benchmark已完成的结论。**

## 到底补了什么

原问题是题位冲突：少数合法细分集中在同一家庭的同一天，而一天只能选一个B。原969项中949项入选；未入选的20项包括E类烘干3项、F类热水器17项。

这次保留全部家庭、10000份日常A和每户原十个日期。只移动外部响应事件，并在已有合法B候选间联合分配题位。当前969/969项均已实际进入最终题目，分母仍为扩展前登记的原细分目标。20项逐项原标签及入选国家见[验收结果](../../benchmark/ab_generation/validation/scene_coverage_20261114/RESULT.json)。

## 审稿中发现的问题及处理

**事件时段是否是为了覆盖随便编的？** 原论文代码明确读取事件的trigger_h/end_h，18/19是默认值。新增16:00—20:00开始、持续一小时、十分钟网格，是本benchmark明示的实验场景范围，不能称为原论文固定18—19实验分布或各国真实事件频率。搜索有固定预算且受家庭原计划约束；未找到见证不解释成不存在可行方案。代码依据见[原版快照](../../benchmark/ab_generation/paper_v1_clock_source.py#L96)。

**会不会改乱居民生活或者增加EB没有的动作？** 家庭和完整A逐条对比完全不变。B仍来自原有限动作域，完整程序、洗衣烘干依赖、连续充电和日服务约束照常验收。没有新增停冷、装机、人工装取或切碎程序。覆盖标签里的manual_unchanged、cooling_stop_duration=unchanged是旧分类字段，不代表执行了这些动作。

**新时段只在某类家庭出现，会不会让模型走捷径？** 原核心补缺确实只涉及E/F。修订后增加604题匹配对照，八国×六类共48个组合的补充时段计数完全一致：16:00为1题、16:10为3题、16:20为1题、16:30为1题、16:40为2题、17:20为5题，每个组合13题。其余9376题保留主参考时段。分析必须分开报告主面板与补充面板；计数匹配不能证明所有变量独立，也没有消除全部动作与事件交互差异。

**969/969是否夸大覆盖？** 它只表示原“角色×电器×根动作细分”全部至少出现一次，不代表全部联合动作空间、全球家庭分布或每格足够统计样本。跨国重复目标另算：964/969达成，剩余5格已有题目但只入选一个国家。分别是A类洗碗延后超过120分钟、C类洗衣延后30—60分钟，以及E类烘干提前不超过30、30—60、60—120分钟。当前受约束的直接交换检查未补齐这5格，但没有证明全局不可行；不能据此做这些细分的独立跨国比较。

**是否筛掉居民不愿接受或效果不好的B？** 没有使用真人接受标签，也没有以物理节能结果筛题。当前保留1742题名义事件用电变化为负的情况、6181题热效应尚未知，以及2538题软制冷偏好冲突。负值是名义计算，不是EnergyPlus实测，也不直接等于居民拒绝。

## 生成算法能否成为论文中的完整方法

可以作为可复用的数据构造方法。完整结构是：调查约束的家庭与生活规则 → 独立日常A → EB原生动作候选及依赖补全 → 原细分目标与题位容量约束 → 外部事件补缺与联合选题 → 匹配对照 → 原生执行、覆盖复算与身份封存。

算法说明已明确输入、参数、目标函数、硬约束、失败状态和复现入口，见[场景算法](../../benchmark/ab_generation/SCENE_ALGORITHM.md)和[家庭到计划完整算法](../../benchmark/ab_generation/ALGORITHM.md)。核心CP-SAT这次找到可行解，未证明最优；两阶段结果也不是全局最优。论文贡献应落在可追溯的数据构造协议、EB语义保持、容量受限覆盖和独立验收，而不把CP-SAT/IPOG-C包装成新的求解理论。

复用边界也需要写清：新的1000户场景阶段从已封存父批次独立重跑；父批次的完整家庭到计划重建以及公开96户两次重建是上一轮单独证据。本轮没有重新声称把这三段在同一条新命令下全部跑过。新输入若无法满足覆盖与生活约束，流程应显式失败，不为凑数改家庭或放宽动作。

## 后续benchmark的验收边界

生成阶段通过；正式问卷仍需为每一题在同一建筑、天气、设备、初态和实际事件下取得A/B物理后果。新增场景已经输出event、context_relative_path、context_sha256、scenario_sha256和pair_id，物理结果必须与这些身份以及A/B哈希共同关联，不能默认套回18:00—19:00。

本轮未跑新的EnergyPlus或生成真人答案，也没有切换线上问卷。57户仍有个别已配备类别未在其十个B中被修改（烘干53户、EV4户），与父批次一致；这不表示A/B缺少每日服务。训练/验证/测试必须按家庭分组，并核对源调查家庭等关联，防止同户十题泄漏。
