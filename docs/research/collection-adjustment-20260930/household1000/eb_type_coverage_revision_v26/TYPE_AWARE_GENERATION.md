# 把EB类型放进数据生成：具体生产方案

2026-10-14。目标是1000户的类型覆盖与EB一致。类型先约束任务世界，最后用具体事实核对覆盖；不是生成完补标签。本文件是当前V26的实现设计，尚未执行新版世界生成。

## 1. 先联合分配家庭条件与类型，不先凑人数

保留中国市级普通住宅家庭的源人口/住房约束，排除镇、乡村。对每个家庭列出可以适配的类型：谁承担能源安排、能否安排规律外出/居家/不规律活动、是否有具体照护对象、是否有EV功能和合法接入。类型只用于研究情景适配，不能推断真实偏好或改写就业证据。

先证明六类核心情景均有可行家庭，再根据联合可行性设计每类人数或区间，正式生成之前冻结。演员人数比例不启用；均衡覆盖只能是有声明的候选设计，也须通过源结构、同户资源和角色适配检查。不能为凑某类制造EV所有权、改年龄、删除不适配家庭。未成年独居等责任人问题单列核对，不能默默默认成年户主。

学校原50户支持审查分两层：已有活动/照护条件能支持什么；重生成明确设计情景后可能支持什么。比如有老年人只证明年龄结构，不能证明正在照护或失能；只有具体保护服务和可用责任人建立后，才可生成E。具有EV功能也不证明F已成立，仍需出行、连接、补能及操作条件。

## 2. 每户先产生一份稳定的角色政策

生成一个role_policy，由EB参照、家庭条件和固定随机种子共同确定，至少包括：责任人及权限范围；日期化活动情景；通常舒适设定与临时调整边界；具体服务目的与可协商条件；是否逐次/当天确认；费用取舍；照护/出行保护规则；来源和设计身份。

政策在该户十个日期之间保持稳定，日期变化产生工作日/休息日、出行和服务状态变化。可给每户不同的作息基准、设备组合、服务频率和可行时间窗口，不能把同类复制成一张模板。变化范围及分布是有声明的研究设计，不当作中国联合日记概率。

源人口、住房、工作证据保持在source_facts；研究给定的偏好和授权放在given_role_policy；作息、服务、计划和状态分别记录派生规则。关键规则有原型/代码版本、种子、输入hash及理由。未指定的个人细节保持未知，真人接受/评分/解释全部留待采集。

## 3. 六类分别改变哪些内容

| 类型 | 活动与服务 | 具体协商政策 | 对A/B的作用 |
|---|---|---|---|
| A | 规律外出及返家后的服务；可移动任务须留合法操作窗口 | 费用优先；先提出建议，角色决定是否接受 | A满足通常服务；B展示可解释的节省/不便，不能默认自动执行 |
| B | 居家占用和舒适保护；家务时间较受限 | 较窄热舒适边界；逐次明确确认 | A从本户舒适设定生成；B覆盖边界内与越界请求，并呈现持续时间 |
| C | 日期之间的外出/返家变化及有用途的期限 | 谨慎、当天再确认；任务期限较刚性 | A逐日重排但保留服务目的；B可落入临时冲突，不能用固定通勤表代表全部日期 |
| D | 规律外出，可调任务与足够操作余量 | 较宽舒适边界；约定范围内允许自动安排 | A仍满足同户服务；B在约定内与超出约定时体现不同权限后果 |
| E | 具体儿童/老人保护服务，照护与同户资源冲突 | 安全优先；提醒为主，改动需明确协商 | A先安排保护服务；B可改变安排但不能隐去照护/安全后果，不预填拒绝 |
| F | EV连接/停车、下一次出行、补能目标及操作约束 | 出行可用性优先；边界内允许自动错峰 | A交付给定出行与访问目标；B区别于普通延后家务，并保留跨夜、离家与SOC后果 |

费用优先与控制权限是角色输入，不是人类接受概率。原型的scoring_weights和vpp_override_prob不作为标签或聚类输入。

## 4. 先有需求，再有正常A和协商B

先生成协调同户成员的完整日程，再定义服务的对象、数量、释放、用途和期限；区分必须完成、通常安排和可协商改变。类型影响活动情景及协商边界，但不能从已经排好的A倒推服务目的。

正常A必须满足给定服务及资源约束，温控由本户政策读取。旧plans.py统一26℃不能继续支配所有新类型：例如B参照通常设定范围为24.5–25.5℃，需要先修订明确给定的正常温控和需求，再重新编译；不能只改演员提示词。通常设定范围、请求设定值变化和实际室温漂移是不同量，不把三者混成同一个温差阈值。

A冻结后生成B，使用同一家庭、需求、设备、初始化和天气。B可改变动作/时间/温控请求，并分别记录：是否在给定权限内、是否需确认、是否造成不便、是否可能未交付服务。保留权限越界、不便或坏B；这些标记供研究审计，不预填真人答案，也不作为演员“正确答案”。B的模拟执行分支只是该请求的假设物理后果，不证明已经获得授权。

十日期的B应覆盖多种取舍，并在不同类型下都有可做、需协商和不满足的情况；避免“某类型总接受/总拒绝”或只凭类别/机制猜答案。最终机制构成和幅度在小样本开发后冻结，不根据真人最终答案反向调角色。

## 5. IDF继承动作，问卷继承语义

旧EB额定功率、容量、COP、程序及物理曲线按原已声明参数锁定。类型改变的是使用情景、服务和控制计划，不能随类型随意调硬件功率或效率。

IDF读取同一账本中的人员/房间占用、实际程序、温控、热水和EV轨迹。费用取舍、授权本身不作为虚构物理参数；它们通过合法/假设控制方案间接影响输入，同时原样进入角色卡和共享模型输入。同一物理请求对A、D可以产生相同电量、不同角色评价，这不是覆盖失败。不能为了分开六簇刻意造出六种负荷曲线。

原前端展示角色的明示政策、成员约束、A/B动作、服务后果及模型边界。演员仍自行给出采纳、评分和解释。明确给定的角色条件需要被遵守，未指定的取舍可由演员补充；不能把全部偏好写成未知后又声称六类存在，也不能把给定偏好写成实测人类回答。

## 6. 对旧代码的准确修改位置

| 旧接口 | 必须新增/修改的读取关系 | 验收 |
|---|---|---|
| worlds.build / activity_model.configure | 联立类型适配；保存given_role_policy；责任人和受保护成员明确，源工作未知不改写 | 名册、住房源结构保持；所有活动选择有资格/情景理由 |
| activity_model.dated | 读取本户稳定活动情景和日期条件；共享资源、照护及操作窗口仍来自一个日程 | 不同类型的实际在家/规律性符合核心条件；同户不冲突 |
| needs.batch_contract / plans.episode | 需求先于A；从政策读取通常温控、保护服务和明确协商范围，替换统一26℃的控制来源 | A可执行、交付服务；单位/用途/期限/偏好身份区分 |
| generate.candidates | 从同户政策生成不同幅度/窗口和权限后果；保留坏B；A/B共同需要不变 | 近边界、联动、不便、协商、服务风险有适用条件；无接受标签泄漏 |
| execution / vehicle_state | 沿用统一时间有序账本；请求与实际执行分开，记录服务和出行失败 | 人/设备/插拔枪/SOC只有一个状态来源，不用计划位置替实际状态 |
| compile_inputs.signals / compile_one | 从同一A/B动作和账本编译，不读取类型码，不按类型改硬件性能 | IDF中的占用、温控、程序、热水和EV信号可逐项回溯 |
| materials.actor / questionnaire_materials | 显示本户给定偏好/权限和成员服务，替换“所有取舍均未知”的旧统一说明 | 演员与模型看到同一事实；当前答卷/隐藏机制/审计标记不进输入 |
| 新事实提取与覆盖验收 | 从上述实际输出提取共同特征，再核EB参照对应和不读标签的聚类 | 六类实质覆盖、组内变化、缺失/模糊、重复、稳定性和权重敏感性 |

当前只是上述接口的实现设计。旧受验收代码和世界不就地修改；在新候选输出目录完成全链重建和验收后才能替换当前输入。旧SQL仅在全输入完全相同时可复用。

## 7. 实施顺序与当前状态

先在学校对原50户做只读源条件支持检查；完善责任人/照护/EV及类型适配，再建立政策、日期化日程和服务。正常A验收后才生成B、编译IDF和进行原50户新版物理/原前端检查。冻结类型构成、生成规则、种子、提取器和数值验收协议，再生产1000户完整静态输入与覆盖验收。全部通过后另审查全量EP准入。

SOURCE_SUPPORT50_REVIEW.json只支持候选条件分析，不证明家庭已被分配成某类，不验证新日程、A/B、IDF、聚类或人类回应。所有未完成的实现和证据仍保留未通过状态。

## 8. 学校原50户支持检查结果

50个实际旧世界的选择/内容哈希和名册检查通过，两种损坏输入均被拒绝。候选支持数A27/B49/C49/D27/E20/F26，其中一户无成年常住责任人；这不是已分配类型或真实偏好人数。六类各找一个不同结构候选的整数匹配可行，该最小筛查不是正式配额或样本量依据。

已有长工作参考情景支持27户、原有通勤情景16户、EV功能覆盖44户。20户仅具备成人与另一幼儿/老人配对结构；当前具名居家儿童照护合同3户且都是外部照护，不能将20户直接称已具备E情景。须重建明确的保护服务和照护/操作安排。has_work是旧参考世界已有工作代理字段，不是新获得的真实职业观测。

本轮只形成候选适配证据和生产设计，未分配正式类型，未生成新世界/IDF，也未跑EP或聚类。
