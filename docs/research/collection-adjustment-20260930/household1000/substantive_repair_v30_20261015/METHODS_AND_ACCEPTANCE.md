# V30：供真人角色扮演的实质A/B任务

用途是收集同一给定家庭角色对正常安排A和系统建议B的接受、拒绝及解释，随后训练和评估角色回应模型。B可以不方便、违反给定条件、不能交付服务，或包含多余操作；这些均不自动成为拒绝标签。是否接受必须来自演员。不能把执行成功、节能或某个规则通过当作演员同意。

## 冻结与证据层次

1000户、2524名成员、城市普通住宅范围、排除镇与乡村、原10个随机日期、4—6类EB功能设备及既定六类覆盖保持。六类数目A101/B303/C319/D101/E85/F91是已声明的结构约束实验配比，不是全国主观偏好占比。家庭、住房、硬件参数、政策、必须需求、正常A和共同前史均不随B变化。

家庭与住房的来源依据沿用已追溯的数据链；设备模型沿用固定EB原生模型和既有参数包；日程、角色政策、85%车辆目标及操作时间块保留其给定参考条件的身份。本版新增的B温控、充电窗口和额外操作均是系统建议的实验条件，没有权威调查支持其发生比例，也不伪称来源家庭的真实习惯。不存在人类答案或偏好标签的自动生成。

## 从输入编码升级为可检验的作用路径

V29遗漏了水箱目标温度改变，并误将无作用的控制请求当作区分证据。本版分三层核验：

1. 指令被完整编码：温度、允许时段、程序及人工操作分别比较，包含热水器目标温度。
2. 指令能进入实际执行：同一热区多台AC共享热区温控，不再将未被温控器引用的单台设定表当作独立执行；编译前检查热区值一致，编译后检查实际IDF的温控表引用。
3. 确有演员能看到的具体内容：实际服务交付或操作可行性改变，人工操作时间或新增预约改变，实际参考负荷发生明确变化，或有明确的水温/房间温度变化。一般确认程序、单纯权限越界、未约束实际执行的控制窗口均不能单独放行。

编码下限与实质后果下限是预定的任务设计条件，**不是人类最小可觉差、真实费用或人群调查结论**。本版对负荷变化使用至少0.1 kWh的明确显示差；热水温度差至少1℃、房间目标时段温度范围变化至少0.5℃；服务交付或可执行性改变可独立构成依据。额外人工操作至少一个既定10分钟时间块，既有操作移时至少20分钟。各路径是并列条件，不要求每题节能，也不把错误B删成合法B。

## 生成方式

从冻结正常A和原家庭可用的设备、程序及操作窗口构造候选。优先保留原V28候选机制，恢复被V29漏项错误排除的热水控温题；原AC请求投影到实际热区温控对象。无作用的候选不保留。

可使用已核对的**A参考运行轨迹**选择确有设备运行的时段。这是条件化任务设计：例如先确认A确有制冷负荷或充电，再施加B改变。它不是自然事件频率抽样，也不是利用演员答案。候选排序不读取B的EP结果；生成后才做独立B仿真验收。验收失败必须记录并修正整类基础规则，不能逐户挑大节能结果来凑通过。

| 系统建议 | 预先核实的作用路径 | 来源身份 |
|---|---|---|
| 推迟程序、跨设备联合移时、超出交付期限 | 真实程序执行、装取时间与交付；允许保留失败B | 原参考设备程序/因果执行器＋给定B干预 |
| 水箱60℃改为35℃，或改变预热时段 | A有实际加热输入，保留混水目标和用水量，再核实际水温/电量 | 原参数包不变，35℃是故意可能不合适的系统建议 |
| 修改同房间共享温控 | A该房间确有制冷输入，变化进入实际热区温控表 | EB条件模型＋显式热区控制表示；并非真实家庭接线调查 |
| EV延后充电或仅给10分钟窗口 | 同一车辆、行程和目标下，因果充电轨迹确有改变 | 原充电功率/电池/效率不变，窗口为给定建议 |
| 安静日额外请求现场插拔 | 明确谁、哪两个时段、占用多少预约时间及是否能执行；不新增必须行程 | 给定系统的额外操作请求，不是新增真实需要或推断的愿意 |

较大或明显有问题的B可以保留，但不得造成模型语法错误、缺失资产、伪造操作人或家庭事实。热水不足、充电目标未达、提前取出失败、额外操作或照护冲突应如实呈现；不能渲染成已实施的真实伤害，也不强制演员选择某个答案。

V30.1原50户首次实质验收有13组正式任务及4组既定对照未通过，均来自40分钟热水预热移时：同一20分钟加热可能在60分钟目标窗末段补做，使整窗电量和服务几乎相同。V30.2对整个机制改为至少60分钟移时，并要求B在完整目标窗关闭加热、A在该同窗确有至少0.1 kWh加热输入；不只改失败的13组，不降低后果阈值。原代码、输入、读回及失败报告保存在`development/rule_revision_v30_1`。

V30.2原50通过后，950户的9500组后验拦住13组，均为仅0.5℃空调请求：A确有制冷，但热惯性与部分负荷使实际差异未达原阈值。V30.3将所有单纯依赖AC物理路径的候选提高到至少2℃，补充2/4℃的统一候选层级；不只替换失败13组，其他设备与复合方案仍可通过独立服务/人工路径成立。后验0.1kWh/0.5℃标准不变，旧50验收失效，按新源规则重新验收原50，再处理950。前一版源码、输入、SQL与失败收据保留在`development/rule_revision_v30_2`。

## 先原50户，再950户

使用新的独立版本目录和原50户原日期。先检查500组源逻辑、热水漏项反例、孤立AC日程反例、无作用EV窗口和闲置AC反例。再编译原50户500组及200组既定前史/入水/模型形式对照。正常A及硬件输入需保持相同；严格同IDF、天气、引擎和SQL哈希时才复用结果。

独立核对实际控制引用、实际执行、原始物理输出和页面可见信息。500组及既定对照均需有实质路径；仅物理无Severe/Fatal不足以通过。使用原成熟前端，保留影响信息、填写者本人年龄/性别及简略动作，检查所有500组真实浏览器呈现，并在隔离假参与者库验证提交、修订、恢复与撤回。

原50户全部验收的当前签名、证据哈希和实质路径收据共同解锁950；不凭`passed`文字或旧V29收据解锁。950应用同一冻结规则后，再检查原始案例、物理和页面并同步GitHub。本流程不提供自动1000户全量EP启动。

## 科学结论边界

原50是先行生产回归门，950的失败已用于整类规则开发，因此950不是未见过的独立科学测试集。本版全量检查是生产回归，未来角色模型的科学测试仍需独立演员答案和事先固定的分组/切分。

这能建立可追溯的条件任务世界、明确干预、正常A对照、具体可见后果及采集工程闭合。它不能替代真实建筑校准、真实居民偏好占比、演员理解程度或角色信息是否影响接受回答的真人验证。真人答案应在本版任务冻结后独立收集，旧刺激的答卷不能冒充新刺激答案。
