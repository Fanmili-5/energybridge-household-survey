# V29：任务区分度验收与受约束修正

对象仍为原1000户中国城市普通住宅参考家庭，每户原10个日期、4—6类EB设备及既定六类型覆盖。排除镇、乡村、集体户和非普通住宅。本次只修正B请求及解释呈现；家庭成员、住房、设备参数、给定角色政策、必须服务、正常A和共同前史均冻结。六类型配比沿用V28的结构约束研究设计，并非全国六类主观偏好的真实占比。

## 原EB空调安排与本项目适配

已核对原仓库固定提交 `2b17ae63e613da776c93e900f5dace50d63a88a8` 的原生模型：`always_avail` 在 AllDays 至24:00为1，`cooling_sch` 在 AllDays 至24:00为23.888888888889℃；模型另有25.55℃的HRef表，运行程序还能覆盖设定值。`fan_cycle=0` 为循环模式。因此原EB有全天可用的制冷控制，不代表压缩机全天持续耗电，也不能把某个静态设定值当成全部实验的实际控制轨迹。

本项目V28的5—9月、有人或睡眠的服务房间启用空调，是显式的研究适配，并非原EB逐时安排的复制。本次保留该A安排，避免用无人房间、非制冷季强行开机来拉大A/B差值。对原EB全天可用策略的模型形式比较应另设对照，不混入本次修正。

来源：[原生IDF](https://github.com/Agentic-Intelligence-Lab/EnergyBridge/blob/2b17ae63e613da776c93e900f5dace50d63a88a8/Family_Model/Family_Simple.idf#L1530-L1585)、[EnergyPlus 24.1控制与循环模式说明](https://bigladdersoftware.com/epx/docs/24-1/input-output-reference/group-unitary-equipment.html)。固定文件哈希与逐项核对见 `EB_AC_SOURCE_REVIEW.json`。

## 先判断请求是否明确，再核对物理后果

下列下限是预先规定的任务编码标准，不是由权威调查估计的家庭偏好、设备精度或经真人验证的最小可觉差。其科学用途是排除近乎同义或微小控制请求，不证明演员一定感到差异。协议在B候选选择前冻结，规则不读取EP结果。

| 维度 | 输入侧验收 | 支撑性质 |
|---|---|---|
| 临时调温 | 非零调温均至少0.5℃，改变累计至少30设备分钟 | 研究编码下限，真人可辨识性待试读 |
| 程序开始 | 改变至少20分钟 | 研究编码下限，保留正常A/服务与执行核验 |
| 控制可用时段 | 改变至少20分钟 | 可追溯控制时间差，不等同实际用电差 |
| 人工动作 | 时间改变至少10分钟 | 可追溯操作时间差，须核对操作者与照护 |
| 无原定制冷需求的额外请求 | 逐设备、逐新增时段核实A没有该需求、B新增请求 | 额外服务的研究挑战，不能伪称节能或预设拒绝；其他时段既定需求保留 |

不设最低kWh差值，不按EP结果反复挑选“节电明显”的B。供电、热水、EV与实际执行仍用同一套物理和服务验收；有冲突或未满足的B保留供演员评价，但不自动产生拒绝标签。

## 41组优先问题与857组同显示后果

原审计优先41组同时具有微幅调温、显示后果相同及人工动作不变。先复核源请求，再从原家庭可用的候选机制中修正：尽量保留原设计条件与机制；角色允许幅度小于0.5℃时，不扩大角色边界，改用该家庭实际可用的其他请求，或保留明确越界的挑战。候选排序不读取能耗结果；没有合适候选即停止，不改家庭凑数。

新规则覆盖所有10000组，因此修正数量可能大于41。全部857组逐条保留旧case ID与源哈希，记录是否修正、当前显示是否仍相同、当前可见取舍类型。显示相同的任务明确告知当前精度下模型后果相同，并分别标记温度条件、充电许可、无制冷需求的额外请求或其他可见时间/操作差异。分类是任务结构，不是演员偏好或接受答案。若既没有后果差异，也没有达到标准的明确请求差异，则不得入包。

跨日期复核另发现3组4月30日任务，新增请求时段无制冷需求，但跨入5月1日后有原定制冷服务。“当日没有需求”容易误读为整个24小时均无需求。修正基础谓词为“该设备的这个新增时段没有需求”，保留其他时段服务，并加入正反例；不删除家庭、不修改需求或正常A。规则变化后原50重新签名、材料重建和浏览器复核。全部10000组先做只读候选可用性预检，不能以950运行时的失败来反复改家庭凑数。

临时调温按实际A/B差异分段生成文字。例如A在07:50—12:00制冷，B仅09:00—10:00调温，页面只比较09:00—10:00的设定值，并明确结束后恢复原安排；不能显示成整段使用缩短。全文、时间线、源数据与实际提交的模型输入逐项绑定。

## 分批封闭验收

1. 原50户：500组正式任务加200组前史、入水与模型形式对照；审核源数据、编译输入、共同前史、物理结果、全部500组页面和真实浏览器呈现，以及隔离假参与者的提交/修订/恢复/撤回。假答卷为0人类标签且不进入正式导出。
2. 上述全部通过后，生成 `ORIGINAL50_CONTRAST_ACCEPTANCE.json`；950预检必须校验其当前输入与每项证据哈希。仅物理跑通不足以解锁950。
3. 将同一冻结规则应用到950户；只重新运行物理输入改变的分支。只有IDF、天气、引擎与原SQL哈希全部相同才能复用结果；所有分支重新做当前输入绑定与物理读回。950的9500组源页面全部核验，浏览器检查均匀分布的100户共1000组；不是9500组浏览器普查。
4. 合并41/857清单，校验1000户分区、全部输入/物理/材料验收、520组天气敏感性对照；再同步两套正式包和GitHub。新输入或代码改动会使相关验收失效，不提供自动全量EP启动。

当前工程验收能证明源约束保持、请求编码明确、模拟与页面一致。尚不能证明真实住宅校准、演员可理解性、角色信息对回答的作用、全国偏好占比或最终benchmark有效性；这些需要独立真人与实测证据。

审计工作流参考 [Kassis等，Scientific Agent Skills (2026)](https://doi.org/10.48550/arXiv.2609.00065)，只作为证据分层和可证伪审查的方法，不作为家庭行为或数值下限的实证依据。

后续benchmark应分别报告有模拟后果差异、仅有明确请求差异的题型，不能把编码差异当作已验证的主观代价或演员正确答案。
