# 评测协议

任务是根据给定家庭的生活需求、习惯和约束，评价B相对A是否合适。提案版和带物理估算的UI91版分别登记实际可见信息，后算结果不能补写为旧参与者已经看到的信息。

## 已明确的原则

- 模型输入使用对应人类评价的家庭、A/B、VPP、影响、问卷口径及可见排程；不输入当前答案、理由、质控结论或参与者本人身份。
- 输出为`decision, score, comfort_score, energy_score, vpp_score, reason`。客观VPP达标、节电和服务完成不直接生成偏好标签。
- 同一参与者对同一案例使用最新有效修订；多人真实分歧保留并报告人数，不把多数意见当成唯一真值。
- 同户各日期及共享来源作为关联组，不能随机拆到训练和测试两侧。原50户不构成历史1000户之外的独立测试集。
- 同一`participant_id`跨轮的回答相互关联，不能把不同轮次当成独立自然人。最终划分需同时核查家庭/共享来源及参与者交叉关系，防止标签泄漏。
- 场景数量与答卷数量分别报告，统计不确定性考虑家庭内及参与者内相关性。

## 正式评测前仍需冻结

训练/验证/测试具体ID，模型与提示模板、可见信息预算、主指标、理由评价和不确定性计算方案，须在正式评测前固定。分数误差、接受分类表现和分歧可以分别报告，但当前不把建议当成已执行的模型成绩。

每次评测提供数据/标签版本、分组清单、质控规则、实际案例/参与人数、模型版本、解码设置和失败率。工程测试、参考仿真及文档完整性不能代替真人理解和benchmark有效性验证。
