# 恢复原 EB 的规划检查与证据复核

当前数据路线仍是：真人家庭问卷 → EB 规划及 EP 配对仿真 → 真人接受/拒绝、四项评分 → SFT 候选数据。没有接入模拟家庭评分器。

## 修复原因

真实测试中，模型的热水器指令缺少温度；部分任务仍与响应时段重叠。问卷适配器只向原 resolver 提供了基础温度/时钟检查，还删除了原生 VPP 不重叠约束，并遗漏物理与电价证据复核回调。因此不完整方案可被选择，到执行器才被拒绝。

## 修改

- `native_planning.runtime_errors` 对齐固定版本 `family_runner.run_family_agent` 内的 `_portfolio_runtime_errors` 与 `_hard_policy_errors`：明确电器命令、动作字段、当前运行状态、任务窗口、VPP 冲突和 EV 服务窗口。
- 恢复 `_adaptive_v3_observable_planning_inputs` 原样生成的响应时段约束。
- 使用原 `_adaptive_v3_resolve_planning_response` 的修正次数与停止条件，错误交给模型，不替模型选择新方案。
- 接回原生物理/电价证据复核及 `_adaptive_v3_cached_impact_review`，按事件、阶段、完整上下文缓存，不把旧证据用于新状态。与原生流程一致：初始候选通过检查时才执行该轮复核；无活动或即将到来的事件时不额外执行这一回调。
- 每次模型调用保存 `purpose`，区分初次规划、指令修正和证据复核。新文件纳入运行时源码哈希。
- 新生成结果版本为 `eb.paired_ep.v2.8`；历史结果及评分不重写。候选导出仍保持原先只接受当前运行契约的规则。

## 保留边界

不引入 RuleMILP、不调用预设家庭评价、不制造接受/拒绝、不强制方案一定不同。原 EB 电动车保护规则、执行拒绝、控制器回退继续保留。该改动恢复指定原生规划路径，不宣称整个问卷系统等于完整 benchmark，也不保证每次模型生成都正确。

## 验证

离线测试禁止外网模型调用。新增回归将适配器检查输出与直接从固定上游源码提取的原 `_hard_policy_errors` 闭包逐项比较。真实 EP 测试使用明确标记的模型答复 fixture，覆盖缺温度 → 模型修正 → 实际执行 → 双方案展示，并检查没有生成真人评分。

运行：`EB_TEST_NATIVE_EP=1 /Users/fanmili/studytest/.venv/bin/python scripts/test_offline.py`。

恢复复核可能增加模型调用，真实模型的完成耗时与策略效果需另行实测；没有通过延长 300 秒任务上限来掩盖问题。

## 第二遍审计与失败分支验证

- 将真实测试中第 1 轮第 3 次、旧适配器曾选中的模型答复，连同原问卷重新送入当前真实 EP 路径。旧记录有选中方案，新路径拒绝该答复并要求修正；刻意重复同一答复后停止重试并使用原生回退。配对前缀一致。没有重新调用付费模型，重放产物没有写入线上真人记录。
- 新增重复无效答复、证据复核请求失败、原生 EV 保留已有充电窗口三个回归。有效初选遇到复核网络失败时按原生 resolver 保留，未把网络失败改写成用户拒绝。
- 页面复查文字改用执行报告，不再展示模型声称但未执行的收益或调度意图；原始模型解释仍保留在决策记录供审计。时间轴继续由实际 EP 控制轨迹生成。
- API 错误保存底层错误类型和白名单数值计数，避免只剩 `LLMCallError` 无法区分连接失败与输出失败；不保存异常正文、密钥、请求头或 URL。
- 本地 132 项后端测试通过（包括真实 EP、家庭快照、保存/导出、并发收据及隔离）；浏览器手机/桌面入口、代理错误、保存后刷新、队列失败重试、重复提交、评分草稿恢复通过。浏览器接口为 mock，不冒充线上付费端到端测试。
- 补充修改已部署到阿里云；部署前无排队/运行任务，已备份旧源码。云端 9 项原生规划回归通过（含真实 EP）。HTTPS 首页和会话接口登录后均返回 200，未登录返回 401；线上 JS 与本地一致，会话报告版本 `eb.paired_ep.v2.8`、engineering 模式、允许生成。历史两条任务未改写。

### 明确保留的限制

真实旧任务的两条 EP 分支均有 8451 次警告、0 严重错误，其中三类热水终端各 2813 次提示热水温度低于目标温度。不能将“模拟成功”解释成所有服务需求均已满足；没有为了清除警告擅改上游建筑或设备参数。已有服务结果和温度边界仍需结合查看。

当前适配是所选原生规划/执行路径，并不是原 benchmark 全量生命周期、模拟多成员评价和所有可选实验工具的复制。真实模型在新版约束下的生成质量、调用时长，仍需新的真实运行验证；离线重放无法证明未来模型一定给出好策略，也无法保证 300 秒内完成。
