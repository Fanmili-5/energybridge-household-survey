# V28正式50户/950户发布自查

本次审查针对供真人扮演、训练与评估共享角色回应模型的参考任务世界。验收对象是当前发布的两个不相交角色集合及其源数据、物理回读和采集协议。审查由本项目助手完成，没有独立同行评审。

结论分两层：V28全1000户的条件参考生产与正式采集协议可以接受；真实人群六类偏好比例、真人角色有效性和建筑/设备实测校准没有得到证明。1000户是有统计锚点的合成任务世界，不能描述成1000个实测中国住户或全国偏好代表样本。

## 发现与修正

| 问题 | 修正 | 验收证据 |
|---|---|---|
| 同日修订覆盖字典值，但保持首次提交顺序；先答第1日、再答第2日、再修改第1日时，页面可能恢复第2日的旧本人信息 | 当前答卷按各日期最后追加的顺序返回；最后一次明确留空的年龄/性别也恢复为空；追加历史保留 | 两版HTTP测试增加跨日期修订与空值恢复，虚构记录不进入正式导出 |
| 邀请码CSV写出后数据库登记中断；部署看到CSV存在便跳过登记 | 每次部署都核同一CSV与已验收角色集合；同码同户登记幂等，中断后重放原凭据，不更换已领取身份；冲突或额外家庭拒绝 | 7项恢复故障注入及实际备份恢复校验 |
| 已有数据库丢失凭据密钥时可能自动生成新密钥，导致旧邀请码和恢复码失效 | 现有数据库缺密钥时拒绝启动，要求恢复一致性备份；事务内再读当前会话，防止退出/撤回后的旧快照继续授权 | 密钥缺失、撤回后旧会话、凭据冲突反例 |
| 案例验收引用回读hash，却未直接检查页面每个数值和当前物理验收签名 | 核当前内容门与完整配对集合、真实A/B文件字节；逐项核三种电量范围、事件窗口、末态及尾段；从当前源世界重新构造全部角色/任务/影响 | 500/9500条全量只读复验；两版各7项拒收反例 |
| 执行看板残留V27的“全量静态待验收/950户未运行”，浏览器计数混用历史V27与当前V28 | 当前看板改为V28实际范围，历史记录保留；区分500页历史浏览器验收、当前10000案例源/JS检查与尚未完成的最终浏览器提交复验 | 公共状态一致性及源码/发布载荷hash校验 |

JS中的整数与Python的浮点数序列化可能不同。源角色/任务/影响逐字段比对；派生页面hash通过实际发布的`joint-view.js`验收器核对。没有忽略不一致或调整源数值来迁就hash。

本次修正没有重新生成家庭、配比、日期、A/B或IDF，没有启动EP。50/950案例发布包保持原签名；采集服务换用新封存代码版本。旧运行代码、邀请码、数据库和备份保留。测试使用独立临时库，不把虚构试填写入正式库。

## 科研证据与限度

| 环节 | 当前可以支持的结论 | 不能据此声称 |
|---|---|---|
| 城市家庭与住房 | 七普城市普通住宅统计控制、辅助来源匹配与联合补全有记录；排除镇/乡村 | 合成逐户成员、细年龄、户型为实测；边际能唯一识别联合分布 |
| 活动、照护与作息 | 年龄、工作来源提示、日期和同户共享资源进入同一日程；未知就业不变成职业 | 钟点、外部协助、日托为中国真实频率或观测个人偏好 |
| 六类 | 给定政策先冻结；源结构与正常A可行性限定类型；实际世界特征恢复六类覆盖 | A101/B303/C319/D101/E85/F91是自然人口比例；构造后聚类是独立人类类型效度 |
| 电器、服务与A/B | 原EB六功能模型，每户4–6类；共同服务先定义，正常A冻结，多个B机制及不满足保留 | 覆盖率为真实拥有率；服务失败自动等于人类拒绝；B比例为真实事件频率 |
| IDF与学校仿真 | 当前字节门、全1000户及两种敏感性范围、SQL时序/计量/人数与来源闭合 | 空调曲线范围外真实品牌性能、建筑热负荷校准、个人舒适或等末态净节能成立 |
| 正式问卷 | 原成熟界面保留影响、四评分与理由；本人年龄/性别和当前回答不进入角色输入；可恢复、修订、撤回 | 工程协议通过就是真人理解通过；参与者已验证身份；50/950天然为独立训练/测试集 |

## 尚未关闭的证据门

1. 当前正式库真人答卷仍为0。本次没有招募、合成真人标签或启动训练。先以原50户入口试读，核角色、需求及后果理解，再检查角色信息是否影响回答与解释。
2. 最终正式发布版本的实际浏览器提交全流程复验仍未完成；历史隔离浏览器试填、当前HTTP测试、源案例检查及JS绑定检查分别报告，不能互相替代。
3. 后续共享模型评估需按填写者、角色及来源/模板关联分组，冻结预算B和合法历史。不能让当前答案进入模型输入，也不能把角色类型或技术约束当成正确回答标签。
4. 自然六类偏好比例和实测校准需要对应目标调查或观测。这些缺失限制研究主张，不能靠程序通过或更多EP运行补成数据证据。
