# EnergyBridge 真人问卷—家庭角色模拟器：目的导向完整审计

审计日期：2026-09-12
审计对象：`energybridge-household-survey` 本地工作树、线上网站 `47.85.194.154`、学校计算服务及当前数据出口。
审计目标：判断本项目能否从真人家庭问卷稳定得到可追溯的监督样本，训练家庭角色模拟器，并在独立评测通过后接回 EnergyBridge 的家庭评价位置。

## 1. 必须先冻结的目标合同

一条监督样本的语义应固定为：

> 同一家庭的事实、成员信息、态度与设备日程 + 随机研究情境 + 原安排及 EP 结果 + EB 建议及 EP 结果 → 该家庭代表的接受/拒绝、四项评分和可选原因。

四项评分为 `score`、`comfort_score`、`energy_score`、`vpp_score`。接受/拒绝不能由四项分数反推，真人原因不能由 EB 推理代写。技术不可执行与家庭不接受是两个概念：前者应停止生成或单独标记，后者才是角色模拟器需要学习的真人标签。

拟回接位置必须与采集时的评价范围一致：模型只评价参与者实际看到的完整方案对和模拟结果，不能把这一个最终标签复制到 EB 内部每次规划决策。

## 2. 当前结论

| 阶段 | 当前判断 | 依据 |
|---|---|---|
| 受邀工程演示 | 可用，但需保持有人值守 | HTTPS、登录、持久保存、小时快照、学校计算健康检查均在线 |
| 正式真人采集 | **暂不放行** | 线上仍为 `engineering`；当前版本没有真人端到端样本；身份、研究说明、季节语义和发布验收未完成 |
| SFT 候选记录 | 结构已具备 | 候选包含画像、环境、方案对、仿真、标签、哈希和来源；始终标记 `training_release=false` |
| 可训练发布数据集 | **尚未完成** | 只有格式审阅导出，没有去重、家庭级划分、质量筛选、数据卡和发布清单 |
| 家庭角色模拟器 | **尚未完成** | 仓库内没有 SFT 训练、基线对照、独立评测或校准流程 |
| 替代 EB 最终家庭评价 | **尚未完成** | 尚无训练模型到 EB 最终评价入口的适配器与影子验证 |

当前项目已搭好“采集候选”的前半段，不能把“网页能跑”解释为最终研究目标已完成。

## 3. 审计维度与验收条件

### A. 研究问题与标签语义

**要查什么**

- 输入、输出、评价时刻和可见信息是否固定。
- `accept/reject` 是家庭接受性，还是技术合法性、节电成败或模型偏好。
- 四项分数的题意是否单一，整体分是否独立填写。

**当前状态**

- 当前最终问题和四项分数已明确，标签来源能区分工程测试与家庭代表自报。
- 一日比较会截断跨午夜任务的次日用电；页面虽然说明了这一点，但这种标签只代表“截至当日 24:00 的部分结果”。回接 EB 前必须固定同一个评价截止点。

**放行条件**

- 写成版本化 label contract；采集页面、SFT prompt、评测和 EB 适配器共同引用。
- 无变化方案、技术失败、回退方案和截断结果分别定义是否进入训练。

### B. 问卷测量与填写负担

**要查什么**

- 每题是否对应 EB 输入、EP 绑定、分层分析或质量控制；不允许“先收了再说”。
- 家庭整体态度与成员态度是否重复，成员信息是否被误当成成员本人投票。
- 必填、选填、条件题和不可生成答案是否对参与者清楚。
- 手机端完成时间、退出点、漏答率和认知误解。

**当前状态**

- v4.1 共 66 个题目定义：26 个家庭事实、1 组成员列表、10 个偏好、1 个家庭控制态度、6 个模拟环境字段、22 个研究扩展字段。大量题目是设备条件题或选填字段，定义数不等于每人必答数。
- 一位填答者代述成员，代码没有把成员字段伪造成独立投票；家庭最终标签仍是一位代表综合判断。
- 成员可选态度与家庭必答偏好存在潜在重复，尚无真人完成时长、漏答和重测证据。
- 全年化后仍有季节语义缺口：`H_ac` 按抽定月份询问空调使用，但 `H_ac_temp` 只问制冷温度；冬季供暖目标仍采用研究默认值。冬季标签可能混合“空调供暖习惯”和“固定研究供暖参数”。

**放行条件**

- 先做 10–20 人认知访谈/可用性试填，记录每页耗时、修改次数、退出点和误解。
- 给每个字段标注 `execution_input / sft_input / analysis_only / quality_control` 用途。
- 修正冬季 HVAC 问法与执行绑定，或在修好前限制相应季节/设备组合。

### C. 家庭 JSON 与 EB 输入映射

**要查什么**

- 原答、规范值、展示文本、EB 投影和派生值能否逐字段追溯。
- 用户没有回答的内容是否保持未知，研究默认值是否单独标注。
- 每个选择的设备和时间窗口是否真正进入 EB。

**当前状态**

- 原回答、题表快照、规范值、家庭记录、EB 配置和哈希均独立保存。
- 当前不会把家庭强制归入原 EB 五类；所选设备都会进入本次模拟。
- 地区、房型、面积、面积口径和楼层进入环境匹配；其余扩展字段主要留存分析，不自动影响 EP。
- 午夜开始、跨夜或超过 8 小时的热水安排可以保存，但不能生成当前模拟；这会使某类真实家庭系统性缺少最终标签。

**放行条件**

- 自动生成字段级 lineage 表，证明每个执行字段的来源。
- 按设备和答案组合报告“可保存但不可生成”的比例，不能只分析成功样本。

### D. EB 主线一致性

**要查什么**

- 当前调用的是作者正式日级主线、哪个方法、哪个上游提交。
- 家庭 onboarding、日历、VPP 通知、逐步观察、规划、执行和记忆更新是否保留。
- 本项目新增的适配只负责数据注入、物理接口和最终真人评价，不能暗改 EB 策略。

**当前状态**

- 当前原生采集入口为单日 `eb_native_loop`，固定上游提交并保存控制轨迹哈希；模拟家庭最终接受检查被关闭，真人标签在运行结束后另存。
- `service_outcomes.py`、`closed_loop.py`、`paired_ep.py` 等仍保留旧的第 4 天/72 小时历史逻辑，但现行 `native_runner` 路径未调用。历史路径与现行路径尚未在目录、测试和文档上彻底隔离。
- 当前为“控制流程对齐”，不是“物理资产逐字节等同”：为了让原作者未接入 IDF 的若干电器真实进入电表，本项目增加了经过验证的设备端口。

**放行条件**

- 生成可机器检查的主线路径清单和上游差异清单。
- 旧四日模块移入明确 legacy 区或加导入阻断测试，防止重新进入当前 worker。
- 对外表述区分控制流一致、接口适配和物理资产变化。

### E. EnergyPlus 物理与配对有效性

**要查什么**

- 两份方案必须使用同一住宅、天气、日期、设备参数和随机种子，只改变 EB 控制。
- 每个电器命令必须能从 EP 输出读回；总表变化要与设备变化一致。
- 单位、时区、日界线、跨午夜、供暖/制冷和失败告警是否正确。
- 全国资源的覆盖率、失败率和选择偏差。

**当前状态**

- 配对同环境和 baseline-before-planning 保护已实现；基线失败时不调用模型，也不另抽有利日期。
- 50 个住宅是共享作者参数的研究原型，不是 50 类经中国住宅实测校准的建筑。天气是站点典型年，不是参与者当日实况。
- 现有全国资源基础验证不能证明 365 日 × 50 住宅 × 246 站点全部有效；当前仅对少量非夏季日做过真实 EP 回归。

**放行条件**

- 对地区、季节、住宅、设备组合做分层离线抽样，公布成功率、警告类型、温度/能耗合理范围和缺失模式。
- 把每次 baseline/proposal 的 IDF、EPW、结果哈希和端口读回写入发布质量表。

### F. 情境随机化与样本设计

**要查什么**

- 日期、VPP 时刻、持续时间和策略差异是否有足够覆盖。
- 随机化是否在看到家庭答案或标签之前完成，是否可复现。
- 同一家庭只有一次判断时，画像与情境效应能否区分。

**当前状态**

- 日期按浏览器会话在 365 天等概率抽取，VPP 开始时刻为 17/18/19 点、持续 0.5/1 小时；种子和概率被保存。
- 日期不是按地区、季节或极端天气配额平衡；参与者分布会决定最终覆盖。
- 无变化或近似相同的方案仍可能进入评价，信息量低。
- 一家庭一案例只能训练总体条件预测，很难检验同一家庭的稳定边界。

**放行条件**

- 预先写明抽样与配额方案，并实时监控地区×季节×设备×事件×方案差异覆盖。
- 对 `has_changes=false`、差异过小和不同 fallback 来源制定保留规则。
- 至少让一部分家庭评价 2 个独立情境，并安排小规模重测；同家庭样本只进入同一数据 split。

### G. 真人反馈有效性

**要查什么**

- 参与者是否完整看到两份方案、事件和 EP 指标后才可评价。
- 接受/拒绝、四项分数和原因是否绑定同一 `display_hash`。
- 是否记录完成时长、过快回答、矛盾答案、重复提交和注意力检查。

**当前状态**

- 展示哈希和两份方案哈希已绑定，评分允许 1–5 小数，保存后不可覆盖。
- 原因可空；当前未形成原因缺失率门槛。
- 浏览器会话只是代理身份；清 Cookie 或换浏览器会变成新家庭，共用浏览器也可能混用。
- 当前没有与研究记录绑定的页面耗时、招募编号或可靠的一人/一家庭防重复机制。

**放行条件**

- 招募渠道发匿名研究编号或一次性链接，用于同家庭关联和次数控制；不需要姓名，也不需要独立登录账号。
- 保存页面级时长、提交序列和最小化的质量标记；规则版本化，原始数据不删除。
- 明确“家庭代表判断”不能宣传成全体成员一致同意。

### H. 数据保存、隐私与恢复

**要查什么**

- 权威数据库、原始记录、派生记录和模拟产物是否分层。
- 权限、访问日志、保存期限、撤回方式、研究联系人和备份恢复。
- 日志或备份中是否包含 IP、Cookie、密钥或可重识别组合。

**当前状态**

- SQLite 为权威记录，目录与数据库权限为 0700/0600；Nginx 访问日志保存 14 个每日轮转周期。
- 小时一致性快照已成功运行且做完整性检查，但快照与主库仍在同一台云服务器，没有异地备份与恢复演练。
- 研究说明只覆盖用途、无需姓名/详细地址和点击保存表示同意；正式分发前仍需项目负责人确认机构、联系人、保留期限、撤回处理、招募/补偿及访问日志处理是否满足研究审批要求。

**放行条件**

- 完成数据清单与最小化审查，写明访问角色、留存/删除、撤回和泄露响应。
- 建立加密异地备份并实际恢复一次，核对数据库、题表快照、候选记录和必要仿真证据。

### I. SFT 数据发布

**要查什么**

- 候选到训练发布之间是否有不可跳过的质量门。
- 是否按真实家庭分组去重和划分，防止同家庭泄漏。
- prompt 是否只含推理时可获得的信息，target 是否只有真人答案。
- 版本、哈希、来源、排除原因和统计是否可复现。

**当前状态**

- `export_candidates.py` 明确只导出审阅 JSONL，所有记录保持 `training_release=false`。
- 当前 `split_group=household_id`，但该 ID 来自浏览器会话，不能证明家庭隔离。
- 尚无 release builder、去重规则、split manifest、泄漏审计、数据卡、token 长度检查和正式发布签名。

**放行条件**

- 构建 `raw -> reviewed -> released` 三层不可变清单；每条排除有 reason code。
- 先按真实匿名招募编号分组，再划分 train/validation/test；策略/事件另做组合外测试。
- 发布统计至少包括标签比例、四项分数分布、原因缺失、设备/地区/季节覆盖、失败与 fallback 来源。

### J. 训练与独立评测

**要查什么**

- 训练目标、基础模型、模板、超参数和随机种子是否冻结。
- 是否与 base、synthetic-only、human-only、human+synthetic 比较。
- 接受分类、四项回归/序数评分、原因质量和校准分别评测。

**当前状态**

- 本仓库没有训练或独立评测实现，因此目前不能声称真人问卷改善了家庭模拟。

**放行条件**

- 人员与情境双重 held-out；最终测试集不得参与 prompt 修改、阈值选择或校准。
- 报告 accept/reject 的 macro-F1、AUROC/PR-AUC 与概率校准，评分的 MAE/秩相关，原因采用盲评或规则明确的人工评审。
- 单独报告 EB 不利答案和少数家庭/设备组合，不能只看平均分。

### K. 回接 EB 与在线安全

**要查什么**

- 模型输入是否与采集时可见信息完全一致。
- 输出解析失败、分布外家庭、低置信度和服务故障怎样处理。
- 新模型是否只替代最终家庭评价，不改 EB 中间规划。

**当前状态**

- 上游存在可定义的最终评分边界，但当前仓库没有训练模型适配器或影子模式。

**放行条件**

- 先离线回放，再影子调用：模型输出不影响 EB，只和保留真人标签对比。
- 通过预设门槛后才替代；异常时返回“无法判断/请求真人”，不能静默填默认分。

### L. 并发、延迟、费用和单点故障

**要查什么**

- 网页保存并发、任务队列、EP/API 实际并发、全链路 P50/P95/P99 和失败率。
- API 速率/费用上限、熔断、重试幂等和恶意重复生成。
- 云、Mac 隧道、学校服务器任一失效时的行为。

**当前状态**

- 当前网站 16 worker、最多 64 pending、每浏览器 2 个任务、每天 50 个新任务、排队上限 600 秒；学校端公布任务/EP/API 槽为 32/32/4。
- 32 EP 并发属于既有压力证据；当前 v3.2 全年版本尚无真实模型端到端任务。旧工程任务曾有 165 秒完成和 300 秒超时，不能代表当前配置。
- 云到学校计算和学校到 API 都依赖这台 Mac 的常驻反向隧道。Mac 睡眠、网络变化或退出登录会中断生成；问卷保存仍可保留。
- 每日 50 个任务若收集 1000 个家庭，理论上至少需 20 个采集日，尚未结合真实完成率和重试率规划。

**放行条件**

- 在不扩大付费消耗前先用模型桩做 50 并发全链路；随后用少量真实模型任务测 P95、失败类型、单任务调用次数和费用。
- 设总费用熔断、模型调用次数上限、全局和招募编号配额。
- 正式采集前把隧道变成受监控的稳定服务，或明确有人值守、自动报警和暂停生成按钮。

### M. 版本、发布、许可证与文档

**要查什么**

- Git 提交、部署包、资源目录和运行服务是否同一版本。
- CI 是否验证当前提交；部署包是否包含所有测试夹具和资源清单。
- 上游代码与资源是否有再分发授权。

**当前状态**

- 当前工作树有 86 项修改/未跟踪路径，线上全年版本尚未提交到 GitHub；最近 CI 成功仍是 2026-09-11 的旧提交。
- 本地正确虚拟环境运行 172 项通过、8 项跳过；学校部署包运行真实 EP 时，170 项完成、2 项因缺少冻结 UI 夹具报错。这是发布包完整性缺口。
- `simulation_resources` 约 1.3 GB，当前主要是未跟踪本地资源；GitHub 源码本身不能重建完整全国资源。
- README 与 DATA 文档仍写“统一天津典型夏季/不按住房切换”，并保留早期 1 EP 槽说明，与线上全年地区匹配、32 EP 槽不一致。
- 上游授权仍需单独核实；本仓库当前没有声明开源许可证。

**放行条件**

- 形成不可变 release manifest：Git SHA、source hash、上游 SHA、资源 catalog hash、问卷/标签版本、依赖锁和部署配置摘要。
- 修复部署包夹具清单，部署后运行与 CI 相同的测试；只有当前提交 CI 绿且线上 readback 一致才发布。
- 为 1.3 GB 资源提供受控对象存储/校验下载或可复建脚本，不依赖某台机器的未跟踪目录。
- 更新 README、DATA、运维文档并核实上游许可证/授权范围。

## 4. 最高优先级问题

### P0：正式采集前必须解决

1. 线上从 `engineering` 切换到隔离的 `human_pilot` 数据目录，并完成一条 v4.1 真实全链路读回；历史工程数据不得改标。
2. 修正或限制冬季 HVAC 问卷—执行语义；固定跨午夜任务的评价截止定义。
3. 引入匿名招募编号/一次性链接，解决家庭去重、次数控制和数据 split。
4. 建立正式 SFT release builder，而不是直接把候选 JSONL 当训练集。
5. 当前源码与资源形成可复现发布；修复部署包缺少回归夹具的问题，运行当前提交的 CI/部署后测试。
6. 完成正式研究说明、数据留存/撤回、访问日志和研究审批核对。
7. 消除或接受并监控 Mac 隧道单点故障；真实模型小样本验收 P95、错误率与费用。

### P1：扩大到数百/上千样本前解决

1. 做分层全年 EP 覆盖和失败选择偏差报告。
2. 建立无变化/差异过小/fallback 方案的训练准入规则。
3. 一部分家庭做多情境与重测，验证标签稳定性。
4. 加密异地备份与恢复演练。
5. 建立质量监控看板：完成率、耗时、生成失败、标签/分数、原因缺失、地区季节设备覆盖和单任务费用。

### P2：训练与回接前解决

1. 完成 base、human-only、synthetic-only、human+synthetic 的同预算对照。
2. 完成人员和策略/事件双重 held-out 评测、校准和少数群体误差分析。
3. 实现 EB 最终评价适配器与影子模式，验证输入范围和失败回退。

## 5. 推荐执行顺序

1. 冻结 v4.1 问卷、情境、标签与评价截止合同。
2. 修正 P0 语义、身份、研究说明、发布和隧道问题。
3. 用 10–20 名受邀参与者试采，先审填写理解、真实延迟、方案差异和数据完整性。
4. 根据试采结果只改一次问卷并升版本；旧答案保持原语义。
5. 扩到 100–200 个家庭，同时完成分层 EP 与质量监控。
6. 冻结首个 reviewed 数据集，做家庭级切分与 SFT 基线实验。
7. 只有独立测试证明模型优于 base/合成基线，才做 EB 影子回接；通过后再谈替代真人评价。
