## 对齐与边界

1. 问卷原始记录先独立保存；生成失败不会丢掉家庭资料。配置从实时家庭回答构造，不分配 EB 五类预设。
2. 成员描述来自一位家庭代表，最终标签是其综合判断，不能称作成员独立投票或全员共识。
3. 家庭整体偏好保留独立回答，不把成员重要性分数平均成隐藏评分权重。
4. 上游固定 commit 2b17ae63e613da776c93e900f5dace50d63a88a8，EnergyPlus 24.1。原安排由问卷习惯和原生 EB 日常计划逻辑生成，EP 计算物理轨迹；事件分支接入原生 EB 规划与执行，重复观测与检查直到共同评价终点。真人评价替代合成家庭评分。
5. 统一住宅、天津典型气象 7 月 4 日、0.60 元/kWh、无补偿。通知时刻 16/17/18 时随机，事件一小时后开始、持续半小时或一小时。跨夜安排按共同评价窗口延长。研究扩展字段不自动更换住宅、天气、费率或设备数量。
6. 热水器午夜或跨夜等上游不兼容安排可保存家庭资料，但暂不能生成有效对比；不偷偷修改用户答案来运行。
7. 当前导出是 SFT 候选，默认排除工程测试；完整家庭资料可独立导出。未评分家庭不伪造监督目标，规划内部日志不作为真人输出。

- 用受邀真人走通一次真实 EB 模型链路，记录耗时、调用量、失败率和显示可理解性；本轮未消费 API。
- 人机验证尚未接入。现有浏览器配额、共享账号及 IP 限速不是可靠的一人一份保证；同校园网络也可能被生成限速影响。公开链接前需后端验证服务与实际额度验收。
- 现有 2 个任务／EP 槽、2 个 API 槽、4 个等待位、120 秒排队截止适合小规模演示；不是 50 人同时生成的体验承诺。管理员也不能绕过资源并发和超时。
