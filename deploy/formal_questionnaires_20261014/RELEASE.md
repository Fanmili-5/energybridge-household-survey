# 50户和950户正式角色问卷

两个不相交的数据版本：原50户、其余950户，每户保留十个原季度分层日期。使用同一V29任务区分度规则与冻结V28家庭/正常A，合计1000户、2524名参考成员、10000组A/B。正式采集沿用成熟前端，保留生活和用电影响、采用判断、四项可空且支持一位小数的评分与理由，新增填写者本人年龄/性别，简略电器动作并保留完整时段展开。

研究对象是有来源锚点的中国城市普通住宅参考角色。家庭统计约束、匹配与参考仿真、研究者给定政策、真人角色评价分开保存。六类A101/B303/C319/D101/E85/F91是结构与可行性约束下的给定政策配比，不是全国自然偏好占比。50/950是角色集合划分，不能自动视为真人或统计独立的训练/测试划分。

## 生产与准入

V27原50数据和旧线上工程库保留。V28在全部1000户中统一修正外出/在家活动覆盖规则，重新核验源结构、作息、照护、服务、A/B、聚类覆盖、设备与IDF。静态验收后，先在学校核验原50户500基准配对和200敏感性配对，通过后才准入950户9500基准配对。B中违反要求的方案保留，不预设演员答案。

天气来自受控CSWD参考文件。98份EPW中9份存在RH超出EnergyPlus24.1字典0–110范围的源值，保留原件，并仅对超限湿度使用上一有效值及估计标志，生成独立插值敏感性版本。最长异常段7小时。所有气象头、干球、其他气象量、家庭、日期、类型、硬件及IDF保持原输入；逐行变化留档。这是参考缺失处理，不能称为气象测量或校准。依据：[24.1缺失值处理](https://bigladdersoftware.com/epx/docs/24-1/auxiliary-programs/missing-weather-file-data.html)、[数据与不确定性标志](https://bigladdersoftware.com/epx/docs/24-1/auxiliary-programs/data-sources-uncertainty.html)、[官方数据字典](https://energyplus.net/assets/nrel_custom/pdfs/pdfs_v24.1.0/AuxiliaryPrograms.pdf)。

SQL读表仅在实际IDF没有对应People组件、输入账本全程为零且SQL没有部分缺失时证明人数为零；任何应有的非零/部分输出缺失拒收。外部照护与装取服务人员的实际SQL名称显式写入编译账本，避免JSON排序改变逐人对应。全部旧账本留档，核对所有IDF字节不变；逐人Schedule Value及逐室人数均与输入账本核验。

每个正式前端案例独立检查当前世界、A/B源文件、SQL读表证据和物理状态，缺失/待计算案例不能进入发布。案例数据仍是参考情境，不变成人类标签。

## 正式收集协议

- 独立正式库，不导入或改名工程试填数据。一个邀请码固定分配一个家庭、一个随机参与编号，十个日期同一身份。领取后生成恢复码；邀请码和恢复码仅保存HMAC摘要。
- 明示自愿参与与角色扮演说明；本人年龄和性别选填，空值保留。本人信息、采用判断、评分、理由在输出侧；模型输入只包含实际可见角色/任务信息与合法历史。
- 每条答卷保存案例、可见页面、源输入与发布版本hash、参与说明版本/时间和回执。相同提交标识重复发送幂等；同一日期修订追加新记录，当前导出只取最后一次。
- 恢复码可以跨设备继续填写；撤回排除该身份全部答卷，后台保留审计轨迹。导出排除撤回者及专用测试数据。
- HTTPS、同源/CSRF校验、固定角色访问、私有0600数据库/密钥/邀请码。网页不提供数据库或答卷批量下载。
- 原生定时任务每6小时生成SQLite一致性恢复包，包括密钥与邀请码；保留最新和上一份压缩恢复包，源答卷库不改动。部署前另有版本化备份与回滚。

`eb.role_response.v1`为正式参与者提交记录；`source_release_sha256`连接对应50/950发布包。`respondent`与`response`不进入`input`。每条记录的`human_identity_validation=not_performed`准确表示未验证个人身份；`training_release=false`表示数据质量评估前不自动进入训练。专用流程验收使用`--fixture-mode`独立库，标签来源为`engineering_fixture`、人类标签数0、正式导出为空。

## 运行与管理

公开正式入口使用`/household50`和`/household950`；研究者私下分发相应邀请码。私有邀请码CSV及答卷不得提交GitHub。正式服务器运行在云端回环18775，经现有Nginx转发；全部EP与接口/数据核验在学校。原真实家庭自报问卷及其他服务保持各自数据与版本。

私有管理：`admin.py provision|export|backup`；准入：`release_acceptance.py`；隔离协议验收：`test_protocol.py`；部署：`activate.py`；一致性恢复：`backup.py`。最终激活回执、逐户案例验收与物理汇总另存公开聚合报告。

2026-10-15自查修正：部署每次都验证邀请码CSV与正式角色集合及数据库登记；中断后重放同一文件，不轮换凭据，冲突拒绝。已有数据库缺少原密钥时要求恢复备份。当前答卷按最后修订顺序恢复，包括明确留空的本人信息。`test_recovery.py`以独立临时库验证中断、冲突、撤回与备份恢复。

当前案例准入在学校核物理报告的实际内容签名、完整数量、A/B真实文件及三种电量范围和末态；从当前源重新构造全案例，并使用`verify_formal_bindings.cjs`调用发布JS的绑定验收器。`release_acceptance.py --node /path/to/node20`需要受控完整研究工作区；云端服务不运行这些生产工具。`test_release_acceptance.py`保留伪造数值却沿用合法证据hash等拒收控制。[本次审查](../../docs/household1000/AUDIT_20261015.md)。

## 科研范围

正式发布表示这两版可以开始实际角色答卷收集。参考输入内部一致性与仿真读表通过验收，并不替代真人角色理解/有效性、人口真实六类偏好比例、品牌设备实测校准或正式benchmark性能验证。原EB空调曲线适用范围与截断、心理湿度警告、有限尾段和A/B末态不等仍明确保留；回答者自行评价，不能把目标规则自动变成同意/拒绝标签。
