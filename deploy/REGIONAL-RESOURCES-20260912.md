省市联动采用固定行政名称快照并允许手工补充城市。先匹配同城且技术验证通过的天气组合；缺少时使用省内代表站。原填省市不覆盖，实际站点与匹配方法另外保存。两份方案冻结同一 IDF、EPW、DDY 与日期，原 EB 规划和设备控制算法不因省份而改写。

资源包含 338 个已下载站点，其中 246 个至少有一个通过的住宅/日期组合；50 个住宅变体、3 个夏季候选日期，共检查 50,700 个组合：36,872 个完成 EP 并通过，13,828 个未通过。未通过项包含启动 EP 前的资源预检查拒绝，不能把组合总数等同于实际 EP 启动次数。34 个省级地区的代表站均覆盖 50 个住宅变体，每组合至少有一个有效日期。实际抽样只使用通过的组合。完整验证及边界见 `simulation_resources/README.md`。

发布验证：

- 本地 162 项离线回归通过；随后新增的云端快速哈希与计算端完整资源哈希一致性测试单独通过。
- 学校 Linux 上 11 项地区环境检查通过，包含实际 EP、配对结果、真人反馈候选样本保存。模型使用固定替身并阻止外网连接，没有付费 API 请求。
- 网页确认广东联动 21 个城市，切换湖北会清除广东城市；深圳展示深圳站，鄂州展示武汉代表站。
- 线上只读环境预览确认深圳同城、鄂州/高雄代表站匹配；原填城市保持不变，没有向真实采集数据库提交测试家庭。
- 云端通过原有隧道读到学校新版本健康状态，两端发布哈希一致。未登录公网 HTTPS 返回预期 401，认证和隧道配置未改动。
- 切换前两端均无运行任务；本地及云端三张数据库表切换前后内容哈希一致。

当前资源验证证明技术运行可用，不代表全国住宅已校准。材料、设备系统继承作者研究参数；地区天气、设计日、地温和面积/热边界接入了实际仿真。电价仍为原 EB 天津权重的统一实验条件，并非当地实际人民币电价。本轮只复核了无付费模型的运行路径，没有重新测试真实模型规划的延迟或输出质量。

## 维护与回滚

仅新增两处 systemd 工作目录覆盖：云端 `/etc/systemd/system/energybridge.service.d/90-regional.conf`，学校 `~/.config/systemd/user/energybridge-compute.service.d/90-regional.conf`。服务其他参数、密钥、数据目录及 API/计算隧道保持不变。旧代码目录保留。

云端一致性备份与发布检查在 `/var/backups/energybridge/regional-20260912/`；本地发布材料和旧数据备份在 Git 忽略目录 `artifacts/regional_release_20260912/`。不要提交真实数据库或密钥。

回滚须先暂停新任务并确认两端空闲，再协调切回两个旧工作目录、重新加载 systemd 并启动。不可只回滚一端，否则发布哈希不一致将拒绝任务；不可用旧备份覆盖上线后新收到的资料。已有地区案例的资源目录须继续保留。
