## 并发与故障处理

| 配置 | 当前值 |
|---|---:|
| 阿里云并行任务进程 | 16 |
| 学校最大任务数 | 32 |
| 同时占用 EP 计算名额 | 32 |
| 同时发起模型请求 | 4 |
| 学校服务 CPU 上限 / 内存上限 | 32 核配额 / 16 GiB |
| 阿里云在途任务上限，包含运行与等待 | 128 |
| 单会话生成上限 / 普通用户每日总额度 | 2 / 250 |
| 失去心跳后远端停止任务 | 60 秒内，另有进程检查间隔 |
| 学校执行期限 / 远程调用期限 / 云端进程期限 | 1200 / 1320 / 1200 秒 |
| 队列等待期限 / 冷启动保守估计 | 2400 / 300 秒 |
| Mac API relay TCP 连接上限 | 64，与模型请求并发分别控制 |

等待 API 时原生 EP 状态留在同一进程，释放 CPU 名额给其他任务，因此内存预算按 32 个任务考虑。学校资源是共享资源，服务有 32 核 CPU 和 16 GiB 内存上限，没有占用整台机器。每天 250 个新任务仍是独立的费用保护额度，不代表并发上限。

满载等待在阿里云 SQLite 队列中进行，计算端不再叠加一层无持久化队列。旧的排队时长样本来自较低并发配置；页面的预计时间不是新容量下的性能保证，需由后续真实规划样本逐步校准。

同一个云端逻辑任务使用固定远端 ID：请求重发或云服务重启不会重复启动该任务。远端失败、中断或超时不会被自动重跑，也不会被当作用户拒绝。远端取消和打包并发发生时，取消状态不会被成功结果覆盖。

所有计算端口只监听回环地址，计算接口另需独立令牌。云端隧道账号仅能开放指定回环转发端口，不能执行 shell。模型密钥只在学校端私有配置中读取，不放入任务包、前端或 Git。

## 数据回传

问卷先落阿里云 SQLite，再发送计算请求。学校为每个任务建立独立目录，保存两次仿真、原生动作、模型请求/回复、EP 输出和展示结果。

回传 ZIP 有总哈希，内部文件有逐文件哈希。云端检查源码版本、请求哈希、压缩包和文件完整性，并防止解包路径越界；最后才写入 `outcome.json`。网站继续检查家庭、方案和展示哈希，再把结果提交到 SQLite。真人评分仍在阿里云收集，计算端不生成真人标签。

完整工程探针使用独立测试目录和数据库，没有混入真人采集库。学校端目前保留完整任务副本，低于 10 GiB 可用空间时不再接收新任务；尚未启用自动删除研究数据。

- 学校端 17 项定向回归通过；本地完整回归及新增取消竞争测试通过。
- 学校经现有代理认证查询模型列表返回 200，当前配置模型可用；这不是付费规划性能测试。
